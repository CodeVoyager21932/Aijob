## 1. 产品结果与完成定义

Aijob 的本地完整 MVP 必须在 coco 的电脑上跑通以下闭环：

```text
可信、可追溯的在校生可投官方岗位；规模与分布如实报告
  -> 自动采集、清洗、去重、结构化和来源追溯
  -> 上传 PDF/DOCX 或粘贴简历文本
  -> 隔离解析后直接编辑，保留原件、完整经历和来源关系
  -> 资格、经历证据、偏好三轴匹配
  -> 可解释的岗位推荐与官方投递链接
  -> 按方向查看有样本门槛的确定性 JD 洞察和个人证据对照
  -> 针对选定岗位生成简历对照修改稿
  -> 用户逐段接受、拒绝或编辑
  -> 复制或导出统一 ATS 友好 DOCX
  -> 保存投递状态并可删除全部个人数据
```

岗位采集、用户简历、匹配推荐、AI 简历优化、官方投递交接和数据删除全部完成前，不能把任何单个切片称为“完整 MVP”。

## 2. 范围

### 2.1 P0

- 本硕博在校生可投的实习、校招、应届与管培岗位按逐条事实和来源准入判断。ADR-0035–0037 已将 100 家/1000 岗及人工企业 20%/岗位 10% 降为报告项，SME、职能与城市为观察项，撤销可达 50% 聚合门及公司岗位上限；必须如实报告，不以数量或学历/院校全局排除。
- 用户岗位目录只接受企业官网与企业官网确认的官方 ATS。高校就业网、政府公共就业站、企业认证公众号和其他二手页面只能用于发现企业及官网方向，不能成为目录岗位真源；访问政策或主体证明不足不能获准公开。缺投递入口的岗位可按 ADR-0035 进入明确标识的本机待审核目录，补齐官方入口后才可公开。
- 岗位快照、规范化、来源内幂等、跨来源疑似重复、字段证据、要求拆解、不可变岗位版本和复核状态。
- 正式 `/jobs` 列表、详情、筛选、未知字段覆盖率、来源与官方投递入口。
- localhost 自动匿名 owner 会话；后续邀请环境使用一次性邀请令牌。
- PDF、DOCX、粘贴文本三种简历入口；隔离解析后直接编辑，原件留存/下载、首次自动收录完整经历和局部纠错，不再设置脱敏或逐句确认关卡。
- 确定性三轴匹配、版本化推荐、五态岗位决定。
- 确定性 JD 洞察、样本门槛、官方原句追溯和已确认简历证据对照。
- OpenAI-compatible 模型适配器、受控 AI 简历优化、模板降级、逐段确认和 ATS 友好 DOCX 导出。
- 原件、正文、经历和保留产物长期保存至用户主动删除；只有临时解析副本最长 24 小时，迟到任务继续校验 owner epoch。

### 2.2 不在本轮

- 公开云部署、公共注册、手机号/邮箱登录和跨设备恢复。
- OCR、图片简历、旧版 `.doc`、压缩包、宏文档或复刻原简历复杂版式。
- 自动填写、模拟登录、批量投递或替用户提交申请。
- Redis、消息总线、独立搜索、向量数据库和公共管理后台；生产浏览器旧禁令已由 ADR-0037 替代，允许 collector-worker 内受控隔离浏览器和复用 CLI 服务的受限内部台。
- 职业测评、从零生成虚构经历、录用概率或匹配度百分比。

## 3. 数据与岗位目录

### 3.1 来源和发布范围

- 来源只能是企业官网、企业确认的官方 ATS、高校就业网站、政府公共就业站、企业公开招聘页面或人工核验的企业认证公众号。
- 不抓取 BOSS、实习僧、牛客等综合招聘平台。
- 每个来源先完成主体证明、访问政策、新鲜度、采集方式和精确网络目标评估，再实现或运行适配器。
- `pending_review` 或尚未获准公开的来源只能进入本地 `local_mvp` 目录；公开 `/v1/jobs` 继续只返回真正批准发布的岗位。
- 真实来源探测必须由维护者明确运行；测试和 CI 只使用离线快照。
- 认证公众号不建立生产网络采集；只允许人工可见内容的本机快照，并要求官方 HTTPS 投递页或企业域名招聘邮箱。

### 3.2 岗位数据链

```text
官方响应
  -> 原始快照与内容哈希
  -> 来源内稳定身份和幂等
  -> 规范化与字段级证据
  -> 跨来源疑似重复
  -> JobRequirementSet
  -> 人工复核项
  -> PublishedJobVersion
  -> local_mvp / public 发布投影
```

每条岗位至少包含：公司、公司规模及证据、岗位名、方向、城市、部门、职责、要求、招聘类型/批次、每周出勤、实习时长、到岗时间、毕业年份、学历、专业、语言、薪资、工作方式、发布日期、截止日期、活动状态、来源类型、最后核验时间和投递方式。投递方式为官方 HTTPS URL 或企业域名招聘邮箱；原文未说明时必须保存为 `unknown`，不能由规则或模型补写。

### 3.3 检索与筛选

- 关键词检索覆盖岗位名、公司、职责和要求。
- 结构化筛选支持公司、城市、方向、批次、出勤、时长、到岗、毕业年份、学历/专业、薪资、工作方式、来源和新鲜度。
- 只有存在至少两个真实选项的维度才显示可操作分类筛选；只有一个选项时显示为当前数据范围，零个已知值时显示已知覆盖率和“暂不可可靠筛选”。
- 硬条件筛选结果分为“明确符合”和“信息待确认”。未知岗位不能伪装成符合，也不能被自动劝退或永久隐藏。
- 移动端筛选抽屉先保存草稿，点击“查看结果”后才应用；关闭或 `Esc` 放弃草稿。筛选数量按维度计数。

## 4. 用户旅程

1. 用户打开 `/jobs`，直接浏览岗位或选择“用简历匹配”。
2. 用户先设置城市、方向、出勤、时长等轻量约束；所有问题均可跳过。
3. 用户查看岗位详情、来源主体、最后核验时间、未知项和官方投递方式；也可按方向查看满足样本门槛的 JD 洞察。
4. 用户上传不超过 5 MiB 的 PDF/DOCX，或粘贴文本。
5. 系统隔离解析后直接进入编辑器，姓名、电话、邮箱正常保留；AI 使用由用户启动相应任务，不要求预先脱敏或审批事实。
6. 用户可局部修改内容及字段归属，保留未受影响条目、手改和来源关系；不确定内容保留待整理，不由模型补写。
7. 系统分别显示资格、证据和偏好，并生成有依据、可纠正的岗位推荐顺序。
8. 用户选择岗位进行简历优化，逐段查看原文、建议、原因、岗位要求和经历证据引用。
9. 用户接受、拒绝或编辑每段，复制结果或导出统一单栏 DOCX。
10. 用户前往经过重新校验的官方页面自行投递，返回后更新岗位决定。
11. 用户可随时查看保留期限并删除全部个人数据。

## 5. 功能需求

### 5.1 会话与所有权

- **REQ-SESSION-001**：localhost 首次访问自动创建匿名 owner 会话；不收集手机号、邮箱或密码。
- **REQ-SESSION-002**：会话 Cookie 使用 `HttpOnly + SameSite=Strict`；生产邀请环境额外启用 `Secure`。
- **REQ-SESSION-003**：所有用户对象由服务端会话派生 owner，客户端不能指定 `owner_id`。
- **REQ-SESSION-004（ADR-0038 更新）**：新访客材料长期保留；旧匿名 owner 只在仍活动且主动保存材料的事务中转换，不批量转换、不复活过期或已删 owner。session 独立过期且可撤销，不按会话到期清理长期材料。
- **REQ-SESSION-005**：写操作校验 Origin/Fetch Metadata 和 CSRF；对象不存在与越权使用相同外部响应。

### 5.2 简历输入和隔离解析

- **REQ-RESUME-001**：支持 PDF、DOCX 和粘贴文本；单次最大 5 MiB。
- **REQ-RESUME-002**：校验扩展名、声明 MIME、文件魔数和内部结构；拒绝 `.doc`、图片、压缩包、宏、加密文件、伪造类型和超限内容。
- **REQ-RESUME-003**：DOCX 限制文件条目数、解压后总大小和压缩比；PDF/DOCX 解析有时间、内存和输出字符上限。
- **REQ-RESUME-004**：没有可提取文本的 PDF 显示“可能是扫描件”，回退到粘贴文本；本轮不做 OCR。
- **REQ-RESUME-005**：原件私有加密保留，临时解析副本与保留原件分开；任务只携带 owner、记录 ID 和输入哈希，不复制正文。
- **REQ-RESUME-006**：文件解析不调用 Office、不执行宏或外部资源，运行在无网络、有限资源的隔离子进程中。
- **REQ-RESUME-007（ADR-0038 更新）**：用户启动 AI 任务后可使用其提供的完整材料；取消强制脱敏、逐句勾选和前置事实审批，日志与错误正文仍不能泄露个人材料。
- **REQ-RESUME-008（ADR-0038 更新）**：事实、偏好、经历分开保存并可纠正，不以逐项确认作为使用前置；没有材料支持或不可靠的归属保持未知/待整理。
- **REQ-RESUME-009（ADR-0038 更新）**：原件留至用户主动删除且可下载，删除原件不删除正文；最长 24 小时仅适用于临时解析副本。

### 5.3 三轴匹配和推荐

- **REQ-MATCH-001**：资格只使用 `未发现明确冲突 / 存在明确冲突 / 需补充信息`。
- **REQ-MATCH-002**：证据只使用 `有明确证据 / 部分证据 / 简历暂未体现 / 信息不足`。
- **REQ-MATCH-003**：偏好只使用 `符合 / 不符合 / 未设置`。
- **REQ-MATCH-004**：每个结论必须引用固定岗位版本、要求 ID、用户事实或证据 ID；未知岗位字段和简历未体现必须分开。
- **REQ-MATCH-005**：系统不显示总匹配百分比，不生成录用概率，不因冲突或证据不足自动隐藏岗位。
- **REQ-MATCH-006**：`MatchRun` 不可变引用岗位版本、要求集、事实/偏好/证据修订、规则、词典、模板和实际使用的模型版本。
- **REQ-RECOMMEND-001**：`RecommendationRun` 固定候选岗位版本集合、对应 `MatchRun`、排序策略版本和创建时间。
- **REQ-RECOMMEND-002**：排序采用确定性元组：资格状态、偏好满足、证据覆盖、新鲜度和稳定岗位 ID；内部顺序值不作为前台匹配分。
- **REQ-RECOMMEND-003**：每条推荐展示推荐原因、冲突、未知条件、来源、最后核验时间和官方链接。
- **REQ-RECOMMEND-004**：岗位资格冲突仍可查看和纠正；用户自己决定保存、准备投递、投递或放弃。

### 5.4 JD 洞察

- **REQ-INSIGHT-001**：用户必须选择一个岗位方向，可选城市和公司规模；结果只使用当前活动岗位与活动原子要求集。
- **REQ-INSIGHT-002**：至少 20 个岗位、5 家企业、70% 原子要求覆盖才输出排名；单项至少覆盖 3 个岗位、2 家企业，否则展示实际分母和“样本不足”。
- **REQ-INSIGHT-003**：`required`、`preferred/optional` 和必要性未知严格分开；排名先按跨公司覆盖，再按岗位覆盖和稳定键；明确工具单独统计。
- **REQ-INSIGHT-004**：每项展示岗位数、公司数和最多 3 个跨公司官方原句；不生成词云、录取概率或自由 AI 市场结论。
- **REQ-INSIGHT-005**：个人对照只使用用户确认的 `ResumeEvidence v2`，输出“已经体现 / 简历暂未体现 / 需要确认”；旧证据不得伪造区块引用。
- **REQ-INSIGHT-006**：`JobInsightRun` 不可变冻结筛选、岗位版本、要求集、来源核验时间、算法版本和可选证据修订，并随 owner 删除。

### 5.5 AI 简历优化

- **REQ-AI-001（ADR-0038/0043 更新）**：个人 AI 使用当前 owner 保存的兼容接口和模型，不回退运营方配置；没有密钥、关闭、超时或校验失败时保留固定辅助。搜索另可选仅已有来源、复用已验证搜索能力的个人 AI 或独立 Tavily，不强制两份 Key。
- **REQ-AI-002**：每次外部 AI 使用均需用户明确选择；公开环境默认关闭，必须另经供应商、合规和用户增量 Gate。
- **REQ-AI-003（ADR-0038 更新）**：模型可使用当前任务的完整个人材料与回答，和岗位要求分开组织；个人数字、技能和成果只能由个人材料支持，不要求前置脱敏或确认。
- **REQ-AI-004**：写作模型没有本机文件、数据库或采集控制权，不能直接改写三轴、岗位版本、用户事实或决定。个人搜索用途按 ADR-0043 的独立能力验证及权限执行。
- **REQ-TAILOR-001**：`ResumeTailoringRun` 不可变引用输入简历版本、目标岗位版本、要求集、证据修订、模板/提示词和模型版本。
- **REQ-TAILOR-002**：每个建议段包含原文、建议、修改原因、`requirement_id[]` 和 `evidence_id[]`。
- **REQ-TAILOR-003**：新数字、公司、项目、技能或结果必须回指用户确认的证据；Schema、引用或事实校验失败的内容不得展示。
- **REQ-TAILOR-004**：用户逐段接受、拒绝或编辑；系统不能自动覆盖最终简历。
- **REQ-TAILOR-005**：用户可以复制最终文本或导出统一单栏、ATS 友好、可编辑 DOCX；不承诺保持原文件排版。

### 5.6 岗位决定与官方投递

- **REQ-ACTION-001**：岗位决定只使用 `未决定 / 已保存 / 准备投递 / 已投递 / 已放弃`。
- **REQ-ACTION-002**：打开官方页面与用户自报已投递是两个不同事件。
- **REQ-ACTION-003**：官方 URL 必须来自已审核 `apply_targets`，打开前重新校验协议、主机和路径；企业邮箱必须属于已核验企业域名并保留官方原句。
- **REQ-ACTION-004**：外链返回或刷新后恢复筛选、最近岗位、优化草稿和决定状态。
- **REQ-ACTION-005**：系统不读取企业账号、不自动填写、不模拟登录、不替用户提交申请。
- **REQ-ACTION-006**：邮件岗位只提供复制邮箱与查看官方原文，不自动创建或发送邮件。

### 5.7 删除和保留

- **REQ-DELETE-001**：删除请求立即撤销 owner 对个人数据的访问、递增 `owner_epoch`、取消旧任务并写入持久墓碑。
- **REQ-DELETE-002**：删除覆盖文件/原文、事实、偏好、证据、匹配、推荐、简历优化、导出文件、岗位决定和 owner 产品事件。
- **REQ-DELETE-003**：迟到任务写入必须因 owner epoch 或墓碑失效而被拒绝。
- **REQ-DELETE-004**：删除状态提供处理中、成功和失败重试；不得假报成功。
- **REQ-DELETE-005（ADR-0038/0042 更新）**：原件、正文、职业资产与已保留导出默认长期保留并支持单项/全部删除；临时解析和未保留预览缓存分别按期限清理，不能影响历史修订或投递材料。无正文删除/安全审计最多保留 90 天。

## 6. 早期页面范围（兼容记录）

下表记录旧路由，不要求恢复确认页。当前导入直接进入编辑器，完整经历、简历和面试可独立开始；导航与编辑/输出链路以 ADR-0038/0042 及当前路线图为准。

| 路由/区域 | P0 行为 |
|---|---|
| `/jobs` | 正式岗位目录、关键词/结构化筛选、覆盖率、推荐入口 |
| `/jobs/{id}` | 岗位原文、结构化要求、来源证据、三轴结果、官方链接 |
| `/resume` | 文件/文本输入、格式限制、隐私说明、解析进度 |
| `/profile/confirm` | 事实、偏好、经历证据分组确认和修订 |
| `/recommendations` | 可解释推荐顺序、冲突、未知项和来源 |
| `/insights` | 岗位方向/城市/规模筛选、样本依据、确定性要求排名和个人证据对照 |
| `/jobs/{id}/tailor` | 简历原文与建议对照、依据、逐段接受/拒绝/编辑 |
| `/decisions` | 五态队列、理由、返回续接 |
| `/data` | 保留期限、AI 使用记录、导出与删除状态 |

现有 `/research/*` 保留为历史研究原型，不接管正式产品路由。`/internal-preview/*` 继续作为本地字段复核入口。

## 7. API 边界

统一使用 `/v1`：

- `GET /jobs`、`GET /jobs/{id}`。
- `POST /resume-analyses`、`GET /resume-analyses/{id}`。
- `PUT /profile/facts`、`PUT /profile/preferences`、`PUT /profile/evidence`。
- `GET /profile/document`、`PUT /profile/evidence-selection`：兼容读取确认后的结构化简历区块并重选证据，不恢复已删除原文；新写入最终收口到 Resume V2/Case 真源。
- `POST /match-runs`、`GET /match-runs/{id}`。
- `POST /recommendation-runs`、`GET /recommendation-runs/{id}`。
- `POST /job-insight-runs`、`GET /job-insight-runs/{id}`。
- `POST /resume-tailorings`、`GET /resume-tailorings/{id}`。
- `PUT /resume-tailorings/{run_id}/segments/{segment_id}`。
- `POST /resume-tailorings/{run_id}/exports`。

- `DELETE /profile`、`GET /profile/deletion`。

创建型接口和删除操作支持 `Idempotency-Key`；异步创建返回 `202`、资源 ID、状态地址和建议轮询间隔。错误统一使用稳定 Problem Details，owner 级响应统一 `Cache-Control: no-store`。

## 8. 验收

完整 MVP 必须同时满足：

- 每个已接入来源按其准入要求抽检；每条公开岗位有来源、核验时间、投递方式和重点字段值或 `unknown`。规模与分布如实报告，不恢复 100 家/1000 岗或旧结构硬门；300–500 岗为早期研究设计，当前必要样本按实际改动确定。
- PDF、DOCX 和文本均能完成解析；扫描 PDF、伪造 MIME、超限、宏、加密文件和 DOCX 解压炸弹有安全失败路径。
- 至少 50 个跨职能分类金标，并保留高风险金标覆盖资格、未知字段、证据缺失、偏好冲突和跨来源疑似重复。
- 金标中明确硬条件漏检、错误劝退、无个人材料支持的推断参与结论和虚构经历均为 0；不以未逐句确认替代事实依据判定。
- AI 使用模拟端点通过自动测试；由 coco 在本机提供密钥后完成一次真实兼容端点冒烟测试。供应商不可用时，岗位浏览、三轴匹配和推荐仍可用。
- 跨 owner 越权、CSRF、迟到任务写入、临时解析 24 小时 TTL、原件长期留存、删除后拒绝恢复及官方链接白名单测试通过。
- 洞察通过公司均衡统计、硬要求/加分项分离、低样本拒绝、原句追溯、个人证据引用和删除联动回归。
- 在桌面端和 320 CSS px 移动端跑通“找岗位 → 上传简历 → 确认 → 推荐 → 优化 → DOCX → 官方链接 → 记录状态 → 删除数据”，无横向溢出并满足核心 WCAG 2.2 AA 要求。
- 一套本地命令可以从空数据库完成迁移、加载/采集目录并启动完整链路。

以上保留早期 G2 的验收维度，不生成当前重验任务。2 人校准、6 人正式验证和 72 小时回访是历史研究方法，不是当前开发或发布的固定前置门；反馈随交付收集，工程完成、岗位数量、AI 调用量或页面可用性均不能提升 `E0`。
