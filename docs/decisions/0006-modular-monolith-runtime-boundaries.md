# ADR-0006：采用模块化单体、三个进程、PostgreSQL 真源与岗位快照 Bucket

- 状态：accepted；文件上传边界由 [ADR-0012](0012-isolated-resume-document-ingestion.md) 修订
- 日期：2026-07-15
- 决策者：项目维护者
- 关联：系统架构、安全威胁模型、工程交付规范

## 背景

系统需要隔离公开采集、用户简历匹配和 Web 请求，但工程 MVP 只有少量来源与邀请用户。单进程难以执行网络和数据权限边界，微服务和多种基础设施又会增加部署、分布式一致性和成本。

## 决策标准

- 采集进程不能读取用户数据或模型密钥。
- 匹配进程不能访问采集目标和原始网页。
- 原始岗位响应可重放，但其正文存储不能扩大用户数据访问面。
- 代码、迁移和领域模型保持单团队可维护。
- MVP 有明确恢复目标和可接受成本。

## 选项

### 选项 A：单进程单权限应用

- 优点：部署最简单。
- 缺点：外部网络输入与敏感用户数据共享权限，隔离无法执行。

### 选项 B：多个独立微服务和专用基础设施

- 优点：边界最强、可独立扩缩。
- 缺点：当前规模下增加服务发现、消息、部署和一致性成本。

### 选项 C：模块化单体代码库，三个独立进程

- 优点：共享领域代码和迁移，同时用进程、角色与网络策略落实高风险边界。
- 缺点：PostgreSQL 和单实例仍是单点；岗位快照正文与元数据存在明确的提交顺序、完整性和孤儿清理成本；模块纪律需要持续测试。

## 决定

选择选项 C：同一构建产物提供 `web-api`、`collector-worker` 和 `match-worker` 三个入口，另有不监听公网的 `internal ops CLI`。为避免新增第四个 Worker，`match-worker` 同时执行已写入持久墓碑的 owner 删除任务，但只能调用校验任务 owner、墓碑和 fencing token 的受限幂等清理函数，不能任意删除数据。

PostgreSQL 是唯一查询、任务和元数据真源，通过 schema、角色和外键/唯一约束隔离领域并承担任务表。独立岗位快照 Bucket 只保存原始公开岗位响应正文，绝不存放用户简历、画像、匹配结果、邀请令牌或日志；`collector-worker` 只能读写其专用前缀，`web-api` 和 `match-worker` 没有 Bucket 读取权限。

快照对象键由来源标识与内容哈希确定性生成。采集进程必须先上传并校验对象，再提交 PostgreSQL 快照元数据和版本；上传成功但事务未提交的无引用对象满 24 小时后清理，对象缺失、不可读或哈希不一致时不得发布对应岗位版本。MVP 不引入 Redis/Celery、独立搜索、向量库、Playwright、公共管理端或岗位快照之外的对象存储用途。

2026-07-18 后，本地完整 MVP 允许按 [ADR-0012](0012-isolated-resume-document-ingestion.md) 接受 PDF/DOCX 简历。原文件只以应用层加密形式暂存在 PostgreSQL，不进入岗位快照 Bucket，也不扩大 `collector-worker` 权限。

邀请制 Alpha 接受单 PostgreSQL、单 Web，以及 `collector-worker` 和 `match-worker` 各单实例的单点故障，恢复目标为 `RPO <= 24 小时`、`RTO <= 8 小时`；这是内部测试目标，不是公开服务 SLA。进入私测前完成 PostgreSQL 备份恢复、快照引用完整性检查和删除墓碑重放。

## 后果

- 正向：运行时边界可执行；岗位正文不挤占查询数据库，也不扩大到用户数据存储；基础设施和分布式一致性成本仍受控。
- 负向：Alpha 发生单实例故障时服务会中断；需要监控 PostgreSQL 元数据、Bucket 容量和对象/元数据一致性。
- 后续：为每个进程建立独立数据库角色、服务账号、Bucket 前缀、出站策略和权限/故障注入测试。

## 复审触发条件

- 进入公开 Beta，需要更高可用性承诺。
- 实测查询、任务、PostgreSQL 元数据或岗位快照 Bucket 容量超过当前形态的可接受范围。
- 某模块需要独立团队、独立发布或显著不同扩缩策略。
