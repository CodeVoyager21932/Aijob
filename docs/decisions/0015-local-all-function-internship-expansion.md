# ADR-0015：先在本机扩展全部职能实习，再决定是否上云

- 状态：superseded by [ADR-0017](0017-local-sme-expansion-and-official-account-boundary.md)
- 日期：2026-07-20
- 决策者：coco
- 关联：[PRD v0.2](../01-prd-v0.2.md)、[MVP 路线](../06-mvp-roadmap.md)、[ADR-0002](0002-allowlisted-official-sources.md)、[ADR-0011](0011-mvp-before-participant-validation.md)

## 背景

当前本机目录只有腾讯、美团和南开就业网·好未来三个来源的 31 条产品/运营实习岗位。coco 的验收反馈认为目录过小，并决定把下一轮本地假设扩展为主流大中型企业官网或企业确认 ATS 中的全部职能实习，先达到 100–200 条，再进行参与者验证。

这一决定扩大了岗位职能、来源数量和证据词典，不代表目标用户价值已经得到验证，也不授权绕过登录、验证码、访问政策或公开发布限制。大陆公开网站、50 家公司和 1000+ 岗位不属于本轮执行范围。

## 决定

1. 本轮只在 coco 的电脑扩展 100–200 条全部职能实习岗位，服务器、域名和公开注册继续延后。
2. 岗位职能扩展为产品、运营、工程、数据/AI、设计、市场、销售/商务、财务、人力/行政/法务、研究/咨询、供应链/制造和其他；旧值保持兼容。
3. 来源先建立候选登记和访问政策评估。只有企业自有官网、经企业主体核验的官方 ATS 租户或高校就业网可以进入配置；真实探测仍需 coco 按批次明确启动。
4. `pending_review` 来源和岗位只能进入本机 `local_mvp`，不能因为数量增加而进入公开 `/v1/jobs`。
5. 适配器改为配置驱动并允许复用 ATS/JSON-LD/确定性 HTML 驱动，但每个企业或 ATS 租户仍使用独立的精确网络白名单和请求预算。
6. 新职能不能降低证据标准：资格、经历证据和偏好继续分开；明确工具必须命中本身；无法稳定归一时保持信息不足。
7. 原 31 岗位的 G2 正确性基线保留，但扩大后的范围重新进入 G2 验收。新范围通过前暂停 G0/G1，不把岗位数量或抓取成功计为用户价值证据。

## 后果

### 正向

- 用更丰富的公司和职能检验跨官方来源决策助手是否有价值。
- 共享适配器减少同类 ATS 的重复实现，同时保留租户级访问控制。
- 不购买服务器即可验证来源维护成本和单 PostgreSQL 容量。

### 负向与成本

- 全部职能会扩大分类金标、证据词典和人工抽检工作量，并推迟参与者验证。
- 主流企业官网的技术可访问性不等于允许长期复制或公开展示；本地候选可能因政策、登录或页面结构被暂停。
- 100–200 条目录需要持续复核，新鲜度和来源维护时间可能成为比存储更大的成本。

### 后续动作

- 完成职能契约、来源配置、请求预算、离线夹具和分职能金标。
- 对优先来源形成逐项评估记录；未获批批次不得运行真实探测。
- 目录达到 100–200 条并完成正确性回归后，重新标记 G2，再依次启动 G0 2 人、G1 6 人和补充样本。

## 复审触发条件

- G1 通过并准备邀请制网页部署。
- 单人来源维护超过每周 4 小时，或 100–200 条仍无法覆盖参与者任务。
- 准备扩到 50 家公司、1000+ 岗位、公开注册或大陆公开运营。
