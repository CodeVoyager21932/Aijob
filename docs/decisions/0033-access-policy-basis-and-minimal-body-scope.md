# ADR-0033：以站点公开访问政策为准入依据，并把岗位正文限定在决策必需范围

- 状态：proposed
- 日期：2026-08-29
- 决策者：coco
- 关联：ADR-0002、ADR-0010、ADR-0016、ADR-0026、ADR-0027、ADR-0029、ADR-0032
- 前置条件：**本 ADR 涉及第三方内容使用的法律判断，建议在转为 `accepted` 前取得法律意见。** 工程实现可先按本文落地并保持全部来源为 `pending_review`。

## 背景

`accessPolicyAccepted` 是 `assessSource()` 六个硬门之一，`hardGatesPassed` 要求全部为真。截至 2026-08-28，**34 个来源配置中该门 0 通过、全部 `fail`**；同时 `policyAccess` 占评分 25 分且全部为 0，而 `hardGatesPassed` 之后仍需 `totalScore >= 75` 才是 `pilot`。这是公开 `/v1/jobs` 长期为 0 的直接原因之一。

复核仓库后发现一个**定义缺口**：

- ADR-0002 的原文是负向标准——「不绕过登录、验证码、访问控制或**明确禁止**的访问边界」，并未要求取得肯定性授权。其复审触发条件写的是「官方开放 API、企业授权数据合作或新的合规结论改变访问边界时复审」。
- ADR-0010 只约束网络目标的精确白名单与 SSRF 边界，不涉及内容使用授权。
- `AGENTS.md` 写「技术上可访问不等于获准聚合或公开」，规定了**需要获准**，但**从未定义什么证据构成「获准」**。

严格口径「需要企业明确授权第三方长期复制并公开聚合岗位正文」只出现在 config 的 `note` 字段中，例如美团配置写「尚无允许第三方长期复制和公开聚合岗位正文的明确授权」。这是逐条评估时形成的惯例，而非任何 ADR 的要求。

后果是该门在实践中不可通过：企业 HR 不会主动出具此类授权，法务流程也不会为一个外部聚合方启动。因此无论发现多少企业，可见供给都恒为 0。本 ADR 的作用是填这个定义缺口，而不是放宽 ADR-0029 的来源归属边界。

## 考虑过的选项

| | 方案 | 证据 | 产出率 | 风险 | 能否支撑 100/1000 |
|---|---|---|---|---|---|
| A | 逐企业书面授权 | 邮件或书面同意 | 极低 | 最低 | 否 |
| **B** | **站点公开访问政策为依据** | robots.txt 时点快照 + ToS 条款摘录 + 无禁止聚合条款核验 | 高 | 中 | 是 |
| C | 只做明确写了允许的 | 公开 API、开放数据或明示允许 | 很低 | 最低 | 否 |
| **D** | **把正文限定在决策必需范围** | 只保留职责与任职要求原句 | 高 | 低 | 是 |

A 与 C 的产出率无法支撑 Private Alpha 供给硬门槛，且 A 的等待时间不可预测。B 与 D 叠加：B 提供准入依据，D 缩小内容暴露面，使 B 的风险进一步下降。

D 曾考虑过三种强度：D1 只保留决策必需原句；D2 正文仅内部存储、公开页只展示结构化字段；D3 正文短 TTL、展示时实时回取。选定 **D1**：D2 会牺牲三轴匹配引用原句解释的能力；D3 会大幅提高触网频率，与 ADR-0026 的低频原则直接冲突。

## 决定

### 一、`accessPolicyAccepted` 的判据

来源满足以下**全部**条件时，`accessPolicyAccepted` 记为 `pass`：

1. **robots 允许**：以本次评估时点抓取的 `robots.txt` 为准，采集器 User-Agent 在该文件下对全部已登记 `fetchTargets` 路径均未被 `Disallow`。取不到 `robots.txt`（缺失、超时、非 200）时**保守视为禁止**。
2. **无禁止聚合条款**：站点服务条款或使用协议中不存在禁止第三方抓取、复制、转载或聚合公开招聘信息的条款。评估须摘录相关条款原文与结论。
3. **未绕过任何访问控制**：延续 ADR-0002，不绕过登录、验证码、Cookie/CSRF 依赖、动态签名、付费墙或速率封锁。
4. **遵守速率约束**：`Crawl-delay` 作为逐来源 `minimumIntervalMs` 的下限；同时继续受 ADR-0010 与 ADR-0026 的逐来源请求预算约束，两者取更严者。

### 二、附随义务（缺任一即不得记为 `pass`）

1. **显著署名与回链**：每条岗位标注来源站点，并提供回到官方原页的链接。
2. **内容限定在 D1 范围**：见第三条。
3. **删除通道**：提供可联系的删除与更正渠道。
4. **异议即停**：收到站点或企业异议时立即将该来源置为 `paused`，不先行争辩。
5. **周期复核**：`robots.txt` 与服务条款会变。每次调度刷新须复核，判定转为禁止时**自动暂停**该来源，不得静默继续抓取。
6. **证据留存**：robots 快照哈希、ToS 条款摘录、判定结论与核验时间须持久化在来源配置中，可复核。

### 三、D1 内容边界

1. 只保留做投递决定所必需的**岗位职责与任职要求原句**。
2. **不复制**公司简介、企业宣传、发展历程、融资与榜单信息、福利待遇、职位亮点等营销文案。
3. 只做删减，**不改写、不摘要、不生成**任何新文本；无法确定边界时保留原文而不是猜测（延续 `AGENTS.md` 的 `unknown` 诚实原则）。
4. 字段级提取不足以保证本条：部分雇主会把公司简介与福利写进 ATS 的职责字段本身。实测 `huice-campus-internships`（北森租户）65 条岗位中 20 条职责含公司简介、18 条含福利文案，平均正文 782 字符，远高于其余来源。因此必须有确定性的段落裁剪，仅在出现明确职责小标题时锚定并保留其后内容，遇非职责小标题即停止。
5. 本条不改变 ADR-0029 第 6 条对职责与要求非空的要求：裁剪后仍须完整到足以做决定，裁剪导致为空时保留原文。

### 四、不改变的边界

1. **不放宽 ADR-0029 的来源归属**：岗位事实仍只能来自企业自有域名页面、企业官网确认的官方 ATS，或其中可映射到具体岗位的企业域名招聘邮箱。高校就业网站、政府公共就业页面、企业公众号继续为 `discovery_only`。
2. 不抓取综合招聘平台与第三方聚合站。
3. 本 ADR 只定义 `accessPolicyAccepted` 的判据，**不自动批准任何来源**：`policy.status` 仍须显式变更，`assessSource()` 仍要求六个硬门全过且 `totalScore >= 75`。
4. 自动化测试、CI、构建、Alpha 与 Production 不访问真实招聘站；robots 与 ToS 的实际抓取属于触网步骤，须由人工显式授权。

## 后果

- 优点：`accessPolicyAccepted` 从一道实践上不可通过的门变成可机械套用的判据，无需逐案主观判断；判据以站点自己发布的政策为准，可复核、可留证；D1 显著缩小内容暴露面，同时保留三轴匹配引用原句的能力。
- 代价：需要新建 robots 抓取、解析与强制执行模块，以及访问政策证据字段与周期复核机制——这些此前完全不存在（全仓仅有一个 User-Agent 字符串 `AijobLocalProbe/0.1 (+official-source-review)`）。逐来源评估成本上升。
- 风险：服务条款的解释存在争议空间，本 ADR 不能替代法律意见。robots 允许不等于内容授权；若后续法律结论收紧，须新增 ADR 并把受影响来源退回 `pending_review`。
- 遗留：`policyAccess` 的 25 分如何按本判据计分尚未细化，暂按「硬门通过则给满分、部分满足不给分」处理，待首批实际评估后再校准。

## 验证

- 判据可机械套用：给定任意来源配置与其 robots/ToS 证据，能确定性得出 `pass` 或 `fail`，无需个案主观判断。
- robots 禁止的 `fetchTargets` 被拒绝执行并给出明确原因码；取不到 robots 时保守拒绝。
- `Crawl-delay` 生效为 `minimumIntervalMs` 下限，且与既有请求预算取更严者。
- robots 或 ToS 判定转为禁止时，来源自动进入 `paused` 并记录原因，不静默继续抓取。
- 存储的岗位职责不含公司简介与福利营销文案；裁剪只删减，逐行可在原文中找到。
- 本 ADR 落地后公开 `/v1/jobs` 仍为 0，直到来源显式提升为 `approved` 且 `runtime_scope` 进入 `alpha`/`production`——这是正确行为。

## 复审触发条件

- 取得法律意见，或出现新的合规结论。
- 站点提供公开 API、开放数据或明示的聚合授权。
- 收到站点或企业异议。
- 首批实际评估完成后校准 `policyAccess` 计分口径。
