# ADR-0029：企业官网与官方 ATS 构成岗位目录唯一真源

- 状态：accepted
- 日期：2026-08-03
- 决策者：coco
- 关联：[ADR-0002](0002-allowlisted-official-sources.md)、[ADR-0016](0016-manual-browser-assisted-source-import.md)、[ADR-0017](0017-local-sme-expansion-and-official-account-boundary.md)、[ADR-0026](0026-local-automatic-source-refresh.md)、[ADR-0027](0027-establish-private-alpha-supply-gate.md)、[ADR-0028](0028-capacity-first-private-alpha-supply.md)
- 替代：替代高校就业网站、政府公共就业页面、企业公众号或其他二手公开页面可直接生成用户可见岗位的旧口径；不改写既有采集事实和不可变岗位修订

## 背景

2026-08-03 的系统审查发现，本地用户目录实际包含 152 条岗位和 30 家企业，其中 38 条岗位、17 家企业来自高校就业网站。高校页面能够证明某企业曾经发布过招聘信息，却不能证明企业官网或官方 ATS 当前仍存在同一具体岗位。现有目录、匹配和洞察只排除 `closed`，仍会接收 `review`、`pending_review`、`stale`、`due`、`unknown` 和存在阻塞复核项的记录；界面又把这些页面统一称为“官方原文”，会使用户把二手历史信息误认为当前企业事实。

同次审查还发现 3 条测试岗位进入开发目录、7 条岗位职责为空、14 条岗位存在来源类型冲突，150/152 条可见岗位仍有未关闭复核项。当前 231/149/29 规划器基线与 152/30 用户目录不一致，因此既有数量只能作为待清洗运行事实，不能继续作为 Private Alpha 供给成绩。

PostgreSQL 真源、模块化单体、确定性适配器、不可变修订、幂等任务和自动刷新仍然适用。根因是岗位事实源与用户目录之间缺少不可绕过的统一资格门，而不是底层架构需要推倒重建。

## 决定

1. 用户目录中的岗位事实只能来自：
   - 企业自有域名上的招聘页面或接口；
   - 企业官网明确链接、且租户主体与企业一致的官方 ATS；
   - 上述页面中能够映射到具体岗位的企业域名招聘邮箱。
2. 高校就业网站、政府公共就业页面、企业公众号、新闻、自媒体和招聘聚合平台统一为 `discovery_only`。它们可以帮助发现企业、官网和候选岗位方向，但不得直接产生浏览、匹配、推荐或洞察使用的岗位。
3. 找不到企业官网、官网招聘入口或官网绑定 ATS 时，保留企业候选和历史证据，但不抓取、不导入用户目录，也不以二手页面刷新岗位活动性。
4. 内部来源配置新增独立于 `sourceType` 的目录角色。`canonical` 才能进入目录；`discovery_only` 只能进入候选审计；`disabled` 不再运行。测试来源必须具有独立运行作用域，非测试目录不得读取。
5. 建立中央岗位资格投影。目录、匹配、推荐、洞察和供给统计必须共同依赖该投影，不能继续分别复制宽松的 `review + pending_review + not closed` 条件。
6. 用户可见岗位至少满足：来源为 `canonical`、官网/ATS 主体绑定通过、具体岗位当前存在、明确实习、职责与要求完整、申请方式能够映射具体岗位、来源状态为 `fresh`、活动状态为 `active`，且不存在阻塞级复核项。
7. `due`、`stale`、`unknown`、主体或来源冲突、申请链拒绝、结构变化、职责或要求缺失均阻止岗位进入用户决策链。分类不确定可以保留真实岗位，但必须诚实显示 `unknown`，且不计入分类配额或分类相关匹配。
8. 高校页面或其他发现线索重新读取成功，不能更新岗位的“官方核验时间”。只有企业官网或官方 ATS 的成功证据才能恢复 `fresh`。
9. 来源级 `fresh` 不能替代岗位级核验。每条岗位必须在当前来源政策的刷新周期内由官网/官方 ATS 再次看见；部分刷新不得把本次未观察到的历史岗位整体恢复为可见。
10. 只有由仓库中精确来源配置登记的当前政策才能进入资格集合。历史、测试或孤立数据库来源即使字段看似完整，也必须以 `SOURCE_CONFIG_NOT_REGISTERED` 隔离。
11. 既有来源修订、证据和岗位版本保持不可变；不合格记录进入隔离状态而不是被删除。若在企业官网找到同一岗位，应创建新的官方来源记录并保留线索关联，不能把高校记录原地提升为官方记录。
12. 在中央资格门、测试数据隔离、可信目录重物化、1000 岗推荐完整性、Alpha 身份入口和简历解析隔离通过前，暂停新的真实来源扩容、G0/G1 和外部用户测试。本机自动刷新总开关保持关闭。

## 后果

- 优点：用户看到的“当前岗位”重新具有统一、可复核的企业事实来源；高校历史页不会再制造活动性错觉；目录、匹配和洞察使用同一资格集合。
- 代价：清洗后可见岗位和企业数会显著下降，100/1000 目标必须从新的可信分母重新计算。
- 风险：部分中小企业没有公开官网招聘系统，将无法进入当前产品目录。该缺口应通过更多官方 ATS 来源族和企业官网发现解决，不能降低证据标准补数。

## 验证

- 非 `canonical` 来源的用户可见岗位为 0。
- 测试来源、虚构企业和测试岗位在非测试目录中为 0。
- 可见岗位的阻塞复核项、非 `fresh` 状态、空职责或空要求均为 0。
- 可见岗位的来源配置登记缺失与岗位级核验过期均为 0；部分刷新不能刷新未观察岗位。
- 申请入口 100% 能对应具体企业官网岗位、官方 ATS 岗位 ID，或官网具体 JD 明示的企业域名邮箱。
- 目录、匹配、推荐、洞察和供给报告使用同一资格投影，并在 PostgreSQL 集成测试中证明集合一致。
- 公共 `/v1/jobs` 继续返回 0，直到独立公开准入通过。
