# ADR-0010：采用精确采集网络策略并延后 Playwright

- 状态：accepted
- 日期：2026-07-15
- 决策者：项目维护者
- 关联：ADR-0002、来源与采集设计、安全威胁模型

## 背景

仅按主机名放行无法安全处理共享 ATS：同一域名可能承载多个企业租户。重定向、DNS rebinding、IPv6、路径混淆和浏览器子资源还会扩大 SSRF 与越界采集风险。首批来源不需要浏览器即可验证数据价值。

## 决策标准

- 一个企业来源不能授权访问同 ATS 的其他租户。
- 每次请求和重定向都能在网络层证明目标获准。
- 采集器无法访问内网、用户数据服务和宿主机。
- MVP 不承担浏览器执行任意页面脚本的攻击面和成本。

## 选项

### 选项 A：只维护域名白名单

- 优点：配置简单。
- 缺点：共享 ATS、路径和重定向边界过宽。

### 选项 B：协议、主机、端口、路径/租户精确策略

- 优点：授权范围可审计，并能逐跳执行。
- 缺点：每个来源准入和维护成本更高。

### 选项 C：默认使用 Playwright 让页面自行加载

- 优点：兼容更多动态站点。
- 缺点：脚本、子资源、下载、CPU 和任意网络请求显著扩大风险。

## 决定

选择选项 B，并延后选项 C：

- `SourcePolicy.fetch_targets` 同时限定 `https`、IDNA 规范主机、端口和路径前缀/租户 ID。
- 共享 ATS 为每个企业租户建立独立来源政策，不能继承整站权限。
- 申请链接使用独立 `apply_targets`，不继承采集权限。
- 每次请求及每一跳重定向校验 URL、DNS 全部地址和网络分类；连接使用已验证地址并保持 TLS 校验。
- 网络层阻断私网、环回、链路本地、保留地址、云元数据、宿主机和其他服务。
- 工程 MVP 不安装或运行 Playwright；`browser_required` 来源保持暂停。
- collector 使用每来源频率、并发、响应大小、超时、重试预算和 `Retry-After` 策略。

## 后果

- 正向：来源许可和网络访问范围一致，SSRF 与共享租户越界风险显著降低。
- 负向：首批可接入来源更少，准入配置和测试工作增加。
- 后续：为 URL 规范化、重定向、DNS rebinding、IPv4/IPv6 和共享 ATS 建立固定安全用例。

## 复审触发条件

- 已验证的高价值官方来源只能通过浏览器取得，且 HTTP 适配器无合理替代。
- 能够为浏览器提供独立进程、全子资源拦截、禁止下载/持久化和资源限制。
- 浏览器方案通过新的安全、成本和维护 ADR。
