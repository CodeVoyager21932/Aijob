# ADR-0005：采用匿名邀请会话、owner 所有权和最小保留

- 状态：accepted
- 日期：2026-07-15
- 决策者：项目维护者
- 关联：PRD、安全威胁模型、合规与上线阶段门

## 背景

邀请制工程 Alpha 需要处理简历文本和匹配结果，但当前没有公共注册、跨设备同步和账号恢复需求。完全匿名且只依赖客户端对象 ID 无法安全执行对象授权与删除；提前建设密码或第三方登录又会扩大身份数据和攻击面。

## 决策标准

- 服务端能够可靠确定每个用户对象的所有者。
- 不为私测提前收集邮箱、手机号或密码。
- 用户可以更正、撤回和删除数据。
- 保留时间明确、自动执行且可审计。

## 选项

### 选项 A：公共账号系统

- 优点：支持跨设备和账号恢复。
- 缺点：增加凭据、找回、撞库、通知和合规范围。

### 选项 B：客户端持有对象 ID，无服务端会话

- 优点：实现最少。
- 缺点：对象 ID 泄露即越权，无法形成稳定 owner 边界。

### 选项 C：一次性邀请令牌换服务端匿名会话

- 优点：不收集身份凭据，同时具备服务端 owner 与撤销能力。
- 缺点：默认不能跨设备；Cookie 丢失后的恢复能力有限。

## 决定

选择选项 C：

- 一次性高熵邀请令牌只保存哈希；邀请链接使用不会发送到服务器或 Referer 的 URL fragment，同源引导页通过 POST body 交换，成功后令牌立即失效并从浏览器地址与历史记录中移除。
- 服务端会话通过 Secure、HttpOnly、SameSite=Strict Cookie 维持并映射内部 `owner_id`；邀请交换时固定最长 30 天的 `owner_expires_at`，所有 owner 数据和正常会话都不得晚于它，访问、新修订或再次确认不能续期。
- 所有用户对象查询同时限定对象 ID 与服务端 owner，客户端不能指定 owner。
- 原始简历文本在证据确认后立即删除，未完成确认或异常中断时也最长不超过提交后 24 小时；结构化事实、偏好、证据和匹配固定最长保留 30 天且可提前删除；无正文安全/删除审计保留 90 天。
- 删除立即撤销全部个人数据访问并创建可查询的异步清理任务；墓碑进入可恢复的持久 WAL/等效日志后才返回 `202 Accepted`。原会话降为最长 24 小时、只能查询或幂等重试该删除请求的受限能力，成功终态首次返回或到期后撤销，失败态在期限内仍可重试；恢复旧备份后先重放删除墓碑，恢复链不完整时隔离用户数据而不是开放读取。

本地完整 MVP 允许在 loopback/localhost 环境首次访问时自动创建匿名 owner，以便单机完成端到端链路；该例外必须由服务端环境配置固定，不能由客户端参数开启。Preview、Alpha 和任何非 loopback 环境仍使用上述一次性邀请交换，不因本地例外放宽 owner 鉴权、到期或删除规则。

## 后果

- 正向：在不建设完整账号系统的情况下形成可测试的对象授权和数据生命周期。
- 负向：会话丢失可能无法自行恢复历史数据；Alpha 不提供跨设备体验。
- 后续：实现邀请重放、CSRF、对象越权、自动过期和备份删除测试。

## 复审触发条件

- 用户研究证明跨设备、长期记录或账号恢复是核心价值。
- 产品从邀请制进入公共注册。
- 法律或运营要求需要更强身份核验。
