# ADR-0011：先构建本地 MVP，再进行参与者验证

- 状态：accepted
- 日期：2026-07-18
- 决策者：coco
- 取代：[ADR-0004](0004-concierge-before-automation.md)
- 关联：MVP 路线、产品发现、验证与质量、当前项目交接

## 背景

原路线要求先用 2 名目标用户校准协议，再用 6 名正式用户完成人工礼宾验证，之后才开始 MVP-0 工程实现。当前仓库已经具备一个安全受限的官方来源采集纵向切片和 5 条人工确认研究岗位，但匿名会话、用户约束、经历证据、三轴判断、岗位决定和删除等核心产品旅程尚未实现。

2026-07-18，coco 明确决定：**当前不进行参与者检验，等可用 MVP 完成后再进行。** 在核心旅程尚不存在时继续招募和记录参与者，不符合当前项目推进优先级。

## 决定

1. 立即允许开始 `G2 Local Complete MVP` 工程纵向切片，不再把 2 人校准或 6 人正式验证作为编码前置条件。
2. 产品证据仍保持 `E0`。开始构建只表示接受有限工程投入，不表示问题、价值或市场需求已经验证。
3. MVP 达到端到端可操作状态后，再按固定协议执行：先 2 人校准，再 6 人正式任务与 72 小时回访。
4. Gate ID 为保持历史引用而不重编号。当前执行顺序为：`G2 Local Complete MVP -> G0 协议可用 -> G1 MVP 用户价值`；`G3 数据可持续`可与 G2 并行。编号不再表示执行先后。
5. Private Alpha 仍必须等待 G0、G1、G2、G3 全部通过。参与者验证只是后移，不是取消。
6. G2 全部切片只在本地 `dev/test` 运行。未通过来源准入的岗位只进入 `local_mvp`，不得进入公开目录；公开 `/v1/jobs` 保持现有政策闸门。
7. 本地完整 MVP 的 AI、推荐和简历优化边界随后由 [ADR-0013](0013-local-ai-recommendation-and-resume-tailoring.md) 修订：本地必须实现并显式启用验证，公开环境仍需 MVP 用户验证证明增量后才能启用。规则与固定模板、可纠正证据和删除链路必须继续独立工作。

## 首个工程切片

先完成一个不依赖简历或 AI 的本地岗位决策闭环：

```text
匿名 owner 会话
  -> 浏览 5 条人工确认岗位
  -> 保存五态岗位决定
  -> 前往官方链接
  -> 返回后恢复状态
  -> 删除 owner 数据
```

五态固定为：`未决定 / 已保存 / 准备投递 / 已投递 / 已放弃`。会话之间必须隔离；刷新和外链返回后状态必须保留；删除必须立即撤销访问并可幂等重试。

该切片只是实现顺序，不是完整 MVP 定义。完整 MVP 还必须完成三来源目录、PDF/DOCX/文本简历、三轴匹配、`RecommendationRun`、`ResumeTailoringRun`、DOCX 导出和数据删除，具体以 [PRD v0.2](../01-prd-v0.2.md) 为准。

## 后果

- 正向：先获得可完整操作的产品对象，后续用户测试针对真实 MVP，而不是不完整的研究壳。
- 正向：当前工程目标清晰，可以按匿名会话、决定闭环、事实/偏好、简历证据、三轴判断逐片交付。
- 负向：在用户价值仍为 E0 时承担了一段额外工程成本，必须严控范围，不能借机扩展平台或基础设施。
- 负向：如果 MVP 后验证失败，部分实现可能被修改或废弃；这属于本决定明确接受的风险。
- 约束：不得把工程进度、岗位数量或页面可用性写成 G0/G1 或用户价值证据。

## 复审触发条件

- 本地 MVP 核心旅程无法在约定范围内完成，工程成本明显超过预期。
- 需要公开发布、接入真实简历或启用外部 AI 供应商。
- MVP 完成后的 2 人校准或 6 人验证显示术语、流程或价值主张需要实质改变。
