# Aijob 简历系统：开源调研、问题判断与升级方案

研究日期：2026-09-10。状态：研究完成，方案待 coco 确认。本轮未修改应用代码、数据库、模板或运行配置。

## 1. 建议先对齐的结论

这次应按“简历核心能力重新验收”处理。当前问题已经超出换色、补按钮的范围：模板结构的适配质量、编辑时的内容呈现、PDF 完整性需要一起处理。

建议保留 Aijob 的简历、经历、版本、投递稿、导入和 BYOK 基础，重建简历工作室中的模板实现、纸张预览与导出质量控制。编辑交互主要参考 BOSS 与 OpenResume，模板架构重点参考 Reactive Resume，中文排版参考 LapisCV 与 billryan/resume，长材料参考 RenderCV。各自解决不同问题，不整体复制另一套产品。

30 套模板仍是最终交付范围，其中 24 套专业、6 套适度创意。先完成少量代表版式的完整链路，是为了固定质量标准；不能把这一步当成最终交付，也不能继续用 30 个模板 ID 代表 30 套合格成品。

当前尚不能确认用户那份 PDF 的全部丢失原因：本轮尚未取得该文件及对应正文。已确认纸张中的部分内容是编辑引导，不会导出；真实已填写正文有没有被遗漏，必须单独追踪，不能用这个发现解释掉用户反馈。

## 2. 检索范围与证据等级

本轮通过 GitHub REST API 的 15 种查询、16 页结果，结合已知仓库、中文资源索引、官方站与源码链接继续追踪，取得 362 个去重候选。查询覆盖 resume builder、resume maker、cv builder、cv maker、resume generator、resume template、JSON Resume、Typst、中文“简历/简历制作”及相关 topic。原始查询和抓取时间保存在本目录的 github-search 文件中。

从中整理 130 个相关项目或资源：44 个编辑器/工作台候选、17 个生成器/标准工具、42 个纸张模板/样式包、14 个网页履历主题、9 个资源索引、4 个教学示例。57 个条目达到 1,000 Star。后几类单列，是为了避免把高 Star 的个人主页、教程和资源列表误认成成熟简历软件。

“尽量完整”指这次明确检索范围内的系统整理，不宣称覆盖 GitHub 全部项目。低于 100 Star 的两个例外是此前采用的 Magic-Resume/Magic-Resume，以及作为补充模板集合的 davidculemann/typst-templates。它们不进入“高 Star 成熟项目”的论证。

本轮保留了 130 份 README 快照；其中 10 个项目的 41 个实现文件按提交固定，另有 12 份源码树记录。实际访问了 OpenResume 编辑器、BOSS 模板库与模板详情、Reactive Resume 官网与登录入口、best-resume-ever 模板演示，以及 FlowCV 公共页面。Reactive Resume 未登录编辑器；Magic 在线站访问超时；没有把这两者描述为完整实机验收。

另读取 5 份官方 PDF 样张，共 11 页，逐页提取文本并检查首屏版式：Reactive Resume 的 Gengar、Onyx，RenderCV 的 Classic、Engineering Resumes，以及 billryan 的中文样张。这些只证明所查看样张的表现，不代表它们已经适配 Aijob 或所有中文输入均正确。

Star、push 时间、归档状态来自 2026-09-10 的 API 快照。push 时间只表示仓库发生推送，不等于功能已更新或质量有保证。许可证列保留 API 识别结果；识别不明、附加限制、单独资产许可均不能简化成“免费即可照搬”。完整项目清单见同目录《开源项目目录.md》、catalog.csv 与可筛选研究页。

## 6. 推荐的产品体验

### 6.1 写作与纸张

保留连续模块表单和纸张双栏，但先保证两个区域各自可用。进入工作室默认收起全局侧栏，顶部保留明确返回；笔记本优先保证文字编辑宽度。模块目录用紧凑定位栏，点击定位；已写条目可折叠成“学校/项目名 · 角色 · 时间”的摘要，编辑当前条目时其他材料仍然容易找到。

基础字段使用紧凑的一行或两行排列，长描述自然展开。教育与项目使用各自字段，不让学生先理解“模块”“栏位”“分页规则”。排序、隐藏、复制、改名放在条目/模块菜单中，添加和删除撤销容易发现。页边距、栏宽、分页等属于排版工具，不在每个新条目上默认展开。

点击纸张中的真实条目可以定位表单；输入不强制滚动纸张。模板、材料和 AI 面板打开后保留当前输入、选区及滚动位置。AI 仍使用最新条目与完整经历上下文，采用建议可撤销，不增加新的事实审批流程。

纸张只显示真实可输出的正文。填写示例放在字段旁可展开的帮助中；模板完整样稿放在图库中明确标为“样稿”。空白文档可以显示一张空纸与旁边的开始入口，不再把大片“待填写”虚线框伪装成最终稿，也不自动将样稿写进用户简历。

### 6.2 模板选择和应用

图库采用稳定的列表区与详情区。桌面打开某张模板后，列表仍可滚动；详情不插到整个列表顶部把剩余卡片挤出屏幕。窄屏切换到详情页，返回时恢复筛选、位置与候选。弹层头部/操作区固定，主要列表只有一个滚动容器，避免弹层、比较区、iframe 三层互相截住滚轮。

默认用同一份完整中文短样稿展示版式。选择“我的内容”后仅渲染当前候选，最多同时对照 3 套。详情提供上一套/下一套、当前选择、应用和返回；应用后纸张显示实际模板名，并可撤销到之前排版。

应用模板改变页眉、模块标题、条目/日期关系、栏位默认值、字号间距与分页约束，保留真实正文、模块显示状态和完整经历关联。对旧的手动栏目分配需要明确定义兼容迁移，不能留下模板设为单栏、旧数据仍强制分栏的混合状态。

默认强调正式、清楚、适合学生的版式，保留丰富选择。照片可选；无照片仍需自然排版。科研简历允许自然多页。普通短材料以可读的一页为基准，超过容量时提示用户可精简/换紧凑版式/保留多页，不自动丢条目或缩成难读的小字。

### 6.3 下载的信任感

“已自动保存”“预览正在更新”“PDF 已生成”是三个不同状态。导出固定本次正文、布局、模板和字体版本；失败显示真实原因并保留输入。

下载时无需增加审批页。可选的“查看最终 PDF”直接打开这次待下载的同一份文件，而不是再造一份近似 HTML。只写姓名仍可保存为草稿；若要下载，清楚展示真实内容量，不靠填写引导制造已经成稿的错觉。

## 7. 系统架构与排版路线的选择

### 7.1 保留的部分与需要重建的部分

保留 PostgreSQL、模块化单体、owner 隔离、导入原件、经历库、自动保存、正文/布局修订、投递稿、面试上下文和 BYOK。重建范围集中在：模块输出适配、独立模板组件、字体与分页、纸张预览、模板图库、导出完整性检查。

建议形成明确链路：当前草稿 → 固定正文/布局修订 → 规范化文档结构 → 指定模板与字体版本 → 排版结果 → 预览/PDF/DOCX。文档结构包含真实字段、富文本、顺序、隐藏状态和经历关联；写作提示、图库样稿、按钮与高亮不进入该结构。

每个可见条目形成一个内部内容清单，用于验证标题、日期、正文、链接是否进入结果。清单服务于系统验收和错误定位，不让用户管理证据 ID。旧数据使用兼容读取，新模板不批量重写已投递稿或旧导出文件。

### 7.2 引擎比较

| 路线 | 优点与依据 | 对本项目的代价 | 建议 |
|---|---|---|---|
| 独立 HTML 模板 + Chromium | 现有基础可用，富文本/中文/CSS 易衔接；Resume Matcher 采用此路线 | 必须重新保证分页、字体、预览和打印语义一致，不能沿用当前过度通用的模板表达 | 作为保留路线参与验证 |
| React-PDF 文档组件 | Reactive Resume 的模板真正由 PDF Page/View/Text 等组件组织；浏览器和服务器可共用文档定义 | HTML/Tiptap 富文本需明确映射，布局不是任意 CSS；中文字体、实时预览性能需实测 | 作为主要替换候选，与上一条用同一材料比较 |
| Typst / LaTeX | 专业文档排版与科研长材料有成熟参考，RenderCV/传统 CV 模板体现这一点 | 增加编译环境、富文本映射与交互预览成本；多引擎会放大模板维护量 | 本轮作为版式与长材料参考，暂不同时维护第三条生产链路 |
| 网页截图转图片 PDF | 容易得到表面近似截图 | 不满足可复制文本、链接及可靠内容结构的要求 | 不采用为主导出路径 |

本方案不凭 Star 数断言哪个引擎“性能最高”。审批后的第一段工程验证只比较前两条：同样的中文短稿、双栏多经历稿、科研长稿，以及同样的 3 个参考版式。对比字段完整、文本复制、中文/富文本、真实分页、预览一致性、编辑延迟与部署成本，完成一轮后锁定唯一新主路径。

**推荐取舍：必须替换现在的通用模板拼装方式；引擎是否替换由上述限定验证决定。** 达到全部质量要求时，优先选择改动更少、长期维护更清楚的路线；当前 HTML 路径不能满足时，转为 React-PDF，而不是继续叠加局部补丁。引擎切换如改变现有 ADR，随实施记录为明确的新决定。这个选择由工程证据完成，不把技术选型负担交给 coco。

依据：[Reactive Resume 文档组件](https://github.com/amruthpillai/reactive-resume/blob/730f795073126e850cab348038f9557da6f810fd/packages/pdf/src/document.tsx)、[Gengar 模板](https://github.com/amruthpillai/reactive-resume/blob/730f795073126e850cab348038f9557da6f810fd/packages/pdf/src/templates/gengar/GengarPage.tsx)、[Resume Matcher PDF](https://github.com/srbhr/Resume-Matcher/blob/0932418cf694de227fd5ca030ddbc0d1f40b1bef/apps/backend/app/pdf.py)、[RenderCV 渲染](https://github.com/rendercv/rendercv/blob/1d4b87bc427e4cf61c0ef49623c971b0e2224708/src/rendercv/renderer/pdf_png.py)、[React-PDF 分页文档](https://react-pdf.org/docs/v4/advanced)、[Chromium PDF 接口](https://playwright.dev/docs/api/class-page#page-pdf)。

### 7.3 接口、保存与导出

- 现有 Studio 保存接口继续使用 expectedRevision，并同时保存正文与布局；富文本变换、模板应用和 AI 采用进入同一撤销历史。
- 模板注册表扩展为模板组件/规则、版本、来源、字体需求、模块能力与默认值；不再只用几个通用字符串表达整套模板。
- 导出请求绑定确定修订，内部记录 contentRevision、layoutRevision、templateVersion、rendererVersion、fontSetVersion。再次下载同一产物无需重新渲染。
- 生成结果记录页数、预期可见条目与输出条目的覆盖、文本抽取结果及失败阶段。不能用仅有页数/文件大小的检查代表内容完整。
- PDF 后端只加载受控字体与照片；继续使用现有 Noto 资产，不因复制模板顺带引入来源不清的字体。
- DOCX 独立适配相同内容结构，重点验证完整、可编辑、层级与顺序；不承诺不同办公软件像素一致。
- 新渲染版本通过兼容部署启用；旧模板 ID 能恢复旧稿，迁移不覆盖不可变投递文件。回退到具备新版读取能力的兼容版本。

## 8. 审批后的执行顺序

| 阶段 | 具体工作 | 完成条件与交付物 |
|---|---|---|
| S0 复现与冻结基准 | 取得失败 PDF/对应修订，逐层检查草稿、快照、渲染树、分页、PDF；建立中文短/中/长基准，保存当前表现 | 能说明哪些内容在哪一步丢失；未知项明确记录，不先猜原因 |
| S1 固定版式与渲染路线 | 对照原版样张，验证专业单栏、照片双栏、科研多页；完成两种候选引擎的限定比较 | 有同内容的原参考/新预览/最终 PDF 对照，锁定主路径与字段输出契约 |
| S2 完成工作室核心 | 连续模块表单、条目折叠、稳定双栏、工具分级、材料/AI 就地调用；实现可靠预览/导出 | 从空白和导入都能做出可实际投递稿；编辑、保存、预览和导出同一修订可核对 |
| S3 重建模板图库与 30 套版式 | 按累计 10/20/30 套验收；真实中文缩略图、候选详情/比较、筛选、收藏、返回状态；逐套来源和独立结构 | 30 套均通过内容、视觉、分页；无占位卡片充数，不按配色计为新模板 |
| S4 联合验收与交付 | 旧稿兼容、完整求职链、AI 迟到/保存冲突、移动端/缩放、导出并发、性能；更新路线图与交接 | 实际旅程通过，实测证据与未配置项分列；不能仅凭 lint/test 通过宣布完成 |

S0 的 PDF 定位优先级最高。研究阶段没拿到失败文件不妨碍先准备基准和对标，但在实施中不能跳过真实失败样本而直接宣布“PDF 已修好”。若文件已丢失，用 coco 同样的输入路径生成新样本再定位。

每阶段记录五类结果：Contract（字段/修订/模板含义）、Database/Platform（保存与导出）、Web（实际交互）、Integrated Gate（端到端）、Evidence（可打开的样稿/PDF/记录）。改动涉及修订、迁移、owner 或幂等时运行专属 PostgreSQL 集成验证。

## 9. 这次怎样验收，避免重复失败

### 9.1 模板质量

每套模板保存来源截图/官方样张及 Aijob 中文样稿。对照页眉、栏位、模块标题、条目/日期位置、字体层级、留白与续页方式逐项检查。可以因中文适配调整，但每项差异有解释，不能把原版重新简化成同一套通用卡片。

最终仍执行 30 套 × 3 份代表材料，至少 90 组预览/PDF/DOCX；另外加入只写姓名、超长单条、无照片/有照片、隐藏模块、手动分页、长链接和导入残留格式等边界场景。90 组是最低覆盖量，不是“只要生成了文件就通过”。

普通短稿不出现被空标题、默认分页或留白挤出的第二页；科研材料自然续页；超长条目可合理拆分。所有可见真实字段完整输出，空模块不占纸张。

### 9.2 PDF 完整性

对预期正文建立规范化清单，再抽取 PDF 文本比较。姓名、电话、邮箱、学校/企业、日期、条目标题、正文中的中文、数字、百分号、链接必须能读回；所有可见非空条目均进入文件。允许换行/空格等排版差异，不允许整段、数字或关键字段静默丢失。

文本检查之外，检查页面视觉：文字不能是白字白底、被边框覆盖、移到页外或被 overflow 裁掉。双栏阅读顺序、链接可用性和字体嵌入单独验证。文字能抽取也不自动等于“所有 ATS 都兼容”。

检查实际下载路径，而非只调用底层渲染函数；覆盖保存后立刻下载、刚换模板下载、导入后下载、恢复版本后下载、并发改稿与导出超时。最终预览和下载文件对应相同修订和产物。

### 9.3 编辑体验

验证“新建 → 填两段经历 → 换模板 → 调整一处表达 → 导出 → 返回继续编辑”。另验证导入、经历复用、方向稿复制、已投递稿与面试上下文稳定。模板详情不能挡住后续选择；返回列表不丢位置；取消辅助工具不丢输入。

覆盖 1440/1280/1024 宽度、360/320 手机宽度、原生 200% 缩放、中文输入法、软键盘、键盘焦点和撤销重做。屏幕变窄时切换编辑/预览，保留位置；表单不随整张 A4 纸缩成小字。

### 9.4 性能和真实配置

沿用既定目标：典型 1–5 页输入响应 p95 ≤100ms，正常保存请求 p95 ≤500ms，首个可用编辑界面 ≤2 秒，模板切换/分页争取约 1 秒稳定。先记录同机基线，再与新版比较；图库个人预览最多 3 套，不同时挂载 30 个完整文档。

保存、分页与导出分开测量，后台并行时再测。较旧分页或 AI 结果不能覆盖新输入。真实 AI 仍以用户自行配置 API 为条件；无配置时只记录手工路径与夹具通过，不冒充真实模型联调。

## 10. 本次待确认范围

建议 coco 确认的是这套方向：保留既有业务，以 BOSS/OpenResume 的编辑任务组织、Reactive Resume 的模板工程、LapisCV/billryan 的中文排版和 RenderCV 的长材料能力作为主要依据；优先查清 PDF 正文丢失，再重建模板适配与工作室，最终交付 30 套逐套验收的模板。

本次研究包已经可以作为执行依据，但它不代表修复已经发生。应用代码、数据库和旧文件均未因本次研究被改动；源码快照与官方样张仅保存在研究目录。收到 coco 对方案的同意后，才进入 S0–S4 实施。
