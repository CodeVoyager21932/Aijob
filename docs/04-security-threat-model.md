# 安全威胁模型与依赖准入

## 1. 安全目标

平台同时处理外部网页、用户粘贴的简历文本和可选 AI 输出，三者均是不可信输入。即使某一输入恶意，影响也不能跨越来源采集、用户数据、匹配和运营边界。

主要资产：

- 用户简历、画像事实、求职偏好、匹配结果和邀请会话。
- 来源政策、岗位版本、要求集和人工审核结论。
- PostgreSQL、岗位快照 Bucket、备份、审计记录和迁移凭据。
- 模型 API 密钥、会话签名密钥和 CI/CD 凭据。
- 服务器、开发电脑和构建/发布环境。

本地完整 MVP 接收最大 5 MiB 的 PDF/DOCX 或纯文本，并按 ADR-0012 隔离解析；不接受图片、旧版 `.doc`、压缩包、宏或加密文档。不运行生产 Playwright，不部署公共管理端、独立搜索、向量库、Redis 或消息代理。

## 2. 运行时信任边界

```text
公开浏览器
  -> TLS/Edge
  -> web-api
       -> PostgreSQL 的公开目录、owner 用户数据和任务接口

批准的公开招聘目标
  <- collector-worker
       -> PostgreSQL 的来源、采集、岗位候选和任务接口
       -> 岗位快照 Bucket 的 collector 专用前缀

允许列表中的 OpenAI-compatible 端点（本地用户显式启用）
  <- match-worker
       -> PostgreSQL 的指定用户输入、岗位版本和匹配接口

维护者
  -> internal ops CLI
       -> 来源审批、岗位复核和审计接口
```

PostgreSQL 是唯一查询、任务和元数据真源；岗位快照 Bucket 只保存原始公开岗位响应正文，不保存用户简历或其他用户数据。边界通过独立进程、服务账号、数据库角色、Bucket 前缀策略、出站网络策略和密钥作用域执行，不只依赖代码约定。

### 2.1 权限矩阵

| 主体 | 允许 | 明确禁止 |
|---|---|---|
| `web-api` | 匿名读取已发布岗位；按 `owner_id` 创建/读取/修改/删除用户对象；写入任务和最小产品事件 | 任意外部 URL 请求；读取岗位快照 Bucket 或持有其凭据；批准来源；读取其他 owner 数据；持有采集或模型密钥 |
| `collector-worker` | 读取已批准 `SourcePolicy`；访问精确采集目标；读写岗位快照 Bucket 的 collector 专用前缀；写采集运行、快照元数据、来源修订和岗位候选 | 读取用户 schema、简历或匹配结果；访问专用前缀之外的 Bucket 对象；访问模型；修改来源审批；访问宿主机和内网 |
| `match-worker` | 隔离解析任务指定 owner 的文档；写不可变 `MatchRun`、`RecommendationRun`、`ResumeTailoringRun` 和导出；通过受限幂等函数执行已写墓碑的 owner 删除任务；显式启用后访问批准模型域名 | 代替用户修改 `JobDecision`；任意删除 owner 数据或删除无有效墓碑的数据；访问采集网络、原始网页或岗位快照 Bucket；读取其他 owner 数据、管理来源或执行模型输出 |
| `internal ops CLI` | 使用独立维护者身份审批/暂停来源、人工导入结构化岗位候选、复核岗位、查看脱敏质量、快照元数据和审计记录 | 作为公共 HTTP 管理端暴露；默认读取简历原文或岗位快照正文；绕过审计直接修改生产表 |

数据库角色只授予所需 schema、表和操作权限。应用不能使用数据库 owner/superuser 凭据。生产密钥按进程分别注入和轮换。

PostgreSQL 任务基表不直接授予 Worker 查询权限。`collector-worker` 只能通过受限函数领取 `crawl` 类型，`match-worker` 只能领取 `resume_analysis/match_run/recommendation_run/resume_tailoring/resume_export/owner_deletion` 类型；返回字段按类型最小化。任一 Worker 都不能列出、领取或读取另一权限域的 owner、payload 引用或错误详情。

## 3. 主要威胁与控制

| 威胁 | 后果 | 必须控制 |
|---|---|---|
| SSRF、重定向、DNS rebinding | 访问内网、云元数据或未批准租户 | 精确目标策略、逐跳校验、DNS/IP 校验、连接地址固定、网络层拒绝私网和保留地址 |
| 共享 ATS 越界 | 抓取同主机其他企业租户 | 协议/主机/端口/路径前缀和租户标识共同准入 |
| 超大或压缩响应 | 内存、CPU、磁盘耗尽 | 流式读取、压缩后/解压后上限、超时、并发与频率限制 |
| 存储型 XSS | 岗位内容在浏览器执行 | 原始 HTML 不出岗位快照 Bucket；仅规范化纯文本进入发布版本；上下文转义；CSP 与禁止内联脚本 |
| 快照越权、替换或缺失 | 泄露原始响应、错误版本发布或无法复查 | Bucket 禁止公开访问；collector 专用前缀；确定性对象键；上传后校验哈希/大小；对象不可用时阻止发布；无引用对象满 24 小时后清理 |
| 恶意简历文档 | 解析器利用、解压炸弹、资源耗尽或临时文件泄露 | 三重类型校验、DOCX 结构/解压限制、无网络隔离子进程、资源预算、AES-GCM 暂存、临时目录清理 |
| 间接提示注入 | 岗位/简历改变模型行为 | 用户显式启用；结构化最小输入；模型无工具；固定 Schema；引用校验；模板降级 |
| 邀请令牌泄露或重放 | 未授权访问私测和用户数据 | 一次性令牌、只存哈希、短期有效、交换后失效、URL 清理和安全 Cookie |
| 对象级越权 | 读取或删除其他用户数据 | owner 由会话派生；查询强制 owner 条件；不可使用客户端 user/owner 参数；授权测试 |
| 删除与异步任务竞态 | 删除后旧解析/匹配任务重新写入用户数据 | 删除事务写墓碑、递增 `owner_epoch` 并取消待处理任务；所有用户任务提交校验 epoch、墓碑和到期时间 |
| CSRF、会话固定 | 未经用户意愿执行写操作 | Secure/HttpOnly/SameSite Cookie、CSRF 令牌、登录后轮换会话、状态变更只接受非 GET |
| 滥用与成本耗尽 | 任务、数据库或模型成本失控 | 会话/IP 速率限制、输入上限、并发和日预算、有限重试、熔断和 AI 总开关 |
| 简历隐私泄露 | 个人信息进入日志、模型或他人空间 | 去标识提示、PII 过滤、最小传输、加密、保留期限、日志脱敏、删除任务和审计 |
| AI 越权判断 | 覆盖硬规则或编造经历 | 三轴由确定性代码计算；模型只生成受约束解释；ID 引用与 Schema 校验 |
| 供应链攻击 | 安装或构建阶段执行恶意代码 | 官方来源、锁版本/哈希、安装钩子审查、漏洞/Secret 扫描、最小 CI 权限 |
| 数据或解析回滚失败 | 错误岗位或三轴结果持续对外 | 不可变版本、活动指针、夹具回归、迁移策略、备份恢复和发布回滚演练 |

## 4. 采集网络策略

### 4.1 精确准入

采集目标必须来自已批准 `SourcePolicy.fetch_targets`，每项同时限定：

- 协议仅 `https`。
- IDNA 规范化后的主机名。
- 标准端口 `443`；例外必须单独评审。
- 规范化路径前缀；共享 ATS 必须限制企业租户路径或租户 ID。
- 是否允许重定向及独立的重定向目标集合。

拒绝 URL 用户信息、IP 字面量、混淆编码、路径逃逸、非 HTTP 协议和未经批准的查询参数模板。申请链接使用独立 `apply_targets`，不能借用采集权限；前台不提供可控开放重定向。

### 4.2 DNS 与连接

- 每次请求和每一跳重定向都重新解析并校验全部 A/AAAA 地址。
- 环回、私网、链路本地、组播、保留地址和云元数据地址一律拒绝。
- 校验后连接到已验证地址，并保持正确 TLS SNI/证书校验，避免校验与连接之间再次解析。
- 采集运行环境在网络层不能访问数据库管理接口、宿主机服务、用户数据服务或模型域名。
- 遵守 `Retry-After`，使用有抖动的指数退避和每来源重试预算。

### 4.3 动态页面

工程 MVP 不运行 Playwright。标记为 `browser_required` 的来源保持暂停，不能在普通 HTTP 适配器中偷偷启用浏览器。

未来评估浏览器时必须新增安全复审：隔离进程、全子资源拦截、禁止下载/弹窗/持久化配置、CPU/内存/时间限制和单来源故障隔离。

## 5. 邀请会话与对象授权

### 5.1 公开和私有边界

- 公开/Alpha 岗位列表与详情允许匿名读取，只返回 `publication_state=published` 的版本。本机 `dev/test` 可由服务端固定启用 `local_mvp` 目录展示明确标识的 `pending_review` 岗位；客户端参数不能提升目录范围。
- 简历、画像、匹配、反馈和删除必须处于邀请会话。
- 本机 localhost 首次访问可自动创建匿名 owner；离开本机环境后仍必须使用一次性邀请交换。工程 MVP 不建立密码账号、第三方登录或公共注册。

### 5.2 邀请交换

1. 维护者生成高熵一次性邀请令牌，数据库只保存哈希、用途、过期时间和使用状态；邀请链接把令牌放在 URL fragment，不放在查询参数或路径。
2. 同源引导页先以响应头设置 `Referrer-Policy: no-referrer`，不加载第三方资源；浏览器脚本读取 fragment 后，通过专用交换端点的 POST body 提交令牌。端点禁止记录令牌、请求正文和原始 URL。
3. 成功后令牌立即失效，创建服务端会话并设置 `Secure`、`HttpOnly`、`SameSite=Strict` Cookie。
4. 页面通过替换历史记录或跳转到干净地址立即清除 fragment 中的令牌；失败页也不得保留或回显令牌。
5. 匿名 owner 在账号认领前继续使用最长 30 天的兼容期限；已验证 account 的职业资产不随 session 过期删除。session 始终短期过期且可撤销。删除全部数据时，原会话立即失去所有个人数据权限并降为最长 24 小时的“仅删除状态”能力，只能查询或幂等重试本次删除；成功终态首次返回给客户端后或能力到期时彻底撤销，失败态在期限内仍可重试。

每个会话映射稳定内部 `owner_id`。API 从认证上下文确定 owner，任何客户端提交的 `owner_id/user_id` 都被忽略或拒绝。所有读取、更新、匹配和删除查询必须同时限定对象 ID 与 owner。

邀请交换只接受同源 JSON POST，并校验 `Origin`/Fetch Metadata，不开放 CORS；会话建立后的写操作使用 CSRF 令牌。邀请交换、简历提交、匹配任务和反馈均有速率、并发及体积限制。错误响应不能区分“对象不存在”和“属于其他 owner”。

### 5.3 运营权限

首版来源审批和复核只通过 `internal ops CLI` 进行。CLI 使用独立维护者身份和受限数据库/API 角色，每项变更记录操作者、原因、时间和前后值。不得临时开放公共 `/admin` 接口或共享生产数据库密码。

## 6. 简历文件与文本处理

本地完整 MVP 接受 PDF、DOCX 或用户主动粘贴的文本：

```text
会话与 CSRF 校验
  -> 扩展名、MIME、魔数、内部结构和大小校验
  -> AES-GCM 加密写入 PostgreSQL
  -> match-worker 无网络、有限资源的隔离子进程解析
  -> 服务器和浏览器分别检测非必要 PII
  -> 用户确认结构化事实和证据
  -> 经历证据确认成功后立即删除原文；未完成确认或处理异常时最迟 24 小时自动过期
```

原文件和原文不进入访问日志、分析事件、错误报告或测试夹具。内容视为数据，不作为模板、Markdown HTML、SQL、Shell 或系统指令执行；解析器不调用 Office、不执行宏、外部关系、脚本或嵌入对象。

画像解析任务载荷只保存 `owner_id`、加密原文记录 ID 和输入哈希，不复制简历正文或原文片段。`match-worker` 按任务 owner 读取唯一暂存记录；确认删除、到期或主动删除后，旧任务只能得到稳定“输入已删除”状态，不能从重试载荷恢复正文。

原文记录保存 `raw_resume_expires_at = min(submitted_at + 24h, owner_expires_at)`。解析任务固定该时间，写候选时在同一事务校验原文仍存在、未到期且 owner epoch 未改变；证据确认、主动删除或 TTL 清理会取消相关旧任务。Worker 不把原文写入本地磁盘，达到任务超时或失效后立即丢弃内存缓冲并拒绝迟到写入。

经历证据确认请求标记 `confirmation_complete=true` 时，证据新修订与原文删除/墓碑必须在同一 PostgreSQL 事务提交；成功响应后任何进程都不能再读取原文。事务失败则确认不生效，原文继续受提交后 24 小时和 `owner_expires_at` 中更早期限约束。

PDF 同时校验 `%PDF` 魔数并拒绝加密文件；没有足够可提取文本时返回扫描件回退。DOCX 必须包含合法 OOXML 关键部件，限制条目数量、解压总量、压缩比和路径，拒绝宏与外部关系。图片、旧版 `.doc`、压缩包和其他格式不属于 MVP。

## 7. AI 安全与供应商门

本地 AI 能力只有在环境配置允许且用户对当前任务显式选择后调用，规则和固定模板构成完整降级路径。公开或远程环境启用外部模型前必须有已接受的供应商评审，确认：

- 输入是否用于训练、保留多久、由哪些分包方处理。
- 存储和处理地区、跨境路径及删除能力。
- 服务账号权限、允许域名、预算、故障和退出方案。
- 用户可见告知、关闭 AI 后仍可用的基础能力。

AI 开启后：

- `match-worker` 只能向批准模型域名出站，模型密钥不进入其他进程。
- 发送前删除联系方式等无关字段，解释阶段只发送确认后的最小结构对象。
- 外部岗位和简历文本被明确标记为数据；模型没有工具、文件、数据库或网络控制权。
- 固定 JSON Schema、枚举和 ID 引用通过后才能展示。
- 资格、证据、偏好三轴由本地确定性代码产生，模型输出不能覆盖。
- 不记录原始提示词/响应正文；只记录模型别名、版本、令牌、耗时、成本和稳定错误码。

## 8. 数据保护、保留和删除

- 生产连接强制 TLS；PostgreSQL、岗位快照 Bucket 和备份启用静态加密，简历原文使用应用层加密字段或等效密钥隔离。
- 岗位快照 Bucket 只保存公开岗位响应正文，绝不保存简历、画像、匹配结果、邀请令牌或其他用户数据；Bucket 访问日志同样不得包含对象正文。
- 原始简历文本在用户完成经历证据确认后立即删除；仅未完成确认或处理异常时允许暂存，且最长不超过提交后 24 小时。
- 已验证 account 的 `ProfileFact`、`JobPreference`、`ResumeEvidence`、Case、Resume、Interview 和 Debrief 等职业资产默认长期保留并由用户主动删除；匿名 owner 保留历史 30 天兼容期限。导出和临时正文最长 24 小时，只有无正文审计或不可逆汇总可以按独立期限保留。
- `match-worker` 的定时入口只能通过受限到期函数选择 `owner_expires_at <= now()` 的 owner；函数在同一事务写到期墓碑、递增 epoch、取消旧任务并入队清理，不向 Worker 返回其他 owner 内容。
- MVP 禁止在进程内或共享层跨请求缓存 owner 数据；每次读取都重新校验会话、owner、墓碑和到期时间。公开岗位缓存不得混入个性化结果。
- 不含正文的管理员、授权、删除和安全审计记录保留 90 天。
- 删除请求在同一事务写墓碑、递增 `owner_epoch`、取消待处理用户任务并撤销事实、证据、匹配和决定的全部读取能力，再创建可观察的清理任务。原会话只保留短期删除状态查询/重试权限，不能读取其他 owner 对象。`match-worker` 只能用任务关联的 owner、墓碑和 fencing token 调用幂等清理函数，清理实时表、任务载荷、持久派生数据和临时副本；成功终态首次返回后撤销剩余能力，失败态不恢复数据访问。
- 删除墓碑在返回 `202 Accepted` 前必须进入可随恢复链重放的持久 WAL/等效日志；Alpha 的 24 小时业务 RPO 不允许已接受删除请求复活。备份中的到期数据通过备份生命周期删除；若从旧备份恢复，必须先重放删除墓碑再开放服务。墓碑恢复链不完整时，恢复出的用户数据保持隔离，直至完成删除确认或达到原 `expires_at`。

审计记录不得保存简历正文、岗位全文、模型提示词、原始邀请令牌或可逆联系方式。访问审计记录本身也使用受限角色。

## 9. 密钥、日志与响应安全

- 密钥通过受控环境或密钥服务注入，不进入仓库、前端包、镜像层和普通日志。
- 日志只记录请求/任务 ID、owner 的不可逆内部引用、版本、状态、耗时和错误码。
- URL 记录前移除查询与片段；错误堆栈不得包含输入正文。
- 前台统一输出转义，设置 CSP、`X-Content-Type-Options`、`Referrer-Policy` 和合理的 frame 限制。
- 模型、采集和 API 错误使用稳定公开错误码，不把上游原始响应返回用户。
- 建立密钥轮换、会话撤销和泄露响应步骤。

## 10. 第三方依赖准入

招聘聚合、简历匹配等未知垂直项目不作为运行底座。正式通用依赖必须记录：

| 检查项 | 要求 |
|---|---|
| 身份 | 官方仓库、官方包名和可验证维护者 |
| 必要性 | 标准库或现有依赖不能合理完成同一任务 |
| 维护与安全 | 发布/响应记录、安全政策、OSV/OpenSSF 等信号 |
| 许可证 | 与使用和分发方式兼容；数据许可证单独判断 |
| 安装行为 | 审核构建脚本、二进制和安装钩子 |
| 依赖树 | 检查传递依赖与高风险包 |
| 固定版本 | 锁文件、完整性哈希和可重复构建 |
| 可替换性 | 通过内部接口隔离，不让核心域绑定单一库 |

CI 至少执行依赖漏洞、Secret 和许可证检查；第三方 Action 固定提交 SHA 并使用最小令牌权限。Star 数量只能作为维护信号，不能替代审查。

## 11. MVP 安全验证门

进入邀请制私测前必须通过：

- SSRF、共享 ATS 越界、重定向、DNS rebinding、IPv4/IPv6 保留地址测试。
- 采集进程无法读取用户表或模型密钥，匹配进程无法访问采集目标；只有 `collector-worker` 能访问岗位快照 Bucket 专用前缀，`web-api` 和 `match-worker` 的读取尝试均被拒绝。
- 邀请令牌重放、会话固定、CSRF、对象级读取/修改/删除越权测试。
- 超大响应、超长简历文本、任务重试和成本限额测试。
- 岗位与模型输出不能在前台执行脚本或改变三轴判断。
- PDF/DOCX 的伪造 MIME、超限、宏、加密、路径逃逸、ZIP bomb、超时和崩溃均安全失败且不影响 Worker 主进程。
- AI 关闭时岗位、三轴和推荐可用；公开环境未通过供应商门时没有出站调用。
- 简历原文件/原文不进入日志、岗位 Bucket 或模型请求，经历证据确认后立即删除且未完成或异常处理最长 24 小时的链路通过。
- 匿名 owner 30 天兼容、已验证 account 长期资产主动删除、审计 90 天过期和备份删除墓碑流程均可验证。
- 依赖无未接受的 Critical/High 漏洞，密钥不在仓库、镜像、前端或日志中。

任何一项未通过，都不能通过扩大测试范围来绕过。
