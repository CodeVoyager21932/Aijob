# 安全威胁模型与依赖准入

## 1. 安全目标

平台同时处理外部网页、用户简历和 AI 模型，三者都属于高风险输入。安全设计的首要目标是：即使某个网页、文件或模型输出恶意，影响也不能跨越其所在边界。

需要保护的资产包括：

- 用户简历、联系方式和求职偏好。
- 数据库、对象存储和备份。
- 模型 API 密钥和其他服务凭据。
- 企业来源注册表和岗位可信状态。
- 管理员账号和人工审核结果。
- 服务器、开发电脑和 CI/CD 环境。

## 2. 信任边界

```text
互联网公开页面（不可信）
  -> 采集隔离区（只出不进、无用户数据）
  -> 原始内容隔离存储
  -> 清洗与结构化区
  -> 岗位数据库

用户简历（敏感且不可信文件）
  -> 文件隔离与安全解析
  -> 用户确认的结构化证据
  -> 匹配服务

岗位结构化数据 + 用户证据
  -> 无工具权限的 AI 网关
  -> Schema 校验
  -> 推荐结果
```

采集进程不能读取用户简历或模型密钥。简历解析进程不能访问任意互联网地址。AI 网关不能调用采集器、执行命令或读取服务器文件。

## 3. 主要威胁与控制

| 威胁 | 可能后果 | 必须控制 |
|---|---|---|
| SSRF | 访问本机、内网、云元数据或其他敏感服务 | 来源域名白名单、限定 HTTPS、DNS/IP 校验、逐跳校验重定向、阻断私网和保留地址 |
| DNS rebinding | 审核时是公网，抓取时解析到内网 | 请求前重新解析并校验全部地址；网络层默认阻断内网出口 |
| 恶意或超大响应 | 内存、磁盘、CPU 耗尽 | 响应大小上限、超时、流式读取、并发限制、内容类型白名单 |
| 存储型 XSS | 恶意 HTML 在用户浏览器执行 | 不展示原始 HTML；转为纯文本；输出统一转义；严格 CSP |
| 间接提示注入 | 岗位内容改变模型指令或诱导泄密 | 外部内容明确分隔；模型无工具和密钥；固定输出 Schema；输入输出过滤；对抗测试 |
| 恶意 PDF/DOCX | 解析器漏洞、宏、脚本、解压炸弹 | 文件签名检查、大小/页数/解压上限、隔离进程、资源限制、恶意软件扫描、永不执行宏或附件 |
| 文件路径穿越 | 覆盖系统文件或读取其他用户文件 | 服务端生成文件名、对象存储隔离、禁止使用用户原始路径 |
| 简历隐私泄露 | 个人信息进入日志、模型或其他用户空间 | 最小化传输、租户隔离、加密、日志脱敏、删除链路、访问审计 |
| 供应链攻击 | 恶意依赖、安装脚本或被劫持版本执行 | 依赖准入、锁版本和哈希、漏洞扫描、SBOM、最小依赖、禁止未知安装脚本 |
| 密钥泄露 | 模型和基础设施被滥用 | 密钥管理服务或环境注入、最小权限、轮换、禁止进入前端和仓库 |
| 抓取规则失效 | 错误岗位、空数据或大量误关闭 | 解析夹具、字段约束、数量异常告警、失败隔离、人工抽检 |
| 越权访问 | 用户查看或删除其他人的简历 | 服务端对象级鉴权、租户字段、权限测试、审计日志 |
| AI 越权判断 | 模型覆盖硬条件或编造经历 | 确定性规则优先、引用 ID、Schema 校验、禁止模型修改资格状态 |

## 4. URL 与网络访问规则

- MVP 只抓取管理员审核并登记的来源，不直接抓取用户提交的 URL。
- 允许协议仅为 `https`；确有必要的官方 `http` 来源单独评估。
- URL 不允许用户名、密码、非标准端口和非 HTTP 协议。
- 域名和每次跳转后的域名都必须在 `allowed_hosts` 中。
- DNS 解析结果包含私网、环回、链路本地、组播或云元数据地址时拒绝请求。
- 采集容器在网络层无法访问数据库管理端口、简历存储和宿主机服务。
- 不把目标服务器的原始错误响应直接返回给普通用户。

## 5. 简历文件处理

安全流程：

```text
上传
  -> 扩展名、文件签名、大小检查
  -> 随机对象名和隔离存储
  -> 恶意软件扫描
  -> 低权限进程限时解析
  -> 纯文本和结构化字段
  -> 删除临时文件
```

默认限制应包括文件大小、页数、解析时间、内存和 DOCX 解压后总大小。文件不进入 Web 静态目录，不提供原文件公开 URL，不执行嵌入脚本、宏、链接或附件。

第一版可以优先开放“粘贴简历文本”，待文件隔离链路通过安全测试后再开放 PDF/DOCX，以降低首轮风险。

## 6. AI 安全边界

- 岗位描述和简历文本都被标记为数据，不属于指令。
- 模型只接收结构化字段和必要原文片段。
- 模型调用账户不持有数据库、文件系统和采集权限。
- 使用固定 JSON Schema 验证输出；验证失败进入重试或降级，不直接展示。
- 不允许模型生成或执行 URL、SQL、Shell、模板和前端 HTML。
- 对岗位描述中的“忽略之前指令”“输出密钥”等文本建立固定对抗样本。
- 模型供应商不可用时，产品降级到搜索、硬筛和基础证据对应。

## 7. 第三方项目与依赖分级

### 7.1 竞品

只研究产品机制，不获取运行权限。

### 7.2 参考仓库

- 默认只通过网页阅读架构和代码片段。
- 不运行仓库中的安装、构建、Docker、GitHub Actions 或脚本。
- 不把整段代码复制进项目。
- 如需验证某种算法，使用我们自己编写的最小测试实现。

### 7.3 正式依赖

正式依赖必须填写准入记录：

| 检查项 | 要求 |
|---|---|
| 身份 | 官方仓库、官方包名、可验证的维护者 |
| 必要性 | 标准库或现有依赖不能合理完成同一任务 |
| 维护 | 有持续发布、问题响应和兼容性说明 |
| 安全 | 查看安全策略、已知漏洞、OpenSSF/OSV 信号 |
| 许可证 | 与项目使用方式兼容，数据许可证单独判断 |
| 安装行为 | 审核构建脚本、二进制文件和安装钩子 |
| 依赖树 | 检查传递依赖数量和高风险包 |
| 固定版本 | 锁文件和完整性哈希 |
| 可替换性 | 通过内部接口隔离，避免业务逻辑绑定单一库 |

项目规模和 Star 只能作为信号，不能代替审查。小项目默认不进入运行环境；大型项目也不能因为流行而跳过漏洞和许可证检查。

## 8. 候选通用基础设施

以下只是进入后续安全评估的候选，不代表已经批准安装：

- API 与数据校验：FastAPI、Pydantic。
- 数据访问：SQLAlchemy、Alembic、PostgreSQL。
- HTTP 客户端：HTTPX。
- 必要时的动态页面渲染：Microsoft Playwright。
- 测试：pytest、Playwright E2E。

招聘聚合、简历匹配等垂直小项目不进入候选依赖清单。

## 9. 供应链要求

- Python 和 Node 分别使用锁文件固定完整依赖树。
- CI 执行 `pip-audit`、OSV Scanner 或等价扫描。
- 生成 CycloneDX 或 SPDX SBOM。
- 开启 Dependabot 或 Renovate，但升级必须通过测试和人工审核。
- CI 工作流使用最小令牌权限，第三方 Action 固定到提交 SHA。
- 发布镜像执行漏洞扫描，不以 `latest` 标签作为唯一版本。
- 不在开发电脑以管理员权限运行采集器或不可信构建脚本。

## 10. 上线前安全门

- SSRF、重定向和 DNS rebinding 测试通过。
- 恶意/超大简历文件测试通过。
- 抓取 HTML 无法在前台执行脚本。
- 提示注入样本不能影响硬条件或泄露信息。
- 用户数据对象级鉴权测试通过。
- 依赖无未接受的 Critical/High 漏洞。
- 密钥不在仓库、前端包、日志和错误报告中。
- 用户删除操作能够覆盖原文、解析结果、向量和缓存。

任何一项未通过，都不能用“先上线再说”绕过。
