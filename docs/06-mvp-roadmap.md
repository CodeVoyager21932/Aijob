## 生效口径

- 供给单位为在校生可投岗位，覆盖实习、校招、应届和管培；依据显式条件排除不可投，unknown 保留，不推断补写。
- ADR-0035 已将 100 家/1000 岗、运营缓冲与人工占比改为报告项；城市、职能为观察指标，不能把规模愿望写成准入否决。报告项也不能被省略。
- 逐来源主体、访问政策、投递交接、活跃可核验、字段稳定等质量要求继续守门。robots 与 ToS 按 ADR-0033 核验；robots 允许不代表来源 approved。
- 本机 local_mvp 可以保留待审核事实；外部查询由逐岗位资格与双向 public_version_id 对账守门。缺少准入来源时公共目录为空是正确结果。
- 原句、硬性要求、优先条件分开；Case 固定岗位版本与要求集，只有用户明确确认才升级；投递列表不得冒充岗位直达页。

## 路线与下一目标

已完成工程基线 → OS-7 关闭 → SA Phase A / 首次取证 → 岗位事实纠偏与独立工作区验收 → 业务恢复完成 → **产品主体研究完成，下一开发入口为理解规则与方向比较的最小完整旅程**。

上一轮“主体已具闭环，先补账号部署”的优先级已被coco纠正。本轮研究建议先修复本硕博、否定/优先语义、多轴分类和小样本洞察，再让“看方向→看原句→关联材料→开始申请”成立；后续将供给变成异常驱动的自动化，并补齐材料复用与时间管理。详见[实施顺序](reviews/product-core-research-2026-09-05/implementation-plan.md)。这些是具体设计建议，尚未实现；浏览器渲染、robots策略和语义AI等边界调整也未因此生效。来源准入、可靠性和安全验收保留，按实际发布能力落实，不取代主体改进。40/70/100继续是供给报告检查点。

coco于2026-09-05明确取消单家公司岗位上限，按[ADR-0036](decisions/0036-remove-company-job-cap.md)执行：不再统一到30，而是取消30/10及30条截断。取消上限已通过949/949全仓测试、lint、类型检查与构建；其后的业务恢复也已完成。图谱按企业/岗位分别统计不意味着重新限制公司岗位数。

本轮没有启动任何真实来源；既有来源刷新权限仍遵守 AGENTS 与 ADR-0026。首次启用、扩大请求范围、恢复暂停来源和浏览器快照需要人工明确操作。不得因本轮工程验收而自动打开定时采集、真实 AI、邮件、服务器或用户实验。
