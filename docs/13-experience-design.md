# P0 体验设计规范：官方岗位投递决策助手

> 状态：Draft / 待用户验证
> 适用范围：本地完整 MVP 与后续 Private Alpha
> 当前用户假设：未来 30 天正在真实投递实习岗位、已有中文简历、近期使用过多个官方渠道的中国大陆在校生；全部职能范围仍为 E0
> 体验目标：帮助用户完成可核对的高质量投递决策，而不是增加浏览时长或制造一个“匹配分”

## 1. 体验原则

1. **先给岗位，再索取数据**：第一屏直接进入岗位列表，匿名用户无需提交简历即可浏览。
2. **渐进获取信息**：先询问完成筛选所需的少量约束；只有用户主动选择个性化匹配时才请求 PDF、DOCX 或简历文本。
3. **把判断拆开**：资格、经历证据和个人偏好分别呈现，不用总分掩盖冲突、未知或偏好差异。
4. **每个结论都可核对、可纠正**：证据确认阶段可展开岗位原文和简历原文片段；原文删除后，结果页展示用户确认的证据陈述和判断依据，并允许修改事实、偏好和证据。
5. **不替用户做决定**：存在冲突的岗位仍可查看；系统不自动隐藏或禁止投递，只允许用户主动隐藏。
6. **官方页面是自然终点**：平台帮助用户做决策和保留状态，不模拟登录、不自动填写、不追踪用户离站后的浏览。
7. **隐私默认最小化**：粘贴文本先在浏览器本地检查；文件只在隔离解析后返回文本供用户检查。简历原文件/原文在经历证据确认后立即删除，未完成或异常情况下最长保留 24 小时。
8. **AI 可被拿掉**：模板和规则必须独立完成岗位、三轴和推荐；AI 简历优化由用户逐次显式选择，失败时降级且不影响主流程。

## 2. P0 完整循环

```text
岗位列表
  -> 轻量约束
  -> 岗位详情与来源证据
  -> 简历隐私检查
  -> 事实 / 偏好 / 经历证据确认
  -> 资格 / 证据 / 偏好结果
  -> 可解释岗位推荐
  -> 简历对照修改与 DOCX
  -> 保存、准备投递、投递或放弃
  -> 官方页面交接
  -> 返回后记录状态
  -> 复访与数据控制
```

用户可以只完成“浏览岗位 -> 查看详情 -> 前往官方页面”的短路径；简历匹配不是查看岗位或官方链接的前置条件。任何中断后，只要匿名会话仍有效，用户应回到上次岗位、筛选和决策队列，而不是重新开始。

## 3. 入口与信息架构

### 3.1 第一屏：岗位列表

邀请链接首次打开后直接展示岗位列表，不建设营销首页。页面顶部保留两个清晰但不互相阻塞的入口：

- **先浏览岗位**：默认路径；立即查看本地目录中的全部职能实习岗位。
- **用简历匹配**：进入轻量约束，说明只有在需要经历证据匹配时才会请求 PDF、DOCX 或去标识化文本。

列表首屏至少展示岗位名称、企业、城市、实习时间要求、来源类型、最后核验时间和岗位当前状态。无法可靠提取的字段显示“未说明”，不能用空白、默认值或推断值替代。

筛选不要求登录，也不以弹窗强迫用户完善资料。城市和岗位方向作为首要筛选；公司、批次、出勤、时长、到岗、毕业年份、学历/专业、薪资、工作方式、来源和新鲜度按数据可用性渐进展开。只有一个真实值的维度显示为当前范围，零个已知值的维度显示覆盖率，不制造无效选项。“清除筛选”必须始终可见，零结果时保留已选条件并告诉用户是哪组条件造成收窄。

### 3.2 P0 页面与层级

| 页面/区域 | P0 任务 | 主要动作 |
|---|---|---|
| 岗位列表 | 浏览、筛选、恢复上次进度 | 查看详情、保存、开始匹配 |
| 岗位详情 | 核对要求、来源、时效和资格信息 | 前往官方页、匹配此岗位、记录决定 |
| 约束确认 | 填写事实和偏好 | 保存并查看结果、稍后填写 |
| 简历输入与隐私检查 | 上传 PDF/DOCX 或粘贴文本，处理明显个人信息 | 选择文件、粘贴、遮盖、确认、取消 |
| 经历证据确认 | 核对解析结果与原文片段 | 确认、修改、删除、补充 |
| 决策结果 | 分轴理解资格、证据和偏好 | 查看依据、修正信息、更新状态 |
| 岗位推荐 | 按确定性顺序比较依据与未知项 | 查看岗位、修正条件、开始优化 |
| 简历对照修改 | 核对原文、建议、原因与证据引用 | 接受、拒绝、编辑、复制、导出 DOCX |
| 决策队列 | 管理尚未决定和已行动岗位 | 继续判断、前往官方页、修改状态 |
| 数据控制 | 查看保留期限和删除状态 | 删除个人资料与匹配数据 |

导航命名使用任务语言，例如“找岗位”“我的决定”“我的数据”，不使用“AI 中心”“画像中心”等实现术语。

## 4. 渐进约束与简历输入

### 4.1 先确认最小约束

首屏筛选只询问城市、岗位方向、每周出勤和持续月数。用户进一步请求资格判断时，再补问最早到岗时间和毕业年份；两项都允许跳过并保持未知，不要求一次填完所有资料：

| 信息 | 类型 | 询问时机 | 默认处理 |
|---|---|---|---|
| 目标城市 | 偏好 | 首屏筛选 | 未设置，不视为不符合 |
| 产品 / 运营方向 | 偏好 | 首屏筛选 | 可多选，未设置时不用于过滤 |
| 每周可出勤天数 | 用户事实 | 首屏筛选 | 未知，不推断 |
| 可持续实习月数 | 用户事实 | 首屏筛选 | 未知，不推断 |
| 最早到岗时间 | 用户事实 | 查看资格结果前 | 未知，不推断 |
| 毕业年份 | 用户事实 | 查看资格结果前 | 未知，不推断 |

用户事实、岗位偏好和简历经历证据必须分组展示、分开保存。未填写或未确认的信息一律保持未知，不能为了得到完整结论而补猜。

### 4.2 请求简历的时机

只有用户选择“用简历匹配”“匹配此岗位”或希望查看经历证据时，才展示简历输入。入口提供 PDF、DOCX 和粘贴文本；输入页必须在提交按钮附近说明：

- 当前步骤不把原文件发送给第三方模型；后续简历优化是否调用模型会再次单独询问。
- 原文在经历证据确认后立即删除，未完成或异常情况下最长不超过提交后 24 小时。
- 结构化事实、偏好和经历证据默认保留 30 天，用户可以提前删除。
- 平台不把简历用于训练自己的模型，也不写入普通日志、分析事件或错误报告正文；选择外部 AI 时在同意页单独展示该端点的数据使用与保留说明。

文件最大 5 MiB，只接受 PDF 和 DOCX。旧版 `.doc`、图片、压缩包、宏和加密文档显示明确原因；PDF 没有可提取文本时提示“可能是扫描件”，提供粘贴文本回退，不诱导用户反复上传。

### 4.3 浏览器本地个人信息检查

粘贴文本在提交前由浏览器检测手机号、邮箱和居民身份证号码等明显个人信息。PDF/DOCX 先在服务端隔离解析并做服务器检测，再把解析文本和命中类别返回当前 owner 页面；浏览器再次检测并允许用户处理。在用户确认前，任何路径都不得把简历原文发送给 AI。

交互要求：

- 按类别显示命中数量并在原文中高亮，不在提示或埋点中记录命中内容。
- 提供“遮盖全部明显个人信息”和逐项“遮盖 / 这不是个人信息”操作；遮盖后的文本可预览和继续编辑。
- 检测未命中时仍提示自动检测可能遗漏，要求用户主动确认“我已检查并愿意提交当前文本”。
- 检测命中但未处理时，主按钮保持不可提交；用户可返回编辑或取消匹配。
- 正则或本地检测组件失败时，不上传原文；降级为人工检查说明，并要求用户重新确认。
- 不把“已脱敏”描述为绝对保证，统一使用“未发现明显个人信息”或“你已确认当前文本”。

## 5. 事实、偏好与经历证据确认

解析结果不能直接参与确定性判断。确认界面按以下顺序处理：

1. 用户事实：毕业年份、最早到岗时间、每周出勤、持续月数。
2. 岗位偏好：城市、方向及明确排除项。
3. 经历证据：经历陈述、类型、时间、技能/产出以及对应的简历原文片段。

每一项必须支持确认、修改、删除；不确定项支持“暂不确认”。修改经历证据时保留原文片段供核对，但不能把系统推断自动写回原文。用户未确认的字段不得参与“未发现明确冲突”或“有明确证据”的结论。

部分解析成功时，只展示已解析内容并明确标记失败部分，不要求用户重新粘贴整份简历。原文仍在保留窗口内时允许回到片段核对；原文已因确认、主动删除或 TTL 清理时，只展示候选陈述、位置/哈希不可回放提示，用户可以手动确认、修改或删除。系统必须把“用户补充”与“解析所得”区分记录。

## 6. 三轴结果与统一术语

岗位详情和决策结果必须分别显示三个轴，禁止展示“匹配度 87%”之类的总百分比，也不使用含混的“推荐 / 不建议”替代事实。

| 轴 | 允许的前台术语 | 含义与展示要求 |
|---|---|---|
| 资格 | `未发现明确冲突` | 只表示当前已确认信息中没有硬条件冲突，不等于企业认可或必然录用 |
| 资格 | `存在明确冲突` | 引用岗位原文、用户事实和具体冲突；允许用户修正并重新判断 |
| 资格 | `需补充信息` | 指明缺少的是岗位信息、用户信息或两者 |
| 证据 | `有明确证据` | 至少一条用户确认的经历直接支持对应要求，可展开确认后的证据陈述；不恢复已删除的简历原文 |
| 证据 | `部分证据` | 只支持要求的一部分，或证据强度有限；说明未覆盖部分 |
| 证据 | `简历暂未体现` | 当前已确认经历中未找到支持，不等于用户不具备能力 |
| 证据 | `信息不足` | 要求或经历信息不足，不能判断是否有证据 |
| 偏好 | `符合` | 岗位满足用户已设置的相关偏好 |
| 偏好 | `不符合` | 展示与哪项偏好不一致；偏好冲突不是资格冲突 |
| 偏好 | `未设置` | 用户尚未表达该项偏好，不作正负判断 |

结果摘要先展示资格，再展示证据，最后展示偏好。颜色只能作辅助，状态必须同时有文本和图标；“存在明确冲突”不得使用阻断式红色整页或禁用官方链接。

用户修改事实、偏好或证据后，旧结果显示“依据已变化”，必须重新运行后才显示新结论；不得把新旧依据混合展示。

### 6.1 可解释岗位推荐

推荐页不显示总分，而是按稳定顺序逐条回答“为什么排在这里”：

- 先展示资格状态，再展示偏好满足、证据覆盖、新鲜度和来源。
- 明确分开“存在冲突”“岗位未说明”“简历暂未体现”和“偏好不符”。
- 每条都可展开岗位原句、用户事实和经历证据，支持立即修正并创建新运行。
- 冲突岗位仍可进入详情、保存或前往官方页，不使用禁用按钮或整卡警告色自动劝退。
- 排序依据变化时旧列表显示“依据已变化”，用户主动刷新后生成新推荐，不能静默跳动。

### 6.2 简历对照修改

用户从一个岗位进入“针对这个岗位优化简历”后，先看到将发送给外部模型的数据范围和“使用 AI / 使用模板”选择。选择 AI 是当前任务的一次性同意，不形成以后默认授权。

每个建议段固定展示：

1. 原文。
2. 建议稿。
3. 为什么修改。
4. 对应岗位要求。
5. 所依据的用户确认经历。

操作只使用“接受”“拒绝”“编辑后使用”。没有证据引用、出现新事实或校验失败的段落不展示；模型不可用时明确切换为模板建议，不伪装成 AI 结果。页面持续显示已接受/待处理数量，允许随时返回岗位且保留草稿。

完成后提供“复制完整文本”和“导出可编辑 DOCX”。导出前预览统一单栏结构并说明不会保留原文件复杂版式；DOCX 只包含用户最终接受或编辑的内容。

## 7. 来源证据与岗位状态

来源信息分项展示，不使用暗示“绝对真实”“平台担保”的统一绿色认证徽章：

- 发布路径：企业官网 / 官方 ATS / 高校就业网。
- 发布主体或转载主体，以及平台能够核验的关系说明。
- 原始页面域名和可访问的原始链接。
- 最后核验时间，使用绝对日期时间；相对时间只作辅助。
- 当前状态：招聘中 / 待复查 / 已关闭 / 状态未知。

“待复查”和“状态未知”岗位仍可查看历史详情，但不得进入默认可投岗位列表；用户主动打开时明确说明原因和最后一次成功核验时间。“已关闭”保留在用户决策历史中，不再出现在可投岗位列表。

岗位字段与原文不一致、来源跳转变化或用户反馈失效时，应提供“报告问题”，并让用户选择最小原因：页面打不开、岗位已关闭、投递入口变化、信息与原文不一致、其他。

## 8. 决策队列与官方外链交接

### 8.1 决策状态

每个岗位只有一个当前决策状态：

| 状态 | 适用时机 | 允许的主要转移 |
|---|---|---|
| `未决定` | 看过但尚未形成决定，或结果刚生成 | 已保存、准备投递、已放弃 |
| `已保存` | 值得以后继续判断 | 未决定、准备投递、已放弃 |
| `准备投递` | 已决定投入时间准备或正在填写 | 已投递、已保存、已放弃 |
| `已投递` | 用户明确自报已在官方页面完成提交 | 准备投递、已放弃（需记录修正原因） |
| `已放弃` | 用户决定本轮不投 | 未决定、已保存 |

已保存、准备投递、已投递和已放弃都提供不阻断状态更新的快捷理由与可选说明。指标中“投递”映射为准备投递或已投递，“暂缓”映射为已保存，“放弃”映射为已放弃；未决定不计入，其他状态没有至少一个理由时也不计入高质量投递决定。

更新为“已放弃”时提供可跳过的最小理由：资格冲突、经历证据不足、偏好不符、岗位失效、时间不足、已经投过、其他。理由只用于帮助用户复访和验证产品，不被自动解释为普遍规律。

“隐藏岗位”是独立的用户操作，不是判断结果；系统不得因为资格冲突、证据不足或 AI 输出自动隐藏岗位。隐藏后必须能在“已隐藏”视图恢复。

### 8.2 前往官方页面

“前往官方投递页”前的交接区域展示目标主体、目标域名、最后核验时间和“将在外部页面完成投递”。不制造多余确认弹窗；仅当最终域名变化、状态待复查或浏览器无法确认安全跳转时显示风险提示。

- 常规浏览器优先在新标签页打开，保留平台中的岗位和决策状态。
- 微信内浏览器如果不能稳定打开或返回，提供“在浏览器打开”和“复制官方链接”，同时保留当前进度。
- 链接点击只记录“前往官方页”，不能自动记为“已投递”。
- 不读取或推断用户在企业网站内的提交行为，不要求用户提供企业账号。

用户返回平台或下一次打开决策队列时，对最近进入官方页且仍为“准备投递”的岗位询问：“这次进展如何？”操作为“已投递 / 仍在准备 / 暂时不投”，允许关闭且不反复打断。

## 9. 复访与数据控制

复访默认进入“我的决定”，按“准备投递、已保存、未决定、已投递、已放弃”分组，并显示岗位最新状态变化。筛选条件、用户事实、偏好和结构化证据在同一匿名会话内恢复；简历原文不恢复。

用户能够：

- 查看上次访问和决策更新时间。
- 继续处理未决定或准备投递的岗位。
- 修正自报状态和理由。
- 查看事实、偏好、经历证据的保留期限。
- 查看固定 `owner_expires_at`；新增或修改信息不会重置倒计时。
- 单独修改事实、偏好和证据，或发起删除全部个人资料。

删除全部个人资料后立即撤销数据访问并进入“删除处理中”；删除范围包括原文件/原文、事实、偏好、经历证据、匹配、推荐、简历优化、导出、决策队列中的个人状态和 owner 关联的产品事件。原会话只暂时保留本次删除状态查询与幂等重试能力，不能重新访问任何个人数据。删除成功后只显示完成结果和不含正文的审计编号并撤销剩余能力；失败时不得恢复用户访问，提供“重试删除”和受控问题反馈入口。

匿名会话过期后，岗位仍可浏览，但个人约束、证据、结果和决策状态不可访问。页面应解释数据已不可恢复，而不是显示通用“登录失败”。

## 10. 状态与恢复矩阵

| 状态 | 用户看到什么 | 主操作 | 恢复与约束 |
|---|---|---|---|
| 列表加载中 | 固定高度骨架屏，筛选区不位移 | 等待 / 返回 | 超时后进入可重试错误，不显示空列表 |
| 零结果 | 已生效条件、没有结果的明确说明 | 放宽一个条件 / 清除筛选 | 不自动移除用户条件，不把待复查岗位混入结果 |
| 岗位详情加载失败 | 岗位名称和已缓存来源摘要（如有） | 重试 / 打开原始页 | 不把失败标成岗位关闭 |
| 文件拒绝 | 具体格式/大小/加密/宏原因和允许格式 | 换 PDF/DOCX / 粘贴文本 | 不把文件送入解析器或模型 |
| 扫描 PDF | “可能是扫描件，暂时无法读取文字” | 粘贴文本 / 换文件 | MVP 不做 OCR，不反复自动重试 |
| 简历部分解析 | 已成功条目、失败段落和影响 | 确认已有内容 / 手动补充 | 不要求重新提交已删除原文；失败项不参与结论 |
| 岗位待复查 | 原因、最后成功核验时间和历史详情 | 查看原始页 / 报告状态 | 不进入默认可投岗位列表；不自动删除用户决策 |
| 官方链接变化 | 旧域名、新域名或无法确认的说明 | 查看已核验新链接 / 稍后处理 | 未通过白名单校验时不直接跳转 |
| AI 降级 | “本次改用固定模板”，不展示模型错误正文 | 继续使用模板 / 稍后重试 | 不影响岗位浏览、三轴、推荐和已有用户编辑 |
| 匿名会话过期 | 个人数据不可访问说明，公开岗位仍可浏览 | 返回岗位列表 | 不通过重新输入邀请链接恢复已过期个人数据 |
| 删除处理中 | 删除范围和请求时间 | 查看状态 | 个人数据立即不可访问，重复请求保持幂等 |
| 删除成功 | 完成时间和不含正文的审计编号 | 返回岗位列表 | 不提供撤销或从缓存恢复 |
| 删除失败 | 数据仍不可访问、失败范围不暴露敏感内容 | 重试删除 / 反馈问题 | 后台继续告警和重试，不能要求用户重新提交简历 |

所有异步状态都应保留稳定尺寸，避免按钮、列表和进度提示跳动。错误消息说明“发生了什么、哪些内容仍安全、下一步是什么”，不向用户展示堆栈、模型输出或内部任务 ID。

## 11. 响应式与渠道要求

### 11.1 移动端与微信内浏览器优先

- 在 320 CSS px 宽度下完成浏览、隐私检查、证据确认、查看三轴结果和更新决策状态，不产生水平滚动。
- 固定底部操作区不得遮挡岗位正文、浏览器底栏或输入法；键盘弹出后当前字段和错误提示仍可见。
- 长岗位描述默认按职责、要求、时间/地点和来源分段，支持在段落间定位，不用连续超长卡片承载全文。
- 微信内浏览器必须测试复制链接、外部浏览器打开、返回后状态恢复、页面分享导致邀请令牌泄露等场景；页面不引导用户把含邀请令牌的 URL 分享给他人。
- “先浏览”和“用简历匹配”在首屏都可见，但不使用覆盖内容的全屏引导层。

### 11.2 桌面端

- 岗位详情与三轴结果采用可读的双栏对照：一侧岗位要求与来源，一侧资格、证据和偏好；窄屏自动回到单列顺序。
- 证据确认阶段保持要求与对应简历原文片段的视觉关联；原文删除后的结果页改为关联用户确认的证据陈述，不能因排序或异步加载错位。
- 键盘用户可依次访问筛选、岗位列表、详情、证据和主要操作；不要求拖拽或悬停才能完成任务。

桌面和移动端使用相同术语、状态和数据，不建设功能不一致的“简化移动版”。

## 12. WCAG 2.2 AA 验收要求

核心旅程按 WCAG 2.2 AA 验收，至少满足：

- 使用语义化标题、地标、列表、表单标签和按钮；屏幕阅读器能读出岗位、状态、来源和三轴关系。
- 所有功能可仅用键盘完成；焦点顺序与视觉顺序一致，焦点样式清晰且不被固定区域遮挡。
- 正常文本对比度不低于 4.5:1，大号文本和非文本关键控件不低于 3:1；状态不能只依赖颜色。
- 目标控件至少满足 24 x 24 CSS px 的 AA 目标尺寸要求，主要移动端操作目标建议不低于 44 x 44 CSS px。
- 表单错误与具体字段关联，说明修复方式；提交失败后焦点移动到错误摘要并保留用户输入。
- 动态加载、解析完成、重新匹配和删除结果通过可访问状态区域通知，不抢夺正在输入时的焦点。
- 在 200% 缩放和等效 320 CSS px 重排下无内容丢失、重叠或双向滚动；文本不使用仅随视口宽度变化的缩放。
- 不使用仅悬停可见的信息或只能手势完成的操作；图标按钮有可访问名称和可见焦点。
- 链接文本说明去向；外部官方页面、复制链接和打开浏览器等动作可被辅助技术区分。
- 会话即将过期时提前提示，并允许在既有数据 `expires_at` 范围内延长本次会话；会话操作不得延长结构化数据固定最长 30 天的期限，已过期后按数据保留规则说明结果。

至少使用键盘、主流屏幕阅读器、200%/400% 缩放和真机触控各完成一次核心旅程验证。自动化扫描只能作为辅助，不能替代人工任务测试。

## 13. 体验埋点与研究边界

P0 只记录验证高质量投递决策所需的最小事件：岗位列表/详情查看、来源依据展开、事实/偏好/证据确认、三轴结果查看、决策状态变化、官方链接点击、用户自报投递和删除状态。

事件不得包含简历原文、岗位全文、个人信息命中内容或外部页面行为。核心指标的完整行为链为：

```text
7 日内完成约束 / 证据确认
  -> 查看至少 3 个岗位
  -> 对至少 1 个岗位查看来源与依据
  -> 选择投递 / 暂缓 / 放弃
  -> 记录理由
```

72 小时内自报完成官方投递是独立的下游强证据，不与链接点击合并。实验门槛与守护指标以 [验证与质量策略](12-validation-and-quality-strategy.md) 为准。

## 14. P0 体验验收清单

- 用户无需注册、提交简历或观看引导即可看到岗位列表。
- “先浏览”和“用简历匹配”两条路径均能独立到达官方岗位详情。
- 粘贴文本在提交前完成浏览器检查；PDF/DOCX 仅进入服务端隔离解析，解析文本在用户确认前不发送给 AI。明显个人信息都有可操作的处理流程。
- PDF、DOCX 和粘贴文本都有明确入口；文件失败可回退到文本，扫描 PDF 不假装解析成功。
- 任一结果只使用本规范中的资格、证据和偏好术语，不显示总匹配百分比或自动劝退。
- 推荐顺序能够解释且依据变化不会静默重排；每条推荐都保留未知项和官方来源。
- AI 修改稿逐段引用岗位要求和用户证据，用户可接受、拒绝、编辑、复制和导出 DOCX。
- 任一结论都能回到岗位要求、用户确认信息或“未知”，且用户可以纠正。
- 来源类型、原始域名、最后核验时间和岗位状态在详情中可见。
- 用户可以保存、准备投递、自报已投递、放弃、隐藏并恢复岗位。
- 官方页面打开失败、返回平台和再次访问时，用户进度不会被静默改写。
- AI 不可用、岗位待复查、会话过期和删除失败都有明确的降级与恢复路径。
- 移动端、微信内浏览器、桌面端和辅助技术均可完成 P0 完整循环。
