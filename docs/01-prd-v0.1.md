# PRD v0.1

## 1. 版本目标

用一小批官方来源和真实岗位，验证“可信岗位发现 -> 简历证据匹配 -> 官方投递”的最小闭环。

本版本不追求全平台覆盖，也不追求全自动。人工来源审核和人工抽检属于产品的一部分，不是失败。

## 2. 核心场景

### 场景 A：没有明确目标的学生

用户填写可实习城市、可到岗时间、每周出勤天数、毕业年份和感兴趣方向。系统先推荐符合资格的岗位，再解释可能适合的方向。

### 场景 B：已有简历的求职者

用户上传简历，系统提取教育、项目、实习、技能和成果证据。用户确认后，系统推荐岗位并展示证据对应关系。

### 场景 C：用户查看一个具体岗位

用户进入岗位详情页，看到官方来源、有效性、硬性要求、职责摘要、匹配证据、缺口和官方投递入口。

## 3. P0 功能需求

### 3.1 岗位发现

- 按关键词、城市、岗位方向、招聘类型、学历、毕业年份筛选。
- 默认优先展示近期验证且仍有效的岗位。
- 支持查看企业、岗位、地点、发布时间、截止时间和来源。
- 搜索结果不混入没有可追溯原始链接的记录。

### 3.2 岗位详情

- 展示结构化职责、要求、地点、招聘类型和截止时间。
- 展示来源类型、原始页面、首次发现时间和最后验证时间。
- 明确显示信息缺失、不确定、疑似过期或已关闭状态。
- 提供“前往企业官方页面”链接，不在平台内代替企业接收申请。

### 3.3 简历与用户约束

- 支持粘贴文本；文件上传在安全解析完成后支持 PDF/DOCX。
- 提取教育、时间、项目、实习、技能、成果和求职偏好。
- 用户必须能够修改和确认解析结果。
- 简历原文、结构化画像和用户偏好分开保存。
- 用户能够删除简历和相关解析结果。

### 3.4 推荐

- 先执行毕业年份、学历、地点、到岗时间等硬条件判断。
- 再比较岗位要求与用户经历证据。
- 输出“优先考虑”“有条件考虑”“不建议”“信息不足”四类结论。
- 每个结论展示支持证据、缺口、不确定项和投递建议。
- AI 不能把用户没有确认的推断写成事实。

### 3.5 反馈

- 用户可以标记“已查看官方页面”“已投递”“岗位失效”“推荐不准确”。
- 反馈用于数据质量和推荐评估，不自动公开用户行为。

### 3.6 管理端最小能力

- 登记和审核官方来源。
- 查看每个来源最近一次采集、成功数、失败数和异常原因。
- 抽检岗位字段和原始页面。
- 处理疑似重复、疑似失效和低置信度记录。

## 4. 页面范围

| 页面 | P0 内容 |
|---|---|
| 岗位列表 | 搜索、结构化筛选、来源和有效性提示 |
| 岗位详情 | 原始来源、岗位字段、匹配解释、官方投递入口 |
| 简历与画像 | 上传/粘贴、解析结果确认、求职约束 |
| 推荐结果 | 推荐等级、证据、缺口、不确定项 |
| 管理端 | 来源登记、采集状态、人工审核队列 |

P0 不做营销首页。打开产品后直接进入岗位列表或用户的推荐结果。

## 5. 关键状态与异常

| 状态 | 产品处理 |
|---|---|
| 岗位页面无法访问一次 | 标记待复查，不立即删除 |
| 连续复查失败或官方明确关闭 | 标记已关闭，停止推荐 |
| 截止时间缺失 | 显示未知，不能伪造日期 |
| 简历字段解析不确定 | 请求用户确认，不进入确定性评分 |
| AI 服务不可用 | 仍提供搜索、硬条件判断和基础证据匹配 |
| 岗位描述疑似包含指令 | 作为不可信文本隔离，不能影响系统指令 |
| 官方链接发生跳转 | 校验跳转后的域名和安全性后再更新 |

## 6. 数据与隐私要求

- 未登录用户可以浏览岗位，但上传简历前必须了解数据用途。
- 简历不得进入普通访问日志、分析埋点和错误报告正文。
- 默认不把用户简历用于训练模型。
- 模型供应商、保存期限和删除机制必须对用户可见。
- 抓取页面的原始 HTML 不直接返回给浏览器。

## 7. 核心事件

- `job_list_viewed`
- `job_detail_viewed`
- `official_apply_clicked`
- `resume_parse_confirmed`
- `recommendation_viewed`
- `recommendation_feedback_submitted`
- `job_reported_inactive`

事件只记录完成产品评估所需的最少字段，不记录简历正文。

## 8. P0 验收条件

- 每个可见岗位都有原始来源和最后验证时间。
- 推荐岗位不存在已知硬性条件冲突。
- 推荐理由能够引用岗位要求和用户确认过的经历证据。
- AI 不可用时，岗位发现和基础匹配仍然可用。
- 用户可以删除简历数据。
- 管理员能够看到来源失败并定位到具体采集阶段。
