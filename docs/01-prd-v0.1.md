# PRD v0.1：官方岗位投递决策助手 MVP-0

> 状态：Draft / 待用户实验验证
>
> 首轮用户：未来 30 天真实投递产品或运营实习、已有中文简历、近期使用过多个官方渠道的中国大陆在校生
>
> 本文只定义当前 MVP-0 的产品行为和验收条件，不承载礼宾实验方法或长期生命周期。实验协议见 [产品发现与实验](09-product-discovery.md)，当前是否进入开发以 [MVP 路线与决策面板](06-mvp-roadmap.md) 为准。

## 1. 版本目标

用 20-30 条人工导入并复核的产品/运营实习岗位，交付一条可以验证真实投递决策的最小链路：

~~~text
匿名邀请进入岗位列表
  -> 先浏览或填写轻量约束
  -> 查看岗位详情、来源与时效
  -> 按需粘贴去标识化中文简历
  -> 确认事实、偏好和经历证据
  -> 分开查看资格、证据和偏好
  -> 保存 / 准备投递 / 已投递 / 已放弃
  -> 前往官方页面并在返回后继续
~~~

MVP-0 验证的是用户能否更快、更清楚地形成高质量投递决定，不验证岗位规模、自动采集覆盖率或 AI 使用量。

## 2. 范围与前提

### 2.1 岗位样本

- 只包含 20-30 条产品/运营实习岗位。
- 岗位由运营人工导入、复核并保留原始页面证据。
- 来源只允许企业官网、由企业官方链接或确认的 ATS、高校就业网及企业公开招聘页面。
- 每条岗位重点核对：城市、到岗时间、每周出勤、持续月数、毕业年份和招聘批次。
- 没有可追溯原始链接、主体证明或最后核验时间的岗位不得发布。

### 2.2 运行前提

- Alpha 通过匿名邀请链接进入，不收集手机号或邮箱。
- PostgreSQL 和内部运营 CLI 等技术契约由架构文档定义；MVP-0 不要求公共管理后台。
- AI 默认关闭，规则和固定模板必须独立完成全部用户链路。
- 自动化 1 个来源是并行数据切片，不是 MVP-0 上线前置依赖。

### 2.3 P0 与非 P0

| P0 | 非 P0 |
|---|---|
| 人工岗位导入、列表、详情与来源证据 | 大规模自动采集和全文搜索 |
| 轻量约束与岗位筛选 | 职业探索、职业测评和简历生成 |
| 粘贴简历文本、隐私检查、证据确认 | PDF、DOCX、图片或压缩包上传 |
| 规则/模板资格与证据解释 | 黑盒匹配分数、自动简历改写 |
| 决策队列、官方外链和返回续接 | 自动填写、自动投递和企业招聘端 |
| 匿名会话和用户主动删除 | 手机号、邮箱账号与公共管理后台 |

## 3. P0 用户旅程

1. 用户通过匿名邀请进入岗位列表，第一屏直接看到岗位，不经过营销首页。
2. 用户选择“先浏览”或“用简历匹配”；系统先询问城市、岗位方向、出勤和时长。
3. 用户查看岗位详情中的来源类型、原始链接、最后核验时间和当前状态。
4. 只有用户主动选择个性化证据匹配时，系统才请求粘贴去标识化中文简历。
5. 浏览器本地检测手机号、邮箱和身份证号等明显个人信息；用户处理或明确确认后才提交。
6. 用户分别确认事实、求职偏好和经历证据，未确认项保持未知。
7. 系统分开显示资格、证据和偏好，不合成为百分比。
8. 用户将岗位标为未决定、已保存、准备投递、已投递或已放弃，并记录决定理由。
9. 用户前往官方页面；返回后仍能继续查看原岗位和更新状态。
10. 用户可以查看保留期限并删除自己的简历原文、结构化数据和相关派生数据。

详细交互、状态文案与响应式要求见 [体验设计规范](13-experience-design.md)。

## 4. P0 功能需求

### 4.1 匿名访问与会话

- **REQ-SESSION-001**：Alpha 用户通过一次性匿名邀请链接进入，不要求手机号、邮箱或第三方登录。
- **REQ-SESSION-002**：邀请凭证交换为安全会话后必须从地址栏移除；用户数据只能由所属会话访问。
- **REQ-SESSION-003**：邀请会话建立时固定最长 30 天的 `owner_expires_at`；普通访问和新增修订都不能续期。会话过期后仍可浏览公开岗位，但个人约束、证据、结果和决策状态不可访问或恢复，并按该期限自动删除。
- **REQ-SESSION-004**：匿名身份不得降低对象级鉴权、删除鉴权或审计要求。

### 4.2 人工岗位导入与来源

- **REQ-SOURCE-001**：只有来源注册表中人工审核为允许状态的官方或公开招聘来源可以导入。
- **REQ-SOURCE-002**：每条岗位必须记录发布主体、来源类型、原始 URL、首次发现时间、最后核验时间和导入/解析版本。
- **REQ-SOURCE-003**：来源展示必须区分企业官网、官方 ATS 和高校就业网；不能使用暗示绝对真实性的统一“可信”徽章。
- **REQ-SOURCE-004**：运营者能够通过内部 CLI 导入、复核、暂停和恢复岗位，并查看失败原因；MVP-0 不开发公共管理后台。
- **REQ-SOURCE-005**：疑似失效、来源变化、低置信度或信息冲突的岗位进入待复查，不自动伪装为有效。

### 4.3 岗位列表与详情

- **REQ-JOB-001**：匿名用户进入后的第一屏直接展示岗位列表，并同时提供“先浏览”和“用简历匹配”入口。
- **REQ-JOB-002**：P0 首轮筛选只使用城市、岗位方向、每周出勤和持续月数；毕业年份和招聘批次仍在详情与资格依据中展示，但不作为首屏筛选控件。所有缺失值必须显示未知。
- **REQ-JOB-003**：列表显示企业、岗位、城市、来源类型、最后核验时间和当前状态。
- **REQ-JOB-004**：详情显示原始职责与要求、结构化条件、信息不确定项、来源证据和官方申请入口。
- **REQ-JOB-005**：没有可追溯原始链接的记录不得发布。
- **REQ-JOB-006**：存在明确资格冲突的岗位仍可查看、纠正和访问来源页；系统不得自动隐藏，只有用户可以主动隐藏。

### 4.4 求职事实、偏好、简历文本与经历证据

- **REQ-RESUME-001**：本版本只支持粘贴去标识化中文简历文本，不支持 PDF、DOCX、图片或压缩包上传。
- **REQ-RESUME-002**：提交前明确说明用途、处理方式、AI 是否启用、保存期限和删除方式。
- **REQ-RESUME-003**：解析教育、时间、项目、实习、技能和成果等经历证据；对应原文片段只能保留到证据确认、主动删除、提交后 24 小时或 `owner_expires_at` 中最早者。片段删除后只保留候选陈述、位置和哈希，未经用户确认仍不得参与确定性结论。
- **REQ-RESUME-004**：用户必须能够确认、修改或删除解析结果；未经确认的推断不得作为确定事实参与结论。
- **REQ-RESUME-005**：用户能够删除简历原文、结构化事实/偏好/证据、派生结果和相关缓存。
- **REQ-RESUME-006**：用户可以单独确认和修改城市、岗位方向、招聘类型、毕业年份、到岗时间、实习出勤和明确排除项；这些求职约束与简历证据分开保存，缺失项保持未知。
- **REQ-RESUME-007**：手机号、邮箱和中国大陆身份证号等明显个人信息先在浏览器本地检测；用户处理或明确确认后才提交正文。
- **REQ-RESUME-008**：简历原文在证据确认完成后立即删除；未完成确认、异常中断或用户离开的记录也必须在提交后 24 小时内删除。
- **REQ-RESUME-009**：结构化事实、偏好和经历证据不得晚于会话建立时固定的 `owner_expires_at`，最长保留 30 天，到期删除；新增或修改修订不能延长该期限，用户可以随时提前删除。

### 4.5 资格、证据和偏好结果

- **REQ-MATCH-001**：系统先依据到岗时间、每周出勤、持续月数、毕业年份、招聘批次等明确字段判断资格；目标城市和岗位方向只进入偏好轴，不能伪装成企业资格要求。
- **REQ-MATCH-002**：资格只使用“未发现明确冲突 / 存在明确冲突 / 需补充信息”。
- **REQ-MATCH-003**：经历证据只使用“有明确证据 / 部分证据 / 简历暂未体现 / 信息不足”。
- **REQ-MATCH-004**：偏好只使用“符合 / 不符合 / 未设置”。
- **REQ-MATCH-005**：三类结果分别展示对应岗位原文、用户确认的事实或证据、缺口和未知项，不能合成为“匹配度百分比”。
- **REQ-MATCH-006**：不得使用“优先考虑”“有条件考虑”“不建议”等全局推荐标签代替三类判断；产品只提供依据和待确认项。
- **REQ-MATCH-007**：岗位要求未知与简历暂未体现必须分开；前者不能被解释为用户不具备能力。
- **REQ-MATCH-008**：未经用户确认的事实和证据不得参与确定性结果；所有引用必须能够回到岗位要求和用户证据。
- **REQ-MATCH-009**：规则或解释发生变化时，已有结果应保留可追溯版本，不能静默改写历史决定依据。

### 4.6 AI 边界

- **REQ-AI-001**：MVP-0 的 AI 功能默认关闭，岗位浏览、资格判断、证据对应和模板解释必须完整可用。
- **REQ-AI-002**：AI 解释只有通过既定增量价值 Gate 后才能以受控特性开关启用。
- **REQ-AI-003**：AI 只能解释已提供的岗位要求、用户确认事实和经历证据，不能修改资格规则或生成不存在的经历。
- **REQ-AI-004**：含 owner 数据的 AI 输入、输出和派生结果必须可追溯、可删除；`MatchRun` 只引用提示词与模型版本，不把完整提示正文写入普通日志。关闭 AI 后不得残留用户不可删除的专属结果。
- **REQ-AI-005**：AI 不可用、超时或输出校验失败时，直接展示规则和模板结果，不阻塞用户决定。

### 4.7 决策队列与官方投递

- **REQ-ACTION-001**：每个岗位的用户状态只使用“未决定 / 已保存 / 准备投递 / 已投递 / 已放弃”。
- **REQ-ACTION-002**：已保存、准备投递、已投递和已放弃均支持记录至少一个结构化原因和可选补充说明；更新状态不强制填写，但没有理由的记录不计入高质量投递决定。
- **REQ-ACTION-003**：产品只链接到官方投递页，不代替企业接收申请，不自动填写或批量提交。
- **REQ-ACTION-004**：记录“查看官方页”和“用户自报已投递”为两个不同事件。
- **REQ-ACTION-005**：用户从官方页面返回后，仍可恢复原岗位上下文并更新决定状态。
- **REQ-ACTION-006**：用户可以反馈岗位失效、来源变化、条件解析错误或证据判断错误。

### 4.8 数据控制

- **REQ-DELETE-001**：用户发起删除后立即撤销对相关数据的继续访问，并显示处理中、成功或失败状态。
- **REQ-DELETE-002**：删除覆盖简历原文、事实、偏好、经历证据、匹配运行、岗位决定、owner 关联的产品事件、AI 派生结果和相关缓存。
- **REQ-DELETE-003**：删除失败必须可重试并进入运营告警，不能向用户假报成功。
- **REQ-DELETE-004**：产品事件、普通日志和错误正文不得包含简历原文、原文片段或明显个人信息。

## 5. 页面与状态范围

| 页面/界面 | P0 内容 |
|---|---|
| 岗位列表 | 核心筛选、来源类型、最后核验时间、状态、先浏览/简历匹配入口 |
| 岗位详情 | 原始职责与要求、结构化条件、未知项、来源证据、官方入口 |
| 隐私检查 | 本地个人信息提示、修改文本、确认提交、取消 |
| 事实/偏好/证据确认 | 分组确认、修改、删除、未知状态和原文对应 |
| 资格与证据结果 | 资格、证据、偏好三栏及各自依据，不显示百分比 |
| 决策队列 | 五种状态、理由、返回续接和用户主动隐藏 |
| 数据控制 | 保留期限、立即删除、删除进度与结果 |

P0 必须覆盖加载中、零结果、部分解析、岗位待复查、官方外链变化、规则/AI 降级、会话过期以及删除处理中/成功/失败状态。每个失败状态都要提供可执行的下一步，不能只显示错误代码。

## 6. 数据保留与隐私口径

| 数据 | 默认保留 | 提前删除 | 说明 |
|---|---:|---|---|
| 简历原文 | 经历证据确认、提交后 24 小时或 `owner_expires_at` 三者取最早 | 支持 | 不进入普通日志、分析事件或错误正文 |
| 事实、偏好、经历证据 | 到固定 `owner_expires_at`，最长 30 天 | 支持 | 只保存完成当前决策所需字段，新修订不续期 |
| 岗位决定、匹配依据与 owner 级产品事件 | 到固定 `owner_expires_at`，最长 30 天 | 支持 | 与匿名会话所有权绑定；只允许另行保留不可逆汇总 |
| 不含正文的删除审计 | 90 天 | 不适用 | 仅证明请求和清理结果，不保留用户内容 |

隐私、安全和匿名会话的具体技术控制以 [安全威胁模型](04-security-threat-model.md) 和 [系统架构](05-system-architecture.md) 为准。

## 7. 核心事件与指标

### 7.1 最小事件

- constraints_confirmed
- evidence_confirmed
- job_viewed
- source_and_basis_viewed
- job_decision_updated
- official_link_opened
- application_self_reported
- profile_deletion_requested
- profile_deletion_completed

事件只记录匿名会话、岗位、状态、原因分类、版本和时间，不记录简历原文或证据正文。

### 7.2 北极星指标

> 在一个 7 日活跃求职周期内，已完成约束与经历证据确认且查看至少 3 个岗位的用户中，对至少 1 个岗位完成“查看来源与依据 -> 投递/暂缓/放弃 -> 记录理由”的用户比例。

指标映射固定为：“投递”对应“准备投递”或“已投递”，“暂缓”对应“已保存”，“放弃”对应“已放弃”；“未决定”不计入。只有完成来源与依据查看并记录至少一个理由才计入高质量决定。

### 7.3 下游强证据与守护指标

- 单独记录决定后 72 小时内自报完成官方投递的用户数。
- 错误劝退、明确硬条件冲突漏检、虚构经历、未确认事实参与结论、删除失败和隐私事件分别统计，目标均为 0。
- 岗位量、点击量和 AI 调用量不作为成功替代指标。

## 8. MVP-0 功能验收

- 匿名受邀用户无需提交简历即可浏览岗位、查看来源证据并前往官方页面。
- 每个已发布岗位都有可追溯原始链接、来源类型、最后核验时间、当前状态，以及六个重点字段的明确值或“未知”。
- 简历文本在离开浏览器前经过本地隐私检查；未经用户确认的事实、偏好或经历证据不得参与确定性结论。
- 任一岗位结果只使用规定的资格、证据和偏好术语，依据可回到岗位原文与用户确认内容；不得出现总匹配分、自动劝退或自动隐藏。
- 用户可以在五态决策队列中继续任务；打开官方链接不能自动记为已投递，返回后可以自报和修正状态。
- 简历原文在经历证据确认后立即删除，未完成或异常时最长不超过提交后 24 小时；用户发起删除后个人数据立即不可访问，并能查询删除进度。
- AI 关闭或失败时，规则与固定模板仍能完成全部 P0 链路。
- 加载、零结果、部分解析、岗位待复查、外链变化、会话过期及删除失败均有可操作的恢复路径。

用户实验方法、量化阈值与 AI 启用 Gate 只在 [产品发现与实验](09-product-discovery.md) 和 [验证与质量策略](12-validation-and-quality-strategy.md) 维护；当前执行状态只在 [MVP 路线与决策面板](06-mvp-roadmap.md) 更新。

## 9. 发布边界

MVP-0 只面向受邀测试者，不对外宣称“已验证”“智能匹配准确”或“官方认证”。是否进入 Private Alpha 由 [MVP 路线与决策面板](06-mvp-roadmap.md) 的 Gate 决定；PRD 不单独维护阶段状态或重复发布阈值。
