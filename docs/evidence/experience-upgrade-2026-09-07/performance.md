# 本轮性能与容量记录

2026-09-08。结论：1万岗位、50并发的热目录/图谱达到p95≤500ms；首次目录仍略超2秒，后台混合请求没有达到相同延迟水平。10万/100用于容量观察，不能据此承诺生产容量。下面比较均为本轮实际运行，上一轮2026-09-06仅保留为历史基线。

## 环境与测法

- Windows 11、i5-12500H、16逻辑CPU、约16.8GB内存，Node22.16，Docker PostgreSQL16.15；每个数据库权限边界连接池10。
- 独立合成库，101家公司，招聘大户约占40%岗位，未知地点约20%，未解析约10%，6种方向。岗位正文较短，批量岗位没有完整历史深度；不能等同于真实生产分布。
- 回环HTTP，真实路由、会话、CSRF与Case写入。每个用户顺序发10次请求，分为预热后的读取阶段与后台混合阶段。后台执行一次实际目录物化及一次PDF生成→解析，不调用真实招聘站或模型。
- 测量是各阶段的一次运行，不能仅据小幅变化宣称稳定改善。CPU/RSS是API进程指标，不包含整个Docker及浏览器进程树。队列只记录快照，未测持续交互队列积压。

## 1万岗位 / 50并发

单位ms；“首次”是该运行的未命中应用缓存HTTP查询，不是完整浏览器首屏时间，也不是清空操作系统磁盘缓存后的结果。

| 指标 | 优化前 | 当前 | 判断 |
|---|---:|---:|---|
| 首次目录 | 3548 | 2114 | 减少约40%，仍略超2秒 |
| 首次图谱 | 2228 | 1467 | 减少约34% |
| 热目录p95 | 352 | 348 | 达到500ms目标 |
| 热图谱p95 | 331 | 342 | 达到500ms目标，未见热查询提升 |
| 混合目录p95 | 701 | 754 | 本次略变慢，不能宣称混合负载改善 |
| 混合图谱p95 | 789 | 901 | 本次略变慢，继续跟踪 |
| Case写入p95 | 1404 | 1367 | 仍需改善交互延迟 |
| 单次物化 | 1151 | 1527 | 单样本，不是后台吞吐量 |
| PDF生成并解析 | 10239 | 11108 | 单样本，未超时；不是纯解析耗时 |

两轮均完成1000/1000计划HTTP请求，HTTP与两个后台操作均0错误。当前热阶段500请求耗时2.92秒，API峰值RSS约659MiB、事件循环p95约42ms；混合阶段含后台共11.11秒，峰值RSS约839MiB、事件循环p95约44ms。

本轮修改在单次SQL中复用来源元数据和权威活动状态，筛选项只聚合一次，图谱例句先缩减到每项三个再连接。未取消发布资格校验、未截断大公司岗位、未改变双分母、未引入新的基础服务。34项第一轮回归和25项最终回归覆盖查询结果及撤回行为。

## 10万岗位 / 100并发

首次目录23.40秒、图谱23.50秒。两个阶段的计划分母均为1000请求；到90秒后不再为用户安排下一次请求，已发出的请求继续等待结果，故阶段总时长可超过90秒。

| 指标 | 预热后读取阶段 | 后台混合阶段 |
|---|---:|---:|
| 完成 / 计划HTTP请求 | 831 / 1000 | 949 / 1000 |
| 已发出请求错误数 | 0 | 0 |
| 未继续发出的请求 | 169 | 51 |
| 目录p95 | 25.53秒 | 26.41秒 |
| 图谱p95 | 19.70秒 | 18.49秒 |
| Case写入p95 | — | 802ms（183次） |
| 阶段时长 | 105.51秒 | 91.78秒 |

合计1780/2000计划请求完成，220次未继续发出，不可称为全量成功。后台物化8.95秒，PDF生成并解析11.05秒，均单次成功。报告使用p95统计所有已发出请求，未把慢请求剔除。

这里的`hot`只是脚本阶段名：代码的缓存有效期为1分钟，而顺序预热6种查询已经超过该时长，所以这一档不能视为所有请求都命中热缓存。结合代码判断，重建耗时与到期轮换放大了高容量查询等待；仍需专项测量才能区分各类失效占比。当前结果只说明这档容量不达标，不能借“0错误”宣布可用。

原始记录：[10万/100容量报告](performance-capacity-100000-100.json)。这一档未运行旧的全量目录服务，避免重复此前长时间阻塞；因此进程RSS也不宜与先运行过旧全量服务的1万档直接比较。

## 接下来的性能工作

优先解决常规规模下的首次目录与后台混合延迟，单独压测交互任务队列的等待和取消，不用提高超时冒充优化。大规模聚合需要减少每次重建扫描；任何预计算方案仍须受当前发布代次、撤回及到期时间约束，不能简单延长缓存而展示过期岗位。先保留PostgreSQL与现有边界，不为容量探索新增搜索或缓存服务。

复现入口为`apps/platform/src/performance/product-core.ts`。仅设置专属`AIJOB_BENCH_DATABASE_URL`，数据库名须含`benchmark_test`；`AIJOB_BENCH_JOBS=10000`、`AIJOB_BENCH_CONCURRENCY=50`。已有同一合成夹具可以设置`AIJOB_BENCH_REUSE_FIXTURE=1`；新建空库省略该项。指定`AIJOB_TEST_BROWSER_EXECUTABLE`、`AIJOB_TEST_PDF_FONT`启用实际PDF/解析，否则该路径不构成验收。通过`AIJOB_BENCH_OUTPUT`写入新的证据文件，保留历史运行。10万/100的SQL限时30秒，客户端60秒，阶段90秒后不再安排后续请求；未发出及失败请求均须计入容量报告。
