## 本轮具体改进

- **直接使用材料**：上传后进入简历编辑；原文件可找回，删除原件与删除文档分开。姓名、电话、邮箱不脱敏。旧的隐私复核、逐句勾选和初始化不再是新流程前置。
- **完整经历**：带日期的多段实习、多所学校和项目分别成条；要点保留共同项目上下文，模糊的无日期叙述整体保留。首次自动收录有稳定关联和去重；方向改稿不改写经历原稿。
- **保存与版本**：慢保存响应不覆盖新输入；延迟解析结果可显式载入且重试幂等；从设置、岗位或材料返回保留任务输入和滚动位置。实际投递正文及布局成对固定，后来的简历改稿不改变它。
- **真实 AI 接入设计**：用户自行配置 Chat Completions 兼容 API 的地址、模型、密钥、JSON方式、超时与预算。平台不提供个人模型。连接测试使用无个人内容的请求；未配置时仍可手工编辑和使用明确标记的固定辅助。
- **申请工作流**：总览按准备、已投递/面试、结果阶段显示下一项任务；规则核对保留为可展开的旧能力。岗位要求能就地建立准备事项并关联整段经历。统一面试助手使用实际投递稿或启动时选定的材料。
- **生命周期**：用户选择保留练习时，练习与冻结材料独立存在；选择删除时清除对话与快照，迟到的模型结果不能回写。新访客的会话期限与材料留存分开，旧访客不批量转换保留模式。
- **发现并修复申请翻页缺陷**：截止时间游标中的顶层 OR 缺少括号，可能越过 owner/阶段条件；已补齐条件分组，并验证后续页只含当前用户、当前阶段的预期记录。
- **查询性能**：来源元数据在单次查询中复用；岗位活动状态复用权威资格查询的结果；筛选项计数只聚合一次；图谱仅保留每项三个代表例子供后续连接。完整岗位、企业双分母和撤回资格不变。

## 尚未接受为发布就绪的部分

用户自带API的真实回答质量、部署Linux上的新模板与解析环境、SMTP实投、公开来源准入和持续刷新尚未完成。平台无需购买模型；真实兼容服务质量仍需使用真实用户配置分别评价经历、简历、岗位和面试四类结果。实体手机软键盘、长时间工作区使用与持续worker队列等待还需实测。
