# 简历准备：一轮起草与一轮审阅

本轮复用现有 assistant session / turn / adoption 与 owner task，不新增数据库迁移、模型服务或消息队列。`workflow=resume_prepare` 存入 session options，旧会话默认 dialogue。通用稿可以独立使用，Case 稿读取已授权的岗位上下文。

## 行为与事实边界

- 用户启动一次准备后，执行一轮起草，再进行一轮独立审阅；没有循环重写或自动采用。草稿只提出当前条目的修改，仍通过已有采用、版本冲突与撤销路径落稿。
- 第一轮通过确定性引用与数字校验后立即保存在 turn 中。审阅请求、格式或预算失败时，保留这版草稿并明确显示未完成审阅。工作进程重取已保存草稿时不重复起草。
- `personalFacts` 与 `jobContext` 分开发送。个人简历修改与个人成稿只能用前者作为引用和数字依据；岗位职责、年限、指标不会因出现在 JD 中就通过个人事实校验。岗位解释产物仍可引用岗位原句。
- 数字按完整 token 比较，文档和条目 ID 不作为事实依据。独立审阅标记 `unsupported_fact` 的修改保留供查看，但前端与采用服务都阻止直接写入；不会要求用户逐句批准来绕过这个检查。
- 固定辅助提供选材、个人贡献、事实遗漏与完成导出的完整清单，没有 API 时仍可编辑、导出与投递承接；不把固定清单标成模型成稿。

## 定向验证

- 5 个策略单测通过：JD 与个人数字隔离、ID 数字排除、两阶段顺序、第一稿先保留、审阅失败与已存草稿恢复、非法审阅条目 ID、固定辅助。
- PostgreSQL 两组集成共 13 项通过：新增的两个 native fixture 验证起草与审阅恰好各一次、审阅前第一稿已落库、审阅失败后可采用保留稿、无依据标记被采用服务拒绝；既有 11 项保留旧的通用审阅、采用冲突、经历不被覆盖、删除与所有者隔离等边界。
- contracts build、platform/web typecheck 通过。综合构建与浏览器主线由总升级证据记录。

以上模型请求均为本地 fixture provider，不是真实供应商调用或实际写作质量验收。引用与数字检查、独立模型审阅不能证明全部语义事实正确；真实供应商、预算行为与个人材料的内容质量仍需独立验收，不能用这些工程测试替代。
