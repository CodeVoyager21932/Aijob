## 1. 目标与范围

M2 将既有简历解析、事实确认、Resume V2、确定性优化和 DOCX 能力收进同一 Career OS，不再建设第二套简历写入模型：

```text
基础简历资产
→ 解析与用户事实确认
→ 结构化章节和区块编辑
→ 基于真实 Case 创建岗位派生简历
→ 逐条接受、编辑后采用或拒绝建议
→ 切换两种中文模板
→ A4 预览、DOCX 与浏览器打印交接
```

本次没有实现投递状态界面、Interview、Debrief、Knowledge 或旧页面迁移；没有访问真实招聘来源、真实 AI、真实简历、邮件、服务器、开发业务库或 Alpha 库。所有浏览器数据与 PostgreSQL 数据均为合成夹具和随机隔离测试库。`.claude/`、`.data/`、密钥、令牌、本地业务数据库、下载产物和截图均未进入提交。

## 2. 实现结果

### 2.1 同一 Resume V2 真源

- `/resumes` 成为基础 Resume Document 入口；既有 V1 保持只读，用户第一次显式编辑时才初始化 V2。
- 基础简历和 Case 派生简历复用同一结构化编辑器与不可变 content/layout revision；section/block ID 和 evidence 引用可追溯。
- 编辑器支持章节与区块增删、正文修改、证据关联和可访问的上移/下移，不把拖拽或通用富文本作为必需能力。
- 每次保存要求 `expectedRevision`；并发冲突会重读服务端状态并保留本地草稿，不自动覆盖。

### 2.2 岗位派生与建议决策

- Case 派生简历固定创建时的 Case、岗位版本、基础内容修订与证据修订，不会随当前证据漂移。
- Review 通过既有 PostgreSQL owner task queue 生成确定性 findings/suggestions；未接入第二套队列、数据库或 AI SDK。
- 建议只能逐条接受、编辑后采用或拒绝；接受和编辑生成新内容修订，拒绝只保存不可变决定，原修订与证据引用不被覆盖。
- 确定性建议只组合用户已确认的原子证据陈述，不机械重复“技能：”“结果：”等字段前缀，也不创造经历。
- 当前 Review 查询按最近更新时间和稳定次序返回最新一次运行，重复生成后不会误取旧运行。

### 2.3 模板、预览与导出

- 中文经典单栏与中文紧凑技术模板共用同一语义正文；换模板只追加 layout revision，不修改内容或 evidence ID。
- 浏览器 A4 预览、隔离打印节点与 DOCX 导出均读取用户明确选择的内容和布局修订，不会静默改用“当前最新”数据。
- DOCX 继续使用既有无宏、单栏、ATS 友好导出器；没有新增服务器 PDF 服务。
- 岗位列表、Case 列表和其他非简历首屏不加载编辑器、模板或导出逻辑。

## 3. 验收中发现并收口的问题

- 确定性建议曾把结构字段名和完整句子机械拼接，产生“技能：技能：……”式重复；现改为只组合已确认原子陈述，并补多陈述标点回归测试。
- 私有 JD 要求分解曾把岗位标题和纯“职责/要求”标题误当 Requirement；现精确排除标题行，同时保留真实原句、unknown 和 source span。
- 同一 JD 原句可合法产生毕业年份和在校状态两个原子事实，界面此前看起来像重复行；现显示 Requirement 类型标签，保留原始语义而不错误合并事实。
- 当前 Review 曾只按创建时间读取，极近时间重跑时可能返回旧 run；现按 `updated_at`、`created_at`、`id` 稳定倒序，并由集成测试校验最新 run ID。
- migration forward-contract 测试仍把 030 当作最新版本；已更新为 031。
- 首轮总 Gate 中存在一个遗留开发后端和 worker 仍连接测试库，造成随机超时与 Review ID 干扰。确认精确进程树并停止后，重新创建全新隔离库，平台 451/451 与全仓串行测试干净通过。
- 两个确实超过默认 5 秒或旧 15 秒预算的 PostgreSQL 集成用例改为显式 15 秒/30 秒预算；没有删除断言、跳过测试或放宽业务条件。

## 5. 浏览器与视觉 Gate

浏览器验收使用合成私有 JD、合成简历、合成证据和隔离 PostgreSQL：

- 完成私有 JD → Requirements → 基础简历确认 → V1→V2 → 基础编辑 → Case 派生 → Review 三决策 → 模板 → DOCX/打印的完整 M2 路径。
- 基础正文、布局和区块 URL 在刷新、深链、前进/后退后恢复；两个标签页制造 revision conflict 时，陈旧标签页保留草稿且不静默覆盖。
- 修正后 Requirement 列表不再出现岗位标题或纯章节标题；同一原句产生的两个原子事实分别标注“毕业年份”和“在校状态”。
- 1280px、320px 和 640 CSS px 的 200% 等效视口无水平溢出；移动检查器、键盘选择和关闭后焦点返回可用。
- 正常路径控制台无新增 warning/error；打印内容使用隔离的直接 body 子节点，不与应用壳层混排。
- DOCX 接口和页面成功返回；当前应用内浏览器控制器没有暴露原生 blob 下载事件，因此不把“系统下载栏已出现”记为人工证据。DOCX 文件结构、内容修订选择和无宏约束由自动化测试覆盖。

本轮最后一次 `VITE_CAREER_OS_V2=false` 人工复验时，应用内浏览器控制后端在导航阶段超时并重置，未能形成新的 DOM/截图证据。本 Gate 对旗标回退采用：M1 已通过的旧壳层人工验收、M2 的环境解析自动化测试，以及 M2 仅在开启分支注册 `/resumes` 的结构差异检查。旧 `ProductShell` 和旧岗位页本轮没有改动。该限制被接受为低风险验收缺口，并要求在 M3 或 M4 浏览器 Gate 可用时重跑；不得把它写成“本轮人工通过”。

## 7. 风险与证据边界

- M2 证明专业简历闭环在合成数据上的工程可用性，不证明目标用户愿意采用建议、简历质量优于现状或投递成功率提升；产品证据仍为 `E0`。
- 可信供给仍为 22 岗 / 3 家企业 / 3 个官方 ATS，公共与 Alpha 岗位均为 0；合成 Case 和简历不计入供给或用户证据。
- 真实国产模型、自带 API 和未来中转站白名单仍需单独的供应商、隐私、费用与增量价值 Gate；M2 没有调用真实模型。
- `VITE_CAREER_OS_V2` 继续作为紧急回退开关；关闭入口不得删除已创建的职业资产。
- 历史 Phase 2B 和废止总计划只保留历史证据，不得生成 M3 任务。

## 8. 决定

决定：**继续**。

M2 的功能、自动化、隔离数据、浏览器主路径、包体和安全边界满足退出条件；已披露的旗标关闭复验限制不改变 M2 新功能路径，也有 M1 人工证据和本轮自动化/结构证据兜底。当前唯一目标切换为 `M3 投递与持续改进`。

M3 只实现用户显式投递记录、确定性文字面试、结构化反馈/复盘及其回到已确认事实和简历的最小闭环；不进入 Knowledge、真实 AI、真实来源、服务器或旧页面迁移。
