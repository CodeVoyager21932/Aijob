## 4. 字段与质量结论

- 标题、岗位 ID、方向、事业群、工作城市、职责、要求和官方详情链接可以确定性读取。
- 页面筛选映射为“日常实习”，但上述岗位自身的 `projectName` 和 `recruitLabelName` 均为“应届实习”。两者必须分别保留并进入冲突复核，不能静默归一。
- 这 5 条没有稳定提供到岗时间、每周出勤、持续月数、毕业年份、发布日期或截止日期；这些字段必须保持 `unknown`。
- 前 5 条全部属于技术方向，不满足首轮 `product / operations` 样本约束，不更新 20–30 条用户岗位样本进度。
- 初始 HTML 只是动态页面外壳。采集实现应调用经过审批的公开数据接口，不以浏览器自动化作为生产抓取方式。

## 7. 工程验收事实

- 内部接口 `/v1/internal-preview/jobs` 返回 14 条岗位，公开接口 `/v1/jobs` 返回 0 条，政策闸门生效。
- 岗位详情保留原始职责、要求、官方链接、字段证据以及 `known / unknown / conflict` 状态；未知条件没有被模型或规则补写。
- 产品运营岗位同时出现 `product / operations` 时保持冲突并进入复核，不静默选择一个方向。
- 网络目标策略已写入数据库并随 policy 版本不可变：搜索接口不允许查询参数，详情只允许 `postId`，官方岗位页只允许 `postid`，全部禁止重定向。
- 任务实际写入受租约 owner、fencing token 和到期时间保护；并发修订原子复用，临时失败退避重试，永久失败进入 `dead`。
- 移动端和桌面端浏览器均完成列表、详情、来源证据和官方链接交接检查，无横向溢出或控制台错误。
- 自动化测试与 CI 只使用合成夹具或可选本地 PostgreSQL；CI 不访问腾讯或其他真实招聘站。

这些事实只证明第一条工程链路可以工作。来源政策获批、至少 3 个代表来源稳定、用户价值实验和公开上线门仍需分别验证。
