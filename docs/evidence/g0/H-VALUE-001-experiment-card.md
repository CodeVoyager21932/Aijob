# 实验卡：H-VALUE-001 四层礼宾价值验证

- 实验 ID：H-VALUE-001-CONCIERGE-2026-07
- 计划日期：G0 通过后安排

- 关联 Gate：G1；G0 只判断本协议是否可执行
- 关联证据/访谈：待填写 6 份正式任务记录与 6 份 72 小时回访

## 假设

我们相信：来源/时效、资格和经历证据三层信息能改善真实投递决定，且不会造成错误劝退。

如果：让目标用户按“现有流程基线 → 官方岗位清单 → 来源与时效 → 资格与经历证据”逐层完成同一投递决策任务，

那么：用户会更快找到无已知硬冲突且愿意认真考虑的岗位，正确区分四类概念，并在 72 小时内形成可追溯的高质量决定，

因为：增量信息直接减少资格核验和经历证据解释成本，而不是只增加界面的专业感。

## 为什么现在验证

- 风险类型：价值 / 安全
- 如果假设错误，会导致：后续工程自动化没有意义，或造成错误劝退与错误事实风险。

## 方法

- 目标用户：与 H-PROBLEM-001 相同的首轮用户；校准用户排除在正式样本外。
- 样本数量：6 名正式用户；仅在 G0 通过并确认合格招募名单后开始。
- 实验材料：20-30 条经人工确认的产品/运营实习岗位、统一任务脚本、术语检查题、去标识化记录表、72 小时回访脚本。规则与固定模板先行，AI 默认关闭。
- 操作步骤：记录现有流程基线；依次展示四层信息并记录每层新增/撤回/改变的决定；20 分钟任务；四类概念解释；官方外链交接；72 小时回访高质量决定与官方投递自报。
- 数据与隐私处理：匿名邀请，不收手机号或邮箱；本轮准备不请求简历。若未来确需经历证据文本，必须先完成独立隐私说明、去标识化确认和删除约束，且不因拒绝提供而判用户失败。

## 预先定义的判断标准

### 支持假设（G1 全部同时满足）

- 至少 4/6 用户在 20 分钟内找到 3 个愿意认真考虑且根据当前已知信息无硬条件冲突的岗位。
- 至少 5/6 用户正确区分“资格冲突、简历暂未体现、岗位信息未知、偏好不符”。
- 至少 3/6 用户在 72 小时内完成至少一个高质量投递决定，且至少 2 人自报已在官方页面投递。
- 来源与时效、资格、经历证据层的增量能由逐层行为变化和理由支持，而不只是主观喜欢。
- 所有守护指标为 0。

### 反驳假设

- 任一产品结果阈值未达到，或增量信息只提升主观好感而不改善理解、效率或行动。
- 用户无法稳定区分资格、证据、未知和偏好，且校准后仍需主持人代为解释。
- 任一守护事件发生；不能用平均成功率抵消。

### 守护指标

- 明确硬条件冲突漏检 = 0。
- 无冲突被误判并据此劝退 = 0。
- 引用不存在或未确认的经历 = 0。
- 未确认事实参与结论 = 0。
- 隐私或安全事件 = 0。
- 未经独立增量 Gate 不启用 AI；不输出匹配百分比，不自动隐藏或劝退岗位。
