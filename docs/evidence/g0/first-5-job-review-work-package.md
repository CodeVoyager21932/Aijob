# 首批 5 条产品/运营岗位人工核验工作包

## 当前状态

以下 5 条来自腾讯校招 `pending_review` 工程切片，仅是**待人工核验候选**。数据库中的自动规范化、`active` 状态和字段分类不构成人工确认、金标、来源准入或公开发布依据；人工岗位进度仍为 `0/20-30`。

候选表中的 `last_verified_at` 仅表示本地采集最后见到该记录的时间，不代表人工在该时间打开官方页面。人工复核必须另填 `reviewed_at` 和复核者。

## 复核者逐条操作

1. 从候选表打开 `source_url`，确认页面属于腾讯官方招聘主体，记录最终落地域名和是否出现登录、失效、重定向或其他异常；不要绕过任何访问控制。
2. 确认岗位仍可查看、仍接受申请，以及 `apply_url` 是否指向同一官方岗位；不能确认时把活动状态写为 `uncertain`，不要猜测为 `active`。
3. 对照官方页面逐字核对岗位标题、组织/事业群、职责摘录和要求摘录；摘录只需足以定位证据，不复制整页。
4. 判断实际职能是否属于首轮 `product / operations`。若标题或正文同时体现产品与运营，保留 `conflict` 并写明原文，不强制归到单一类别。
5. 逐项核对六个资格重点字段：城市、到岗时间、每周出勤、持续月数、毕业年份、招聘批次。页面未明确出现时必须写 `unknown`。
6. 记录主体证据、最后人工核验时间（带时区）、复核者代号、复核结果 `confirmed / replace / needs_second_review` 和所有未知/冲突说明；复核完成前保持 `pending`，不得计入人工样本进度。
7. 若岗位不是实习、超出产品/运营范围、页面失效或主体无法确认，标记 `replace` 并保留替换理由；不要静默删除该行。
8. 将完成的候选表交给 coco 或指定人工复核者确认。只有确认后才能转换为正式 `import_mode=manual` 样本并更新路线面板计数。

## 模板口径决定

[岗位样本模板说明](../../templates/README.md) 已将 `function_track` 收敛为 `product / operations / conflict`：只有官方标题或正文同时指向产品与运营、且人工不能诚实收敛时才使用 `conflict`，并必须在 `unknown_or_conflict_notes` 保留依据。该值表达“待人工解决的职能冲突”，不代表第三种岗位方向；确认后若证据足够，可改为单一方向并保留复核记录。

## 完成判定

一条候选只有在官方页面逐项人工检查、所有未知/冲突诚实保留、复核记录完整，并由 coco 或指定复核者确认后，才算一条人工核验岗位。准备好表格、自动提取字段或打开页面均不计数。
