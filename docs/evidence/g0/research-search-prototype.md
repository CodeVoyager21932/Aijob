# G0 研究检索原型说明

> 状态：工程交互壳已完成 / coco 已确认“协议已校准”，实际参与人次与逐场记录待确认
>
> 适用阶段：Phase 0 / E0
>
> 计数影响：人工岗位样本为 `5/20-30`；协议校准的可核验记录仍为 `0/2`；正式实验、稳定来源和 72 小时回访仍分别为 `0/6`、`0/1` 和 `0/6`。

## 1. 用途

本原型只用于校准“搜索、筛选、进入详情、返回恢复、零结果和未知字段”是否无需主持人额外教学。它是 G0 实验材料，不是公开岗位产品，也不能单独证明 `H-PROBLEM-001` 或 `H-VALUE-001`。

原型与本地内部复核端保持分离：

- 研究入口为 `/research/jobs`，详情使用 `/research/jobs/:jobId`。
- 研究路由只允许在 `dev/test` 环境注册；生产环境不得注册或通过参数切换进入。
- `/internal-preview/*` 继续用于采集和字段复核；研究页面不展示内部发布警告、采集状态或复核原因。
- 参与者研究页面不提供内部复核入口；复核者只能通过交接文档中的独立地址进入内部端。
- 当前不注册公开 `/jobs/*` 用户产品路由，也不改变公开 `/v1/jobs` 的空结果政策闸门。

## 2. 当前数据边界

研究目录当前包含 coco 确认的 5 条岗位，确认范围和时间见[首批 5 条研究样本确认记录](first-5-job-confirmation-2026-07-18.md)。代码中的 `approvedResearchJobs` 使用独立、显式的研究样本，不会读取整个候选 CSV，也不会把其余 9 条自动采集候选带入。

腾讯来源仍为 `pending_review`。本次人工确认只允许这 5 条进入本地 `dev/test` 研究样本，不等于批准腾讯来源公开发布，也不改变稳定来源、金标、产品证据或 Gate。

装载研究样本时必须同时保留：

- 人工样本 ID、官方来源、发布主体、最后核验时间和复核者确认记录。
- 活动状态必须有人工确认的 `active` 证据；未知、冲突或已关闭岗位不会进入研究目录。
- 官方跳转必须随样本记录精确的 HTTPS 主机、443 端口、路径前缀和查询参数白名单；仅为 HTTPS 不足以放行链接。
- 城市、到岗时间、每周出勤、持续月数、毕业年份和招聘批次的已知值，或明确的 `unknown`。
- 产品/运营分类冲突的 `conflict`，不得把冲突岗位静默归入任一方向。
- 公司稳定标识只使用已确认值；实际样本不足两家公司时隐藏公司筛选，不新增来源或伪造选项。

## 3. 原型交互范围

当前交互壳只覆盖岗位检索所需的最小能力：

- 关键词只匹配岗位名与公司名。
- 城市、公司和产品/运营方向多选；更多筛选包含每周可出勤天数和可持续月数。
- 同一维度内使用 OR，不同维度之间使用 AND；未知或冲突值不被猜测为已知选项。
- URL query 保存筛选状态，以支持刷新、前进后退和详情返回。
- 为满足刷新、分享和返回恢复，`q` 与其他筛选同样保存在 URL；研究原型不把查询发送到服务端或分析系统，未来接公开 API 时必须在访问日志、错误日志和分析事件中剥离完整 query string。
- 已选条件可逐项删除，并始终提供“清除全部”。
- 零结果保留全部条件，不自动放宽；结果区说明未知字段数量。
- 列表采用紧凑单列，详情返回只接受同源研究列表状态。

这些行为只作为协议可用性诊断，不新增第三个核心假设，也不增加 G0 通过条件。搜索次数、筛选组合、零结果和返回恢复只能解释失败原因，不能单独宣告用户价值成立。

## 4. 真人校准执行与证据闭环

1. 首批样本和工程走查已完成；coco 随后确认“协议已校准”，见[完成状态确认](protocol-calibration-confirmation-2026-07-18.md)。
2. 当前确认未包含参与人数和逐场结果；先确认实际人次，再为每个已完成场次归档参与者是否符合招募条件，以及能否独立完成搜索、筛选、进入详情、返回恢复、理解零结果与未知字段；不足两场则补做。
3. 每份记录还需写明主持人提示次数与内容、术语错误、近期行为基线、反例、意外发现和守护事件；无法确认的字段保持“未知”，不得追忆性编造。
4. 确认每个可确认场次所用原型提交、5 个样本 ID、任务脚本和记录表是否一致，并明确期间是否发生任务措辞、界面层级、筛选语义或记录方式的实质修改。
5. 若发生实质修改，记录受影响范围并重做受影响的校准部分。
6. 只有校准记录达到可追溯的 `2/2` 且 6 名正式用户已确认后，才按路线面板规则判定“进入正式实验 / 继续校准 / 修改人群”。

## 5. 明确延后的范围

以下内容不属于当前 G0 研究原型：

- 生产 `/jobs/*`、匿名邀请、事实/偏好、简历隐私检查、经历证据、三轴结果、决策队列和数据删除页面。
- `GET /v1/jobs` 的正式 `JobSearchResponse`、facets、游标、查询指纹及公开详情 repository。
- `catalog.published_jobs` 公开状态、不可变版本检索投影、`catalog.current_published_jobs` 视图、数据回填或内容哈希迁移。
- `pg_trgm`、GIN 或其他尚无真实查询计划与延迟证据支持的索引。
- AI、简历能力、第二来源、来源政策变更或把 `pending_review` 数据公开。

生产检索接口和目录迁移至少延后到 G1 通过并进入 MVP-0 工程切片后；AI 仍需独立增量 Gate；来源公开与 Private Alpha 仍受现有来源准入及 G1-G3 约束。

目录迁移开始前还必须先用契约评审或 ADR 解决两个所有权问题：当前 `publication_state` 已位于来源修订，不能再给公开岗位增加一个未定义优先级的状态真源；历史岗位版本不可变，也不能为了新增检索投影直接重算旧 `content_hash`。后续只能明确状态所有者，并版本化哈希语义或只对新版本启用新投影。
