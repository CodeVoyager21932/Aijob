## 2. 自动化证据

在本地 PostgreSQL 16 上执行：

```powershell
$env:AIJOB_TEST_DATABASE_URL='postgresql://aijob:aijob@127.0.0.1:5432/aijob'
pnpm test
pnpm typecheck
pnpm build
pnpm lint
```

结果：

- 237 项测试通过：platform 159、web 51、config 16、contracts 6、database 5。
- TypeScript 全工作区通过。
- Web 与 platform 生产构建通过；lint 197 个文件，无错误或警告。
- `pnpm audit --prod` 未发现已知生产依赖漏洞。
- PostgreSQL 集成覆盖匿名 owner、CSRF、PDF/文本路由、加密原文、不可变修订、三轴、推荐、模板降级、DOCX、决定、TTL、删除、owner 撤销和 worker 租约接管。
- owner task 的业务提交会在同一事务锁定任务与 owner，核对任务类型、epoch、租约持有者、fencing token 和过期时间；旧 worker 在供应商响应返回后被接管时不能写入成功或失败结果，新 worker 可从 `processing` 恢复。
- 本地简历密钥首次启动随机生成到 Git 忽略的 `.data/`，启动日志不包含简历密钥或 AI 密钥；`alpha/production` 缺少显式密钥时拒绝启动。
- `analysis_result` 受数据库约束，只允许保存解析版本和候选数量；姓名、地址等可能仍存在的去标识化文本与证据片段不会进入普通 JSONB。完整候选仅在 active owner、epoch、固定保留期和简历 24 小时 TTL 均有效时，从加密临时文本即时重建。
- 确认、TTL、解析失败和扫描件失败都会清除简历密文、解析元数据与可能包含姓名的原始文件名；迁移 009 同步压缩旧结果并清理既有过期行，迁移 010 强制已清理行不得再次保存正文密文、解析元数据或原始文件名。
- DOCX 在 24 小时精确到期后会清除密文三元组并终止旧租约；owner 到固定 30 天期限后会并发幂等撤销访问并删除全部结构化数据，无正文审计、删除任务与墓碑在 90 天后清理。
- 32 个命名金标案例覆盖硬条件冲突、未知条件、证据缺失、偏好、技能边界和排序；未把它们计为用户研究证据。

## 3. 浏览器闭环

使用不含个人信息的合成中文简历完成：

```text
31 条岗位推荐
-> 查看岗位来源、原文和三轴依据
-> 记录“准备投递”与理由
-> 显式同意使用去标识化、已确认证据
-> 模板降级生成 2 个可追溯修改片段
-> 接受第 1 段、编辑第 2 段
-> 生成 9,105 字节 ATS DOCX
-> 返回岗位详情确认决定仍存在
-> 删除全部个人数据
-> 旧优化任务返回“不存在、已删除或不属于当前会话”
```

- `?start=1` 会清除旧推荐运行并基于当前 31 个岗位重新生成；旧目录版本不再逐条刷重复警告。
- 推荐创建时冻结 `source_job_records.last_seen_at`；后续重复核验不会改变既有排序，新岗位版本或失效策略会标记旧推荐状态。
- 同一优化任务刷新后只恢复属于该任务的 DOCX；另一个任务的导出 ID 不会串入当前页面。
- PDF/DOCX 模式明确提示浏览器未读取文件正文，切换输入或重新选择文件会撤销旧隐私确认；确认简历和删除 owner 后，浏览器缓存不会恢复已清理的原文或个人结果。
- 岗位详情只展示属于当前岗位版本的 `MatchRun`；错误或过期版本会从地址中移除，并要求按当前岗位重新核对。
- 资格、经历证据和偏好保持分轴，不显示匹配百分比，不自动劝退或隐藏岗位。
