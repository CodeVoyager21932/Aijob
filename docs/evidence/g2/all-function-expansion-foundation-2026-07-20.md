# 全部职能扩容离线基础验收记录（2026-07-20）

## 结论

ADR-0015 的不触网工程基础已经完成：12 类职能契约、来源配置发现、`sourceKey`/`adapterKey` 解耦、四项请求预算、优先与候补公司登记、全部职能能力词典 v2，以及 1000 条合成岗位的单 PostgreSQL 容量回归均通过。

本记录不代表 100–200 条真实岗位目录完成，也不代表新增来源通过准入。字节跳动、阿里巴巴、京东、百度、华为、小米、滴滴、快手和网易仍为 `not_assessed`，没有可运行来源配置；本次没有访问任何真实招聘站。产品证据仍为 `E0`，G0/G1 继续暂停。

## 已实现范围

- `JobFamily` 固定为 12 个版本化值，正式岗位筛选、偏好、匹配输入和中文标签共用同一契约；旧 `product`、`operations`、`other` 数据继续可读。
- 岗位分类器只使用官方分类原词和高精度标题词典；多职能冲突进入复核，无法稳定归一保持 `unknown`。
- `config/sources/*.json` 由目录自动发现，不再维护三个来源键的代码级白名单。
- 来源级 `adapterKey` 可被不同企业或租户配置复用；当前三个适配器键与来源键已经分离。
- 每个来源显式保存 `maxItems`、`maxPages`、`maxRequests`、`minimumIntervalMs`；请求在发出前扣减预算，越界直接失败。
- `config/source-candidates.json` 固定 12 家优先顺序和候补顺序；待评估企业没有 URL、网络白名单或来源键，不能被 CLI 探测。
- `capability-ontology-v2` 增加工程、算法/模型、设计、市场、商务、财务、人事、法务、研究咨询、供应链和制造能力；SQL、Java、Figma、SAP 等明确工具继续走严格原词路径。
- PostgreSQL 容量测试在事务内插入 1000 条合成岗位，验证 12 类 facet、工程职能筛选和 1000 个稳定 ID 的确定性排序后回滚；正式 `aijob` 数据库仍为 31 条岗位，合成记录为 0。
