# G2 验收反馈修正：资料复用、能力证据与数据容量（2026-07-20）

## 1. 结论与证据边界

coco 在本机验收中指出三项问题：数据控制只能删除、跨日需要重复上传；31 条推荐的经历证据普遍为 0/N；目录数量和存储位置不透明。本轮完成工程修正与容量核对，但这属于产品 owner 验收反馈，不计为目标用户行为证据，产品证据仍为 `E0`，G0/G1 未开始，G3 仍为 0/3。

本轮没有访问真实招聘站，没有增加或伪造岗位，也没有改变三个来源的 `pending_review` 状态。

## 2. 资料复用修正

- 新增当前 owner 的 `GET /v1/profile/document`，只返回确认后允许保留 30 天的 `ResumeDocumentRevision`，不恢复已删除的原文件、临时原文或旧版 v1 内容。
- 新增 `PUT /v1/profile/evidence-selection`。用户可从当前有序 section/block 中重新选择 `sourceBlockId`，服务端据此生成新的不可变 `ResumeEvidence v2` 修订；客户端不能提交任意经历正文。
- “简历与画像”页优先显示已保存资料、当前证据选择和“保存证据选择并生成最新推荐”，仍保留上传新版简历入口。
- “数据控制”页增加结构化区块数量、查看/调整资料和沿用当前资料生成推荐；经历证据为 0 时直接说明这会导致推荐页显示“简历暂未体现”。永久删除继续不可恢复。

真实浏览器以纯合成简历验证：确认 4 个结构化区块和 3 段证据后，复访简历页可直接查看并复用；取消 1 段后保存为 2 段新证据修订，并成功重新生成 31 条推荐。

## 3. 经历证据匹配 v3

匹配仍为确定性规则，不使用 AI、向量库或隐藏分数：

1. 只读取用户主动确认的原子 `ResumeEvidence v2`。
2. 先做岗位原词与证据原词的严格匹配。
3. 对“数据分析、用户研究、市场与竞品研究、产品策划、项目推进、沟通协作、运营增长、内容策划、AI 应用”等能力要求，使用有版本的固定能力词典连接可解释的同类行为。例如“用户调研”可由“用户访谈”支持，“数据分析”可由“SQL + 指标看板”支持。
4. 岗位明确点名 SQL、Python、Excel、Figma、Axure、Tableau 或 Power BI 时，必须命中该工具本身；同属一个能力域不能冒充满足。
5. 无法稳定归一的主观要求继续为信息不足；未找到同类行为时继续为“简历暂未体现”。

规则、词典和说明版本升级为 `eligibility-rules-v3`、`zh-cn-internship-v3+capability-ontology-v1` 和 `three-axis-explanation-v3`。推荐页增加可展开的算法说明，岗位详情显示逐项正向证据解释。

合成简历真实浏览器结果不再统一为 0/N：美团“交易产品实习生-AI应用”显示证据支持 1/2，并解释“岗位要求可归一为数据分析，已确认经历中存在同类行为证据”；其他岗位按实际要求出现 1/9、2/6、3/5 等不同覆盖。证据不是为了凑高覆盖，仍允许 0/N 和信息不足。

## 4. 当前 31 条岗位的存储位置与占用

2026-07-20 只读测量：

| 项目 | 当前值 |
|---|---:|
| PostgreSQL 整库 | 14 MB |
| `catalog` 关系分配 | 1,104 kB |
| `ingestion` 关系分配 | 1,192 kB |
| `source_control` 关系分配 | 464 kB |
| 三个岗位相关 schema 合计 | 约 2.7 MB |
| 当前稳定岗位 | 31 |
| 历史不可变岗位版本 | 45 |
| 当前来源记录 | 31 |
| `.data/job-snapshots` | 29 个文件，80,097 字节 |

PostgreSQL 是唯一查询和任务真源，数据位于 Docker 命名卷 `aijob-local_aijob_postgres_data`；Docker Desktop 内部挂载点为 `/var/lib/docker/volumes/aijob-local_aijob_postgres_data/_data`。离线原始快照位于仓库 Git 忽略目录 `.data/job-snapshots/`，只用于可复现解析，前端不直接查询快照。

当前容量很小，扩到 60–100 条不需要 Redis、向量库、新服务器或新的 AI 费用。真正瓶颈是官方来源准入、受限采集、字段复核和新鲜度维护，而不是磁盘。

## 5. 扩容边界与下一步

当前三个来源的单次受限上限分别是腾讯 20、美团 20、南开就业网·好未来 7，理论合计 47；仅重复运行现有离线流程不能可靠扩到 60–100 条。下一轮需要增加经过主体证明、访问政策、网络白名单和离线夹具审查的官方来源，或在完成同等审查后扩展现有来源的岗位流。

coco 需要提供或确认的不是服务器资源，而是：

1. 首个目标规模选 60 条还是 100 条。
2. 产品/运营的优先比例、城市和希望优先覆盖的公司。
3. 明确授权一次维护者真实来源评估/低频探测；不需要账号、验证码、招聘平台 Cookie 或代理。
4. 对新增来源和抽样岗位做少量人工复核；`pending_review` 仍只能进入本机目录。

完成这些确认前，不会为了数量抓综合平台、绕过登录、放宽白名单或把待审来源公开发布。

## 6. 界面验收补充

- 岗位目录的关键词、城市和岗位方向改为统一三列基线；关键词补足与两个枚举条件等高的说明行，“查看岗位”移入独立操作区，避免在桌面宽度下挤压筛选项。
- 已保存简历增加“全选全部”和“清空选择”，并实时显示“已选择 N / 总数 段”。批量操作只改变当前页面勾选，用户点击保存后才生成新的证据修订和推荐。
- 真实浏览器验证清空后从 4/4 变为 0/4 并出现无证据提示；再次全选恢复到 4/4。验证过程未点击保存，因此没有写入个人数据修订。
