## 2. 跨页面问题

1. 整体依赖灰绿背景、绿色按钮、白色圆角卡片和轻阴影，可信但接近通用 SaaS，缺少“向阳、洒脱、聪明”的品牌识别。
2. 导航、环境说明、流程条、页面标题和内容面板都使用相近视觉强度，用户进入页面后缺少明确的第一焦点。
3. 中文标题、说明、数据与来源证据沿用同一套功能无衬线节奏，没有形成“职业刊 × 工作台 × 证据系统”的编辑层级。
4. 主要内容几乎都被装进同尺寸白卡，留白存在但没有气口、章节或边注关系。
5. 颜色只承担正向/警告状态，没有形成群青主路径、杏黄阳光、竹青确认和朱橙人味的品牌系统。
6. 现有响应式结构可继续复用；R2 不应以绝对定位或桌面拼贴破坏未来手机端重排能力。

## 3. `jobs` 页重点问题

1. 首屏大面积浅绿渐变只表达“安全”，没有职业探索的行动感；主按钮与标题之间缺少第二条“直接浏览”的轻路径。
2. 四步流程是通用进度条，未体现当前是“看清岗位条件”的章节，也没有中文编辑感。
3. 筛选区只有字段堆叠，没有“常看方向”、已应用条件数或明确的筛选任务标题。
4. 结果标题展示“100 个岗位”，但接口实际返回 `nextCursor`；页面没有加载下一页入口，用户无法看到目录剩余岗位，也无法理解 100 是首批载入数。
5. 配额缺口以一整段系统文本呈现，重要但难扫描；应保留原始事实，同时改为可读的证据提示。
6. 两列同构岗位卡导致页面非常长，企业、标题、条件、薪资、来源和核验时间缺少横向比较关系。
7. “未说明”颜色过轻，容易被读成普通次要信息；它应保持中性，但需要更明确的视觉和文案边界。
8. 来源与核验时间被放在卡片底部小字中，证据原则存在但不够可见。

## 4. R2 首个切片验收

- 使用已审核的“向阳生长”设计 token，不改 API 契约、匹配语义或来源状态。
- `jobs` 首屏在 1280 下形成清楚的一个视觉高潮，仍能快速进入筛选和结果。
- 岗位结果改为可比较的编辑式列表单元，不使用匹配分、排名或自动劝退。
- 支持读取 `nextCursor` 并由用户明确加载后续岗位；不静默把首批 100 条写成完整目录。
- 来源、核验时间、未知条件和公司配额缺口继续可见。
- 900、720、520 与 320 宽度保持语义顺序、无整页横向溢出、关键操作不依赖悬停。
- 完成后保存同视口 `after-jobs-1280.png`，并运行 Web 测试、类型检查、构建、lint 与浏览器检查。

320px 只验收结构安全、内容保留和核心短路径，不把本轮桌面优先 R2 伪称为手机端专属设计。窄屏下顶部导航允许自身横向滚动，但页面主体没有被迫使用桌面列宽，首屏标题、说明和两个核心动作保持完整。
