# 合规与公开上线门

## 1. 目的与边界

本文件把公开招聘信息、用户简历、AI 推荐和中国境内网站运营涉及的主要合规问题变成阶段检查项。它不是法律意见，也不能替代对具体业务形态、主体、数据流和上线地区的专业复核。

在问题发现和小规模人工实验阶段，可以只处理最小、脱敏、已授权的数据；在公开或经营性上线前，以下项目必须有明确结论和责任人。

## 2. 来源与招聘信息

每个来源必须保留：

- 企业或高校主体、官方域名和来源类型。
- 页面是否公开，是否需要登录、验证码或特殊权限。
- robots、使用条款、版权声明和公开接口说明的检查日期。
- 采集目的、频率、字段范围、原始链接和退出方式。
- 是否只展示必要事实并引导用户回到官方页面。
- 主体提出停止、纠错或删除要求时的处理流程。

禁止绕过访问控制、模拟受限账号、规避验证码或把第三方综合招聘平台的数据作为来源。页面公开可访问不自动等于可以任意批量复制、长期保存或商业再发布；存在不确定性时应暂停该来源并复核。

## 3. 个人信息与简历

上线前至少确认：

- 处理目的、字段、保存期限和接收方是否最小必要。
- 用户在提供简历前能够理解用途、风险、保存和删除方式。
- 联系方式、照片、证件、精确住址等非必要字段默认不进入匹配。
- 用户能够查看、更正、撤回授权并删除原文、结构化证据、向量、缓存和备份中的到期副本。
- 生产简历不进入日志、分析平台、错误报告、测试夹具或开发环境。
- 未成年人、敏感个人信息和委托处理等特殊场景有单独判断。
- 发生泄露、误用或越权时有通知、止损和记录流程。

首个工程切片只接受用户主动粘贴的去标识化文本；PDF/DOCX 上传要在隔离解析、安全测试和删除演练通过后单独灰度。

## 4. AI 与推荐

选择模型或外部 AI 服务前必须通过 ADR 记录：

- 发送哪些字段和原文片段，能否进一步去标识化。
- 服务商是否保存输入、用于训练或向分包方提供。
- 数据处理和存储地区，是否可能发生个人信息跨境。
- 保留期限、删除能力、审计条款、故障和退出方案。
- 用户是否可以关闭个性化推荐并继续使用基础岗位搜索。

产品界面应说明推荐依据、主要限制和未知项；不得把匹配分数表述为录用概率。确定性资格条件不能由模型覆盖，用户应能纠正简历证据和反馈错误推荐。

## 5. 网站与经营性上线

公开上线前需要结合实际主体和服务方式确认：

- 域名、ICP备案及可能适用的互联网信息服务要求。
- 网络招聘服务、人力资源服务或其他行政许可/备案是否适用。
- 隐私政策、用户协议、来源说明、AI 使用说明和投诉申诉入口。
- 算法推荐相关的透明、选择权、标签管理、备案或安全评估要求是否适用。
- 数据本地化、个人信息出境和第三方处理者合同要求。
- 收费、广告、付费排序和商业合作的明确标识及消费者权益边界。

结论应引用届时有效的正式规则或专业意见，不能只引用本设计文档。

## 6. 公开上线 Gate

以下项目全部有证据后，才进入公开 Beta：

- 来源准入、退出和纠错流程已实际演练。
- 隐私告知、同意/授权、访问、更正、撤回和删除链路已验证。
- 数据流图列明所有存储、模型供应商、分析工具、备份和跨境路径。
- 安全威胁模型中的上线门全部通过，无未接受的高风险问题。
- 适用的备案、许可和算法/AI 要求已有书面结论。
- 有备份恢复、事故响应、投诉处理、来源停用和版本回滚能力。
- 小流量灰度期间能够监控岗位错误、推荐错误、隐私投诉和来源投诉。

任一项仍未知时，可以继续受控原型或邀请制私测，但不能把产品描述为已具备公开运营条件。
