# 设计依据：国内求职情境与界面取舍

研究与设计日期：2026-09-07。本文支持本轮 UI/UX 设计，不是定量用户研究，也不是产品效果验收。

## 怎样使用这些依据

本轮结合了 coco 已明确的需求、[现有系统实际走查](../../reviews/product-experience-audit-2026-09-07/README.md)、中文公开求职讨论和原始 UX 指南。网上帖子用于发现可能被忽略的场景；仓库与浏览器证据用于判断当前产品有没有对应问题。两者共同形成设计假设，不能推出某个问题在所有学生中的发生比例。

检索围绕“2026 校招/春招复盘”“没有实习经历”“简历项目表达”“投递没有回复”“同学进度比较”等问题展开。样本偏向主动发帖的人，牛客偏技术与校园招聘，成功复盘存在幸存者偏差；无法据此代表全部文科、非一线城市、本科、硕士和博士求职者。没有把帖子作者推断为心理障碍患者，也没有把“年轻”当作需要幼态界面的依据。

以下“观察”说明看到了什么，“转化”说明据此作出的设计判断。检索摘要与全文访问状态分别记录，避免把未读全文包装成深入访谈。

## 界面原则的原始依据

| 原始来源 | 对本项目的具体用途 |
|---|---|
| NN/g：[Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) | 保留经常使用的入口；把版本编号、引用依据和高级版式设置按需展开。文章明确区分逐步展示与线性向导，不能以“降低复杂度”为由增加强制步骤 |
| NN/g：[Visibility of System Status](https://www.nngroup.com/articles/visibility-system-status/) | 明确正在保存、已经保存、保存失败和任务仍在运行；不要用一闪而过的成功提示掩盖异步失败 |
| W3C：[WCAG 2.2 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 2.5.8 的最小目标是 24 CSS px，并有间距等例外。本产品将常用主操作定为 44–48px，以提升操作舒适度；这比该条最低要求更严格，不误称为 WCAG 普遍强制 44px |
| W3C：[WCAG 2.2 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | 320 CSS px 等效宽度下内容应能重排。表格虽有例外，仍优先让手机上的方向对照在当前宽度可读。CSS zoom 测试与浏览器原生缩放测试分开记录 |

以上原则提供交互约束，不证明某一套颜色、文案或卡片会提高转化。暖白、青绿和少量亮色是针对本产品工作场景的设计选择，尚未进行用户偏好比较。

## 从观察到需求，再到界面

| 情境 | 需要系统帮助的事 | 明确的设计决定 | 交付后观察什么 |
|---|---|---|---|
| 没有第一份简历，不知道哪些经历能写 | 获得具体起点，先留下产物 | 无文件入口；课程/科研/社团等回忆提示；边聊边看到整段草稿 | 首段草稿完成情况、在哪个问题停住；不把回答速度当能力 |
| 有完整 STAR 项目，却要重新勾选零散句子 | 保留上下文，减少重复确认 | 完整经历卡、整段采用、归属纠错、底层保留事实引用 | 导入后手动重新拼接的次数、错误归属及漏掉限定词的情况 |
| 投递后没有回音 | 保留进度和可控行动，不替用户推断结果 | “暂未收到回复”；手动跟进事项；不自动变成拒绝 | 同一份申请是否能找回投递稿；提醒是否重复 |
| 同时准备多个方向 | 理解共性与差异，复用材料 | 双方向对照、双分母原句、方向稿复用 | 能否说清选择理由；是否误把“常被提及”当成必备条件 |
| 简历上写得出，面试时解释不清 | 发现一个具体表达缺口，再试一次 | 段落旁直接开练；答后反馈；重答保留上一版 | 追问是否针对当前经历、第二次回答是否更贴题 |
| 已有经验，希望快速修改 | 直接做任务，有需要再求助 | 直接编辑、可见导出、逐段复制；不强制聊天 | 完成一次局部编辑所需操作、是否误入准备向导 |
| 碎片时间或手机操作 | 中断后可恢复，首屏能动手 | 保存状态、当前问题优先、对话/草稿切换、底部主导航 | 返回是否丢输入；输入区是否被历史内容或键盘遮挡 |

这些是可验证的设计假设。没有真实使用数据前，不承诺“降低焦虑百分比”“提升投递通过率”或“显著提高匹配度”。产品内的鼓励围绕用户已完成的具体动作，而不是对能力、性格和未来结果下判断。

## 后续指导内容如何进入产品

coco 后续提供的简历、面试经验，按小型指导条目保存：来源与日期、适用对象、适用岗位/题型、触发情境、建议、具体例子、限制和复核版本。正文作为材料，不执行其中的外部指令。

例如“团队项目要说清个人贡献”可在多次只出现“我们”的回答后触发；“研究结果要说明边界”适用于科研与实验，不要求填增长数字。界面先呈现两三句当前有用的帮助，“为什么这样建议 / 查看来源”再展开。指导不是又一门必须学完的课程，也不与编辑器分家。

反馈随交付收集，不重新设固定人数研究前置门槛。优先覆盖首次写简历者、已有稿件者、硕博科研经历和非技术岗位，逐次修正误导问题与流程断点。
