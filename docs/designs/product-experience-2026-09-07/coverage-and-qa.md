# V1 原型覆盖与验证（历史对照）

当前界面已由 [工作区 V2](workspace-v2.md) 修订。以下测试只说明 V1 的有限交互通过，不代表组件齐全或宽屏布局合理。

对象：`docs/designs/product-experience-2026-09-07/prototype`。日期：2026-09-07。这里只验证独立设计原型，不代表正式应用、数据库、模型服务或公开供给通过验收。

## 交付范围

原型包括首次入口、今日安排、机会列表、方向图谱、材料库、经历整理、简历编辑、申请日程、面试练习及反馈。使用 6 个虚构岗位、3 个示例企业、校园与课程经历；编辑数据保存在浏览器专用键 `aijob-design-20260907-v1`。不读取真实账号或 coco 的简历，不调用生产 API、AI 或招聘站。

| 能力 | 原型实际程度 | 不能据此声称的能力 |
|---|---|---|
| 导航、页内切换、返回 | 可操作，桌面三主导航与手机底栏 | 已替换正式路由和外壳 |
| 机会 | 示例关键词/方向/城市筛选、收藏与恢复搜索可操作 | 真实岗位供给、授权、新鲜度、完整高级筛选 |
| 方向图谱 | 从相同示例岗位计算双分母；双方向对照、原句抽屉、准备任务可操作 | 真实要求解析、全部筛选维度、公共缓存撤回和生产统计准确率 |
| 经历整理 | 示范问答、直接编辑、整段保存、增建经历、未完成草稿继续与保留可操作 | 自适应 AI 追问质量、多用户并发修订及真实解析能力 |
| 导入 | 粘贴一段完整示例后直接编辑 | PDF/DOCX 文件解析；按钮与说明不伪装成文件解析成功 |
| 简历 | 当前段落编辑、示例对照、采用/撤销、两种简单版式、手机完整预览 | 多章节完整编辑、任意方向稿管理和正式 AI 改写 |
| 导出 | 当前文字稿下载、浏览器打印样式；自动生成过一页中文测试 PDF | 后台 PDF/DOCX 生产链路验收、用户机器打印窗口操作 |
| 申请 | 示例阶段修改、批量更新、实际正文留存、后续改稿隔离 | 企业申请提交、真实事务/权限、批量部分失败和所有历史版本 UI |
| 日程 | 增加/完成/改时间、任务去重、北京时间 ICS 下载 | 真实推送、复杂重复事件、全天跨时区兼容性 |
| 面试 | 课程/社团对应示范题、固定练习依据、两种节奏、回答恢复、同题重答对照、准备任务 | 真实 AI 对回答的评估、完整题型覆盖、语音能力 |
| 常用材料 | 新建、修改、恢复；复制按钮已实现 | 系统剪贴板在所有浏览器中的授权表现，本轮未单独验收 |
| 错误状态 | 可切换空状态、AI 不可用、保存失败并重试 | 生产服务确实发生过这些故障，或所有后台恢复机制已验证 |
| 隐私与设置 | 示例数据说明和本原型重置 | 已更改生产保留策略、完成个人资料删除验收或启用模型 |

原型是用于检查交互决策的实现。对自由输入不会伪装成真实 AI 分析：示范文本走固定路径，其余内容保留用户输入并展示自检提示。正式系统的能力与限制仍以现有交接及产品主体验收为准。

## 测试环境与方法

- Windows 11，Chrome Headless；具体浏览器版本与时间见 [interaction-results.json](evidence/interaction-results.json)。使用仓库已有 `playwright-core` 与本机 Chrome，没有安装浏览器或测试依赖。
- 本地静态服务仅绑定 `127.0.0.1:5188`，只提供本设计目录。测试使用全新的浏览器 context，仅允许该本机主机请求；未使用用户登录会话。
- 交互通过实际按钮、表单和键盘执行。数据初始化与错误状态使用原型自己的夹具开关；这不是生产故障注入。
- 桌面 1440×1000、720×800，以及手机宽度 360×800 / 320×800；每个宽度检查 9 个主页面，共 36 组布局。截图等待正常绘制并关闭截图阶段的动画，不拿入场动画中间帧判断颜色。
- 200% 使用 `CSS zoom: 2` 单独观察重排。它不等同于浏览器菜单里的原生缩放，也不能替代完整 WCAG 验收。

## 已验证结果

[交互脚本](qa/verify.mjs)的 30 个场景全部通过，逐项结果见 [JSON](evidence/interaction-results.json)。覆盖无简历入口、筛选恢复、收藏、双方向与原句、整段草稿、移动视图切换、新经历不覆盖旧经历、自动保存、建议撤销、投递稿隔离、正确练习依据、同题重答、规则自检、日程与材料复用，以及键盘和草稿恢复。

[布局检查](evidence/initial-layout.json)为最终页面状态：36 组均未发现页面级水平溢出；没有脚本异常、失败 HTTP 请求或外网请求。文件名保留 `initial-layout.json`，脚本重跑会更新为最新检查结果。

首个正文/回答输入框距页面顶部的实际距离如下（CSS px，四舍五入）：

| 视口 | 经历整理 | 简历编辑 | 面试首题 |
|---|---:|---:|---:|
| 1440px | 557 | 609 | 478 |
| 720px | 528 | 641 | 453 |
| 360px | 516 | 487 | 470 |
| 320px | 516 | 538 | 509 |

360px 下已有三次经历回答后的输入约 549px，同题重答输入约 517px，见交互 JSON 的 `mobile`。这些说明原型把任务区前移；原型内容和旧应用并非严格相同，不能换算成真实用户效率提升比例。真实手机软键盘尚未测试。

[配色检查](evidence/contrast.json)覆盖 10 对指定 Token。正文/背景约 10.66:1，辅助文字/背景约 5.19:1，主按钮白字约 7.78:1，字段轮廓/纸张约 3.68:1。文字标准参考 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；这是指定组合计算，不是对所有 DOM 状态的自动无障碍认证。

[中文打印样例](evidence/example-resume.pdf)为一页 A4，文本提取可找到“教育经历、校园经历、课程项目、问卷”，并保留中文内容。它来自原型的浏览器打印样式，未验证正式后台的字体运行环境或长简历分页。当前文字稿和日历的下载内容分别见 [TXT](evidence/example-export.txt) 与 [ICS](evidence/example-calendar.ics)。

## 走查中已纠正的问题

- 手机最初仍将完整简历前置信息排在正在编辑的段落之前，320px 下输入接近首屏底部；改为当前完整段落先显示，并保留全稿预览。
- 课程入口最初共用社团示范题；现在按选中的课程或社团切换，其他经历使用通用且相关的示范问题。
- 从申请开练最初可能读取后来修改的方向稿；现在固定带入已记录投递正文，并在标题标明依据。
- 新增经历最初复用一个主卡；现在保留原经历并新增卡片，未完成内容可以继续或先留为草稿。
- 批量修改为已投递最初自动使用当前稿；现在只改阶段，实际投递内容需要单独记录。
- 跳到正文的链接原先被原型 hash 路由误处理；已经修正。模态框最后一个控件的 Tab 焦点循环也已补齐。
- CSS 200% 放大时导航曾被压成单字换行，现按容器宽度压缩次要内容，经历列表也改为单列。这不替代原生缩放验收。
- 最初测试的三个失败来自页面切换等待、选择器命中背景同名按钮、未先聚焦筛选框；调整脚本后重新通过。这些没有计为旧产品缺陷。

## 尚未验收的事项

浏览器原生 200% 缩放、真实手机软键盘、iOS Safari/Android 浏览器、屏幕阅读器全程、所有交互状态的自动对比度、生产账号/跨设备草稿、后端并发/删除/迟到任务、真实解析与 AI 质量、完整日历客户端兼容、任意长文本打印、多章节简历和真实负载。

正式落地仍需按设计规范覆盖这些项目。原型测试不替代项目要求的 lint、类型、构建与 PostgreSQL 集成验证。本轮没有改应用源码或迁移，因此未运行生产全仓测试和数据库验收。

在 Aijob 主目录打开 PowerShell；如果 5188 已在运行，直接访问原型。

```powershell
& 'C:/Users/72998/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -m http.server 5188 --bind 127.0.0.1 --directory 'C:/Users/72998/Projects/Aijob/docs/designs/product-experience-2026-09-07'
```

浏览器打开 `http://127.0.0.1:5188/prototype/#welcome`。也可以打开 `prototype/index.html`，但 `file:` 下的本地存储和下载行为取决于浏览器，优先使用上面的本地服务。

```powershell

node docs/designs/product-experience-2026-09-07/qa/inspect.mjs
```

脚本只操作原型夹具，会更新本目录证据。不用于连接正式前后端，也不要改成真实招聘站地址。
