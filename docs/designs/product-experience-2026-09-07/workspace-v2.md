本轮只修改独立设计目录及设计交接。`apps/web`、平台代码、数据库、真实账号和现有开发成果保持原状态。这些界面尚未替换正式应用；虚构样例和固定示范追问不能计为真实 AI 能力。

## 1. 为什么截图会变成那样

这不是已证实的 CSS 丢失或浏览器渲染故障。V1 的 `.page` 采用 `max-width:1320px; margin:auto; padding:38px 48px 64px`。在更宽的窗口中，主要内容仍只有约 1224px：

| 浏览器 CSS 视口宽度 | V1 页面盒宽度 | 主内容左右各剩余空间 |
|---|---:|---:|
| 1920px | 1320px | 348px |
| 2229px | 1320px | 502.5px |
| 2560px | 1320px | 668px |

以上来自实际浏览器复现，见 [layout.json](evidence-v2/layout.json) 的 `baseline`。2229px 是用于复现宽屏的 CSS 视口；不能仅凭截图的物理像素认定 coco 当时的 CSS 视口或缩放比例。

视觉空旷还来自三个设计决定：把日常工作区做成了居中展示页；用大引导卡占据主视野；只挑少数示范路径，没有将既有组件逐项映射回来。V1 的窄屏测试验证了横向溢出和部分操作，却没有验证宽屏密度与功能可发现性。30 个交互场景通过不等于信息架构合理。

自适应应当在设计阶段确定。浏览器窗口、缩放和操作系统缩放都会影响可用 CSS 空间，组件应按实际可用空间重排。不能把一张 1440px 画布等比缩小作为手机设计，也不能让一整段正文无限拉长来填满宽屏。

## 3. 导航与页面职责

```text
今日工作台
找机会：岗位发现 / 方向图谱 / 我的收藏 / 保存搜索
做准备：我的经历 / 我的简历 / 常用材料
跟进申请：投递管理 / 准备与日程 / 面试练习
底部：求职指南 / 资料与设置
```

分组默认展开，不要求用户先理解内部“Case”“证据 ID”或运行版本。顶部承担当前位置、工作区搜索、保存状态和近期安排，不重复放一套全局大导航。个人资料、删除和 AI 使用说明可找到，但不在普通编辑中反复要求确认。

今日工作台提供四个直接动作：写经历、导入简历、为岗位准备、练面试；然后展示继续上次、近期安排、申请进展、最近材料和关注方向。计数来自当前示例对象，没有匹配度、求职总分或虚构的成功率。

## 4. 组件去向，不能在简化时丢掉

下面按实际仓库组件和现有能力核对。**“映射”说明正式改版的位置；“可操作”只指 V2 本地原型。**

| 既有能力 / 组件 | V2 位置 | 本原型覆盖与正式整合要求 |
|---|---|---|
| `GlobalSidebar`、`UtilityBar` | 左侧分组；顶部当前位置与搜索；手机完整导航 | 可操作；搜索页面、示例岗位和一段示例材料。真实跨对象搜索尚需接口整合 |
| 岗位列表、筛选、来源信息 | 岗位发现；岗位详情抽屉 | 示例关键词、城市、方向与收藏可用；高级筛选仍是说明态，真实来源及撤回状态沿用现有契约 |
| 当前方向图谱、原句分页、双分母 | 独立方向图谱；统计项打开原句再加准备事项 | 双方向示例与原句可用；全筛选、公开缓存和解析覆盖不是本原型验收内容 |
| 收藏、保存搜索 | 左侧固定入口的独立页面 | 可操作、刷新恢复；不只藏在详情弹窗或小按钮里 |
| 完整经历、解析确认 | 我的经历；导入后直接进入内容 | 整段保存、新建和继续追问可操作；PDF/DOCX 解析、归属纠正、合并项目需接原服务 |
| `ResumeDocumentEditor` 章节结构和正文 | 简历工作室：模块目录、正文画布、文档工具栏 | 基本信息 + 教育、校园经历、项目、工具四模块可编辑；排序/隐藏/恢复、预览可用。原型只维护一份方向稿，不冒充多方向稿管理 |
| `ResumeBlockInspector`、证据引用 | 当前经历的材料来源 / 岗位要求对照 | 本原型演示整段关联；正式实现需保留原句定位和来源引用，内部检索仍可细粒度，但不让用户逐句搭简历 |
| `ResumeReviewPanel`、`ResumeSuggestionInspector` | AI 优化的改写对照；桌面辅助栏 | 示例改写、采用、撤销；真实建议绑定修订、逐条决定和冲突处理必须复用原服务 |
| 正文与布局修订、导出 | 工具栏：版式 / 版本 / 预览；页标题旁：导出 | 两种简易版式、最近内容切换、TXT/打印 PDF 可用；完整历史和后台 PDF/DOCX 不在原型中假造 |
| `CaseHeader`、`CaseTabs`、要求和三轴核对 | 投递管理 → 这次申请的六个页签 | 18 类视图中包含完整申请页，能查看要求、关联经历、编辑简历、投递、练习和复盘；资格与偏好仍应独立展示，不能浓缩为匹配百分比 |
| `CaseVersionControl` 固定岗位版本与升级差异 | 岗位要求 → 来源和版本 | 当前原型说明位置，未模拟真实版本差异及升级提交；正式组件必须保留，不作为待删能力 |
| `ContextInspector`、`ResizablePane` | 列表侧览；打开完整申请继续处理 | 岗位抽屉与完整申请可操作。现有申请侧览与可拖动宽度列入正式整合，未声称在原型全部复现 |
| `BulkCaseProgress`、实际投递稿 | 投递管理与申请“投递记录” | 批量阶段操作沿用样例；实际正文单独保存，后续改稿不覆盖；历史与结果枚举要回接真实契约 |
| `PlannerPanel`、`PlannerEditor` | 独立准备与日程；首页近期摘要 | 新建、完成、恢复、修改/延期及北京时间 ICS 可用；日程不再只有申请侧边栏这一个入口 |
| 面试会话和复盘 | 面试练习入口；具体申请下的面试与复盘 | 固定依据、回答、重练、自检与复盘笔记可用；真实 AI 追问与反馈仍未连接 |
| 常用材料、个人数据设置 | 常用材料、资料与设置独立入口 | 常用材料可新建编辑；真实登录、邮箱与个人数据删除没有用假成功替代 |
| 路由恢复、草稿保护、错误状态 | 保存状态、继续草稿、错误旁恢复按钮 | 示例保存失败、离开继续、尺寸切换保留输入可用；真实并发冲突、多 owner 隔离属于正式应用回归 |

这张表是正式前端整合时的防遗漏清单，不等于现有每个组件已经迁移。尤其不能因新截图没出现版本比较、全部筛选或权限反馈，就把原有能力删掉。

## 5. 自适应规则

所有宽度均为 CSS 像素，以实际可用空间决定布局：

| 空间 | 导航 | 内容区与编辑方式 |
|---|---|---|
| ≥1800 | 232px 分组侧栏，可手动收起 | 工作台随剩余宽度扩展；简历显示目录、纸张和辅助栏；单张简历纸最大 820px，正文保持行长 |
| 1200–1799 | 完整侧栏 | 工作台两栏；≤1500 时简历目录移入常驻“模块管理”工具，不挤窄画布；操作入口保留 |
| 1000–1199 | 76px 窄侧栏 + 顶部完整导航按钮 | 当前内容优先，简历画布与辅助工具并排；可以通过完整导航查看文字入口 |
| 768–999 | 窄侧栏 + 完整导航 | 写作采用“对话 / 草稿”切换，简历辅助栏收起但工具栏保留同一组操作；申请日程使用独立页面 |
| 320–767 | 四项底栏 + 顶部完整导航；编辑时隐藏底栏 | 单列、当前输入优先；简历通过模块选择器编辑基本信息及全部章节，再打开完整预览。完整导航含收藏、日程、面试等子功能 |
| 200% 浏览器缩放 | 由缩放后的可用 CSS 宽度决定 | 使用同一套规则；可以滚动，操作和内容不横向越界，不靠 CSS 等比变换伪装 |

1280×720 下 11 个常用目的地完整可见。更短的 1280×520 窗口允许侧栏内容区域滚动，底部设置入口保留。长正文在编辑区增长，缩放或切换视图不清空状态。宽屏主要增加并行查看的信息，不增加无关模块、拉宽每行文字或把每张卡放大。

全局侧栏、页签和移动导航都是真链接或原生按钮。弹窗支持键盘焦点约束、Escape、关闭后回到触发位置；减少动画偏好得到尊重。

## 6. 已执行的验证

环境：Windows，Chrome **151.0.7922.174**，仓库已有 `playwright-core`；仅本机静态样例。没有为了原型运行平台数据库测试或宣称整个项目构建通过。

- [布局记录](evidence-v2/layout.json)：18 类视图 × 9 档宽度，共 162 次检查；320 / 360 / 768 / 1024 / 1280 / 1440 / 1920 / 2229 / 2560。首次检查已通过；短窗可见性与手机模块编辑经视觉检查后再次修订并复核。
- [交互记录](evidence-v2/interaction.json)：18/18 通过，覆盖导航可发现性、搜索、完整申请、手机整段编辑、全部模块、跨尺寸保留、投递留存、练习依据、日程、材料与键盘焦点。
- [原生 200% 缩放](evidence-v2/native-zoom.json)：在新建的临时 Chrome 配置中设置浏览器缩放，不改变用户 Chrome。1920×1080 外窗中实际内容为 949×491 CSS 像素，`devicePixelRatio=2`、CSS `zoom=1`；六个核心页面无横向溢出。实现参考 [Chromium 的缩放偏好代码](https://chromium.googlesource.com/chromium/src/+/lkgr/chrome/browser/ui/zoom/chrome_zoom_level_prefs.cc)。
- [PDF 检查](evidence-v2/pdf-validation.json)：测试中文正文导出 1 页，姓名、四模块及修改后的内容可提取；[测试 PDF](evidence-v2/resume-export.pdf) 和 [提取文本](evidence-v2/pdf-text.txt) 保留。
- CUA 实际浏览器走查了 1280×720 首页；检查了 1920 宽屏、360 手机简历和宽屏编辑器截图。测试中未发现 JS 运行错误或外部网络请求。

复现命令，在 Aijob 根目录运行：

```powershell

node docs/designs/product-experience-2026-09-07/qa/verify-v2.mjs

```

`zoom-v2.mjs` 输出本轮独占的临时浏览器目录；验证结束后清理操作被自动审批策略拒绝，工具只返回 blocked by policy，未提供具体原因，因此保留记录中的临时目录。没有修改用户浏览器配置。浏览器窄视口验证不是实际 iOS Safari、Android 软键盘或所有系统缩放组合的验收，正式移植仍须补这些设备走查。

## 7. 正式整合时的边界与下一步

下一项前端工作应先迁移导航和布局外壳，再将上表中的现有组件逐个接入新位置，保持真实状态、路由和修订契约。先完成工作区、材料编辑、申请详情这条连续路径；不能直接把示例脚本变成生产业务层，也不能趁换壳重写后端。

V1 保留在 `prototype/` 供对照，V2 位于 `prototype-v2/`，使用独立 `aijob-design-20260907-v2` 存储键。原型输入不会覆盖 V1 或正式应用的数据。OS-7、事实纠偏、公司无上限及业务恢复维持已完成状态；真实供给、冷查询/混合性能和运行配置的未就绪项继续按现有交接处理。
