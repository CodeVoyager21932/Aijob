## 结论

现在最该做的是统一有效规则和当前入口，其次才是释放空间。项目不是单纯“旧文件太多”：旧文档仍发布过期指令，多份目录共享 Git 元数据但内容不同，历史验收和真实业务资料又混在相同位置。直接大扫除容易丢改动，也无法解决以后继续积累冲突的问题。

处理顺序为：**文档归一 → 明确可生成的中间文件 → 保存差异后归档旧副本与历史测试环境**。原只读审计仅新增报告、分项清单和忽略目录内的盘点元数据；后续第一批仅修改文档。两个阶段均没有删文件、改产品代码、重置 Git、迁移数据、启动 Docker 容器或重跑产品验收。安装包专属同步、构建、测试及业务资料迁入继续暂停。

## 优先解决的发现

### 1. 当前规则分散，旧规范会误导后续实现

- `private-alpha-readiness-gates.md` 仍有原件最长保留 24 小时、去标识化/白名单等旧要求，与 ADR-0038 之后的原件保留和用户自配 AI 冲突。
- README、路线图、交接和 AGENTS 的不同段落同时留下 022、065、078 等时代的“当前”表述。部分旧计划仍将已关闭的业务恢复列为“下一唯一目标”。
- ADR 索引停在 0036，当前已批准的 0037–0043 没被索引完整覆盖。
- 交接“业务服务仍运行”是当时快照：本次实际看到 8 个容器全部停止，常用服务端口没有监听。历史 PID 和一次健康检查不能成为永久运行事实。

处理：用现有 README/路线图/current 交接/ADR 各司其职；删除或明确替代冲突的当前指令，将阶段流水记录放回有日期的历史证据。先修语义和入口，第一批不大规模移动文件，以免破坏链接。逐项出处见 [文档审计](docs-review.md)。

### 2. 多份目录不等于多份可靠备份

桌面 `C:/Users/72998/Desktop/job` 与 E 盘 `f057` 共用同一 worktree index/HEAD，却分别有 37 项和 138 项工作区差异。旧 Documents 仓是它们的 Git 公共根。删除旧根目录会破坏多个工作树关系。

C 盘 `f057` 是到 E 盘的 junction；C/E `975c`、`b52a` 是实体副本。已比对的非敏感源码相同，不代表 `.data`、配置和密钥也相同。`11dc` 另有独有归档提交 `81b7fa9`，当前主仓没有引用保全它。

主仓 HEAD 为 `a4ff514`，现有产品大量修改尚未提交。审计前默认 Git 状态为 446 项，展开未跟踪目录后为 4,786 个文件项；不能以旧 HEAD 重建主工作区，也不能以“落后若干提交”推断旧目录可删除。详见 [副本关系与差异](project-copies.md)。

### 3. 大量检查留下了材料，但并不都属于日常回归

370 个测试文件中，236 个位于默认递归 package test 的执行入口，134 个来自 vendor 且不由默认 test 自动运行。65 个测试文件依赖 PG 环境配置。没有数据库的绿色单测结果不能代替迁移和真实权限验证。

40×3 的 120 个导出组合、1320 项短稿字段回导计数、界面旅程和真实导入质量是不同证据。后续定向样本仍引用部分旧矩阵的 DOCX/PDF，因此不能仅保留截图后整目录删除。也不能看到 49 个脚本没有字面文件名引用，就全部判为无用。

RR5、RR6/Forme 与旧 Studio 的部分代码仍承担正文兼容、导出或测试职责；“旧”不是删除依据。现有 `dist` 还与测试/包导出顺序有关，先解决干净环境构建顺序疑点，再考虑清理。详见 [测试与代码审计](tests-code-review.md)。

### 4. 可整理空间很多，但业务数据不占主要部分

主目录约 12.857 GB，其中 `.data` 约 10.778 GB。安装包中间产物是主要大头；四组外置项目备份合计仅约 0.613 GB，先保留更合理。

Docker 有 3 个历史测试卷，合计约 7.187 GB；另有当前与旧业务卷，分别约 462.4 MB、409.4 MB。Docker 镜像、构建缓存有共享层，不能将其“可回收”数字相加，也不能全局清理卷。已安装候选、最后安装器和桌面代码按用户决定保留。详见 [运行与存储清单](runtime-storage.md)。

|---|---|---|
| 越来越多文档都写“当前/下一步” | 状态只保留一个权威入口，决定保留替代关系 | 改旧规则时同步索引和适用边界，不只在顶部再追加一段 |
| 测试矩阵很大，用户导入和排版仍反复出问题 | 检查应回答具体故障，不用通过计数替代使用效果 | 固定代表材料+两条核心旅程；同代码不反复扩大验收 |
| 测试角色与真实运行权限有差异 | 用真实角色验证关键数据库契约 | 迁移/权限改动只补受影响 PG 场景，而非再加一整套同义测试 |
| 生成接口可用不等于支持联网搜索 | 生成、搜索和已接来源刷新是不同能力 | 允许连接选择；按实际搜索工具证据提示能力，不逼所有用户配两种 Key |
| 配置后的抓取仍需要人工接入新站 | 自动刷新价值与新来源接入成本需分别呈现 | 保留可靠默认来源与运行状态，不将模型产出的 URL 当已收录岗位 |
| 安装交付提前抢占产品精力 | 产品可用性和发行形态是两件事 | 暂停桌面专属同步，先解决网页上的核心连续使用 |
| 工作树搬迁产生多个实体目录共用 index | 目录复制不等于 Git 隔离或完整备份 | 后续只维护一个开发主目录；归档记录 common dir、独有改动、密钥与数据位置 |
| `.data` 同时放业务证据、备份和临时产物 | 文件生命周期不能只由父目录决定 | 只对明确的临时/可生成目录制定清理规则，不全删 `.data` |
