# 从 0 到 1 的稳定产品工程流程

> 本文定义项目长期使用的阶段顺序、证据类型和变更规则，不记录当前进度、样本数量或下一决策日期。所有动态状态只在 [MVP 路线与当前决策面板](06-mvp-roadmap.md) 更新。

## 1. 流程目的

这套流程用于按风险顺序回答四类问题：

| 证据线 | 要回答的问题 |
|---|---|
| 用户证据 | 问题是否真实、频繁且会影响行动 |
| 产品证据 | 方案是否改善高质量投递决定 |
| 数据证据 | 官方岗位能否合规、准确、持续地维护 |
| 工程证据 | 产品能否安全、可重复、可删除、可恢复地运行 |

任何一条证据线长期缺失，都不能用更多功能、岗位数量、AI 调用或文档数量补偿。

## 2. 稳定阶段

~~~mermaid
flowchart LR
    A["Phase 0 问题发现与校准"] --> B["Phase 1 人工礼宾验证"]
    B --> C["Phase 2 数据切片"]
    B --> D["Phase 3 MVP-0 纵向切片"]
    C --> E["Phase 4 Private Alpha"]
    D --> E
    E --> F["Phase 5 Beta 与扩展"]
    F --> G["公开运营准备"]
~~~

Phase 2 与 Phase 3 可以在价值 Gate 通过后并行，但 Private Alpha 必须等待数据和产品两条线同时通过。

## 3. 各阶段的固定职责

| 阶段 | 核心问题 | 必要产物 | 退出原则 |
|---|---|---|---|
| Phase 0 问题发现与校准 | 首轮用户的近期行为、替代方案和实验任务是否可观察 | 招募条件、行为记录、校准后的实验协议、假设卡 | 能用真实任务而非未来意愿验证最高风险假设 |
| Phase 1 人工礼宾验证 | 分层信息是否改变高质量投递决定 | 人工岗位集、逐层实验记录、行为回访、反例与守护事件 | 价值阈值通过且没有硬性守护事件 |
| Phase 2 数据切片 | 少量官方来源能否持续、合规地采集和复查 | 来源准入、快照、字段字典、适配器夹具、质量与维护成本 | 代表来源稳定、可追溯、可独立失败 |
| Phase 3 MVP-0 纵向切片 | 已验证的人工流程能否变成最小可用产品 | Feature Spec、人工导入链路、规则/模板结果、金标集、测试与删除演练 | 端到端任务可完成且安全、隐私和质量门通过 |
| Phase 4 Private Alpha | 产品在真实求职周期中是否产生复用和稳定决定 | 匿名邀请运行记录、连续行为指标、故障与恢复记录 | 核心结果持续出现，主要失败模式可复现和修正 |
| Phase 5 Beta 与扩展 | 扩大来源、岗位和用户是否仍保持价值与质量 | 分批扩展记录、成本和质量趋势、发布与回滚证据 | 新增供给改善有效决定，守护指标不恶化 |
| 公开运营准备 | 是否具备面向非受邀用户运行的责任能力 | 合规复核、隐私说明、备份恢复、事件响应、申诉和下线流程 | 公开上线条件经过独立检查，不能用 Alpha 目标冒充 SLA |

阶段完成度由 Gate 和证据决定，不由代码量或页面数量决定。

## 4. 每个阶段的共同工作循环

1. 选择当前最高风险、可被证伪的 1-2 个假设。
2. 写清用户、任务、最便宜实验、成功/失败阈值和守护指标。
3. 收集最小必要证据，记录反例和失败原因。
4. 做出继续、修改、回退或停止决定。
5. 只有决定需要工程实现时，才创建 Feature Spec、技术计划和可独立验收的任务。
6. 实现后用真实任务、自动测试和运行证据共同验收。
7. 把结果回写决策面板；影响长期边界的决定另建 ADR。

流程不要求编码前写完所有未来文档，只要求当前决定有足够证据和可验证条件。

## 5. Gate 规则

### 5.1 结果 Gate

- 用户能完成定义清楚的高质量投递决定。
- 结果可追溯到来源、岗位条件和用户确认的事实或经历证据。
- 下游官方投递只作为单独强证据，不能用链接点击冒充。

### 5.2 守护 Gate

以下事件为硬阻断，不能被平均指标抵消：

- 明确硬条件冲突漏检。
- 基于错误或未知信息劝退用户。
- 虚构经历、成果或岗位条件。
- 未经用户确认的事实参与确定性结论。
- 用户数据无法删除、安全事件或隐私事件。
- 来源越过登录、验证码、访问控制或明确禁止的访问边界。

### 5.3 AI Gate

- AI 默认关闭，规则和模板先完成核心链路。
- 只对“同一事实输入下的解释增量”进行实验，不允许 AI 改写资格结果或用户事实。
- AI 必须同时证明理解正确率或决策效率增量，且不引入新的事实错误。
- AI 与模板效果相同、不可稳定复现或不可删除时，继续使用模板。

### 5.4 扩展 Gate

只有新增来源、岗位方向或用户人群能够改善有效决定，且不拉低数据质量、安全、隐私或维护成本边界时，才继续扩展。

## 6. 工程交付规则

### 6.1 纵向切片

每个切片必须让一条用户任务端到端可运行，优先顺序是：

1. 人工岗位可浏览并查看来源。
2. 轻量约束可确认。
3. 简历文本经过隐私检查，用户可确认证据并删除。
4. 一个岗位可分别完成资格、证据和偏好判断。
5. 用户可记录决定并前往官方页面。
6. 一个来源可采集、复查和独立失败。
7. 三个代表来源可与 MVP-0 汇合进入 Private Alpha。

不要先横向建设完整搜索、管理端、消息队列或 AI 平台。

### 6.2 Ready

工作项进入实现前必须具备：

- 明确的用户任务和对应假设。
- 范围内、范围外和可验证验收条件。
- 数据、安全、隐私、失败和删除影响。
- 足够小的变更边界与回滚方式。

### 6.3 Done

完成至少意味着：

- 验收条件和相关自动测试通过。
- 错误、空状态和降级路径可操作。
- 日志与指标不泄露用户正文。
- 安全、隐私、删除和恢复检查通过。
- 目标环境中可重复运行，并留下验证证据。
- 决策面板和必要的契约文档已更新。

## 8. 回退与停止

出现以下任一情况时，回到最早缺失证据的阶段：

- 找不到会影响投递的重复性问题。
- 礼宾结果不改变判断或行动。
- 用户无法正确理解资格、证据、未知和偏好的区别。
- 官方来源维护成本超过可见用户价值。
- 产品频繁出现守护事件。
- 扩展只能依赖越权访问、不可追溯的自动结论或过度收集数据。

回退的目的不是否定项目，而是避免把未经验证的假设自动化和规模化。
