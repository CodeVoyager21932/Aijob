## 1. 目标与完成后的样子

减少三种负担：接手时需要阅读的内容、使用时需要选择的入口、修改时需要重复维护或验证的东西。

1. 正确的产品思路、工程决定和实际教训分别进入对应现行规范，同一要求只在一个位置完整维护。
2. 已关闭计划、旧交接、废弃方案退出当前工作树；必要原文通过固定 Git 提交或本地归档可定位，不继续全文出现在默认搜索中。
3. 网页开发版只有一条推荐启动路径、一个默认工作区和一个个人连接设置入口；历史兼容能力通过明确用途进入。
4. 简历必要回归输入独立保存，不再被几个输入文件绑住整套历史矩阵；重复输出和无独有价值的研究副本可以移除。
5. 日常检查按改动选取；当前使用的测试继续保障行为，已关闭阶段的验收步骤不再自动产生任务。
6. 源码按实际调用职责整理：移除已失去用途的分支和脚本，把仍有用的共用能力与旧流程区分开。旧稿、投递文件和已有配置继续可用。

本轮不以删除比例、磁盘释放量或测试数量作为成功判定，不承诺因此直接改善启动耗时或内存。性能改进需要单独的运行证据。
