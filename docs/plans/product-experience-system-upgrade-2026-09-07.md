# Aijob 本轮升级：需求对齐与执行计划（修正版）

> 历史已实施方案（U0–U6）：直接导入、完整经历、原件留存与个人 API 按 [ADR-0038](../decisions/0038-resume-workspace-and-direct-import.md) 保留；简历排版与机会准备由 ADR-0041–0043 继续演进。下文阶段顺序和“本轮”属于 2026-09-07 时点，不自动重启 U0–U6；当前任务读取 [路线图](../06-mvp-roadmap.md) 和 [当前交接](../handoffs/current.md)。

> 实施补充决定（2026-09-07）：coco 明确要求通用配置并由用户自带 API，平台不提供模型。U1/U3 增加账户独立的 API 设置、连接测试、用量限制、停用/删除和调用错误恢复。个人 AI 不回退到运营方模型；无需选择某一家供应商才能继续建设。连接协议和业务质量分别验收。

## 1. 重新核对后的需求基准

已逐条回读你指定起点至当前的原始发言，以及我对应的回复。这次改进的目标明确为：

**保留已经认可的工作区方向，把简历编辑、真实 AI 辅助、经历与材料复用、求职流程衔接做成熟；消除重复录入、无意义确认和割裂的操作。**

之前的方案有四类偏差需要纠正：

| 对话中的要求 | 正确理解 | 之前需要纠正的地方 |
|---|---|---|
| “少了好多组件” | 核心能力完整、常用操作容易找到 | 不能为了简洁删组件，也不能把每个小功能都升成独立页面 |
| “整个 UI、UX 已经很不错了” | V2 的整体视觉、侧栏与工作区方向得到认可 | 不代表简历编辑器等具体功能已经合格；也不需要再次重做全站视觉方向 |
| “问题不是固定的吗，AI 在哪里” | AI 必须理解实际内容、动态决定下一步并形成成果 | 不能用固定问卷、示例改写或 AI 按钮代替真实智能帮助 |
| “参考成熟简历产品” | 建设完整的文档编辑能力 | 不能继续停留在几个输入框和简单换色模板 |
| 质疑收藏、保存搜索和材料重复 | 需要讲清用途、安排合适入口、减少重复维护 | 不能直接推断用户要删功能，也不能默认原来的页面划分合理 |
| 反对导入脱敏及反复确认 | 导入后保留正常内容，直接编辑和使用 | 不能只修改隐私文案，继续保留脱敏、复核和初始化关卡 |
| 要求系统升级计划 | 按新需求调整现有系统，让功能真正衔接 | 不能为了保留旧规则，让用户继续迁就旧数据结构 |

刚才进一步明确的三项选择，作为本轮正式需求：

- **按任务合并入口**：收藏与常用筛选回到岗位页；经历和常用表达共用入口；简历独立。
- **首次自动收录经历**：新增或导入项目、实习等内容时自动建立关联，后续针对岗位改写只改当前简历。
- **保留上传原件**：原始 PDF/DOCX 保存到用户主动删除，可随时找回和下载。

## 2. 本轮具体改什么

### 2.1 保留 V2 工作区，完成正式应用整合

保留已经认可的视觉方向、桌面分组侧栏、顶部任务工具和移动端导航。页面布局围绕实际任务调整，重点改善编辑、对照、查找与返回操作。

需要补齐的能力包括：岗位侧览、完整申请详情、简历模块工具、版本与投递稿、日程、面试与复盘、材料调用、必要的设置与错误恢复。每项都要对应正式页面和真实服务。

响应式从实施开始同步完成：

- 宽屏允许并排查看材料、正文与辅助面板。
- 笔记本优先保证编辑空间，次要面板可以收起。
- 手机使用可操作的字段和模块编辑，完整纸张另行预览。
- 窗口缩窄、原生 200% 缩放和软键盘出现时，输入与关键动作保持可达。
- 返回岗位、切换材料或打开助手后，保留输入、筛选和位置。

整体氛围保持轻松、有活力；鼓励对应实际进展，不使用空泛好评、能力排名或焦虑式提示。

### 2.2 把简历编辑作为核心产品建设

提供三条平等入口：**从空白开始、导入已有简历、使用已有经历**。不要求先建立经历库、选择岗位或完成 AI 对话。

编辑器包含：

| 能力 | 本轮完成要求 |
|---|---|
| 内容结构 | 模块 → 多条记录 → 记录内要点；教育、实习、项目、科研等具有对应字段 |
| 模块管理 | 添加、自定义、改名、排序、隐藏和恢复 |
| 条目编辑 | 多所学校、多段实习、多个项目；组织、角色、日期、描述分别编辑 |
| 文字格式 | 加粗、列表、链接、清除格式、粘贴整理；不用空格完成对齐 |
| 模板 | 用当前内容预览和切换，正文及来源关系不丢失 |
| 排版 | 字体、字号、间距、页边距、分栏与分页控制 |
| 保存 | 自动保存、撤销重做、历史恢复、方向稿复制，冲突时保留输入 |
| 输出 | 实际页边界、可复制中文 PDF、DOCX 与打印；科研材料允许多页 |

默认实现五种版式：清晰单栏、经典单栏、紧凑技术、简洁双栏、科研多页。这是实施范围的默认值，不是你原先提出的模板数量要求；先完成一种可靠版式的完整链路，再补齐其他版式。

保留现有文档、复制、修订和导出服务，扩展其内容结构与交互。

### 2.3 导入直接可用，原件可找回

导入后的流程固定为：

**上传 → 解析 → 直接进入可编辑简历。**

姓名、电话、邮箱、教育和经历正常保留；解析错误在对应字段或条目中修改。

删除以下用户操作：

- 脱敏预览与隐私复核页。
- 逐句证据勾选。
- 确认资料后再次初始化简历。
- 使用 AI 前先把内容转换成“已确认事实”。
- 为恢复联系方式额外完成核对流程。

原文件与可编辑简历关联，提供下载原件、查看导入记录和删除原件。删除原件不自动删除已经整理好的简历；删除全部个人资料时一并处理。

账号隔离、文件校验和访问控制由系统承担，不增加求职步骤。

### 2.4 经历自动积累，材料可以就地复用

完整经历保留项目背景、角色、行动、产物和结果。简历可以用几条要点表达，但这些要点始终属于同一项目。

具体行为：

- 导入或新增经历时首次自动收录，关联当前简历条目。
- 连续编辑同一个新条目不产生多份重复经历；重复导入同一内容不重复建库。
- 收录完成后，针对岗位调整简历表达只修改当前稿。
- 用户需要更新经历原稿时，可在当前编辑位置完成，不必跳转后重新录入。
- 原经历更新后，可比较相关表达的变化，不自动覆盖所有方向稿。
- 自我介绍、项目长短版和邮件可以组合多段经历，并保存为常用表达。
- 简历、岗位准备和面试页面都能就地调用材料。

用户面对“经历、简历、表达”，不需要管理证据 ID、初始化状态和引用版本。内部依据用于帮助系统理解和保持一致。

### 2.5 实现真实 AI，覆盖五个实际作用点

保持一个求职助手，以整理经历、优化简历、模拟面试三个主要任务呈现；岗位解读和表达生成作为就地辅助。

| 作用点 | AI 需要真正承担的工作 | 用户得到的成果 |
|---|---|---|
| 经历整理 | 理解完整描述和最新回答，判断值得追问什么、什么时候可以成稿 | 可编辑的完整经历与简历表达 |
| 简历优化 | 审阅整份材料的选材、顺序、贡献和表达；可结合方向或具体岗位 | 修改对照、理由及可采用的稿件 |
| 模拟面试 | 根据所选材料和回答继续追问，识别含糊、遗漏或前后矛盾 | 具体反馈、同题重答和准备建议 |
| 岗位解读 | 依据岗位原句解释任务、要求及准备方向；有个人材料时进行联系 | 对工作内容和准备重点的理解 |
| 常用表达 | 根据用途、长度和所选材料组织自我介绍、项目介绍、邮件 | 可复制、修改和反复使用的表达 |

共同规则：

- 不按回答次数机械推进固定题目。
- 不强迫所有经历套 STAR，不强迫补商业增长数字。
- 已经讲清的信息不重复问；不知道、未负责或尚无结果都是正常情况。
- 用户可以直接编辑、跳过、先形成一版或结束对话。
- AI 能处理无岗位的通用简历，不创建虚假 Case 来绕过旧限制。
- 修改结果可以整组或局部采用，并可撤销；不增加一套“事实审批”。
- 不编造用户没有提供的经历、数字或角色。
- 策略与 Skill 用于指导判断，不作为固定问卷，也不变成一排重复角色。
- 对话之外必须留下可继续使用的成果。

AI 不可用时可以继续手工编辑和使用固定提示，但明确区分固定辅助与真实模型结果。

### 2.6 收拢导航，保持功能可发现

默认导航调整为：

```text
今日工作台
找机会
  岗位发现：全部岗位｜已收藏；筛选区提供常用筛选
  方向图谱
做准备
  我的简历
  经历与材料：我的经历｜常用表达
跟进申请
  投递管理
  准备与日程
  面试练习
辅助入口：求职指南、资料与设置
```

收藏保存具体岗位；常用筛选保存关键词、筛选与排序，应用时重新查询当前目录。首版不承诺尚未实现的新增岗位通知。

收藏与申请进度分别表达：随手收藏不会自动增加今日待办，也不被当作已经开始准备。主动开始准备或记录申请后，衔接同一岗位记录。取消收藏不删除已有申请历史。

保留旧链接的兼容入口，功能合并后仍能直达对应视图。

### 2.7 让面试、指导与投递连续起来

面试可以从经历、简历或申请开始，不要求已经投递。提供“边练边改”和“完整模拟”两种节奏，支持暂停、继续和同题重答。

已投递的申请优先使用当时的稿件；后来修改简历不改变历史投递内容或已经开始的练习上下文。

反馈可以就地转为：

- 一项待准备事项。
- 一份更清楚的表达。
- 一处简历修改。
- 用户主动补充的经历内容。

后续收集的求职经验整理为带来源、适用情境和例子的指导卡，在用户遇到卡点时提供，不要求先读教程再使用产品。

## 3. 系统与接口需要怎样配合

继续使用现有 PostgreSQL、模块化单体和三个权限边界。保留已完成的供给、岗位规则、申请、导出和身份基础，调整妨碍新体验的旧约束。

| 系统部分 | 必须落实的变化 |
|---|---|
| 导入与附件 | 增加可长期找回的私有原件记录；原件与解析临时副本分开，旧定时清理不能删除用户保留的原件 |
| 经历 | 完整经历及修订、稳定的简历条目关联、首次自动收录和重复导入去重 |
| 简历内容 | 扩展为模块、多条记录和有限富文本；旧正文与历史仍可读取 |
| 保存与版本 | 正文和布局一次保存；可变草稿与不可变版本分开；导出和投递固定成对版本 |
| AI 审阅 | 支持通用、方向和岗位上下文；用户填写或导入的材料可以直接用于任务 |
| 面试 | 支持无 Case 的经历、简历和通用练习，保留题目、回答和重答版本 |
| 收藏与筛选 | 收藏状态独立于申请阶段；完整查询条件可准确保存和恢复 |
| 材料复用 | 表达可关联多段经历与简历，并在当前页面创建、取用和更新 |

AI 继续通过已有供应商和任务执行基础运行，增加用途区分、交互任务调度与预算控制。模型不直接写数据库；用户采用后的修改由相应业务服务完成。

自动保存、AI 采用和版本恢复共享明确的修订检查。迟到响应不能覆盖新输入，删除后的任务不能恢复已删除数据。

旧文档中“导入必须脱敏”“只能使用预先确认的证据”“原件确认后立即删除”等冲突条款，需要随实现同步替换。不能继续作为新功能的前置限制。

## 4. 调整后的实施顺序

| 阶段 | 交付内容 | 完成标志 |
|---|---|---|
| U0 落实新需求契约 | 将本版决定落实到对象、接口和迁移设计，标记旧限制的替换位置；验证中文编辑与导出兼容 | 不再留下是否脱敏、原件是否保留、是否自动收录等产品选择 |
| U1 贯通首条真实链路 | 空白或导入 → 直接编辑 → 自动收录经历 → 实际 AI 追问/修改 → 一种可靠模板 → PDF | 手工路径独立可用；真实 AI 路径可以用自由输入验证 |
| U2 完整简历编辑器 | 多条目、富文本、全部模板、版式分页、自动保存、历史与方向稿 | 能完成实际可投递的文档，换模板和改稿不丢内容 |
| U3 完善 AI 工作方式 | 整份简历审阅、局部改写、动态经历挖掘、岗位解释与表达生成 | 不同材料和回答产生适当不同的帮助，成果可采用和继续修改 |
| U4 面试与材料回流 | 独立练习、两种节奏、同题重答、常用表达、准备事项和指导卡 | 简历内容能练习讲清楚，反馈能回到当前材料 |
| U5 全工作区整合 | 导航收拢、收藏/筛选、图谱、申请和日程，完整组件与响应式 | 正式页面功能齐全，跨页面工作保持连续 |
| U6 候选验收 | 旧数据迁移、删除恢复、真实运行配置、性能与完整旅程检查 | 主体功能和真实运行条件分别有证据，未就绪项明确 |

工作区基础组件从前期同步使用，U5 完成全覆盖。供应商配置、来源持续观察和已有性能缺口也从前期处理。

U1 的单模板链路用于尽早发现集成问题，后续仍完成完整编辑器和全部范围。不会以这个阶段性产物代替最终交付。

## 5. 验收与明确默认

必须通过以下真实使用场景：

- 新用户没有简历、经历库或目标岗位，仍可直接开始写。
- 导入后联系方式完整，直接编辑；原文件可以重新下载。
- 三段实习、两所学校、多个项目能独立编辑、排序和排版。
- 同一项目的要点保留共同上下文，自动收录不产生重复经历。
- 更换方向稿、模板或修改表达，不覆盖其他稿件和实际投递稿。
- AI 能回应最新回答、跳过已知信息、适时成稿；固定示例不能算通过。
- 没有具体岗位也能优化简历、练习面试。
- 收藏不会制造一堆待办；常用筛选完整恢复关键词和条件。
- 手机、宽屏及原生 200% 缩放下，关键操作和当前输入始终可达。
- 保存失败、网络重试、并发修改和迟到任务不会丢失或覆盖内容。
- PDF 中文、文本复制、链接和多页输出可用，DOCX 单独验证。

AI 的经历追问、简历修改、岗位解释和面试反馈分别评价，不能用一个平均分掩盖单项问题。编辑响应、保存、任务等待及后台并行性能分别测量，沿用已有性能基线；容量探索不取代正常使用验收。

明确保留中国大陆本硕博在校生定位，首批面向 1000 人以内累计尝试者。OS-7、纠偏、公司上限取消和业务恢复不重做。真实来源准入与运行条件继续处理，不混入学生的编辑流程。

本版是完成对话核对和三项选择后的替代计划。coco 已于 2026-09-07 明确授权完整实施；阶段结果见执行记录，不能将本计划当作完成证据。
