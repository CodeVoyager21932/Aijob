## P1：连接、方向与选择权

三种互斥方式：`existing_sources`（仅刷新已接来源，无 Key）、`ai_connection`（复用已验证具备搜索能力的个人 AI）、`tavily`（独立搜索）。当前可用 Tavily 不自动切换；新用户可优先检查已有 AI。失败不擅自换供应商或消耗另一份预算。

首批适配 OpenAI Responses `web_search`、百炼 Responses `web_search`、OpenRouter `openrouter:web_search` 与 Tavily Basic。中转站按已知协议检查，不按模型名字推定支持。HTTP 成功、模型声称能搜索或回答中出现链接均不算通过，必须有真实工具执行及来源元数据。状态区分可用、当前方式不支持、未识别、临时失败；能力与连接修订、模型、适配器版本绑定。首次选择/配置改变时检查，不在每次打开页面收费。

连接表单只要求服务商、地址、Key、模型；协议、JSON、Token、并发和超时放高级选项。模型列表是辅助，获取失败仍可手填。密钥不回显、不要求重复输入。独立搜索的密钥按 owner 加密，复用 AI 时只引用 `profile.ai_connections`。

新增 `user_source_discovery`，由 match-worker 处理，collector 不读取个人连接。match 通过受限函数提交公开 URL 线索，无安装、启用和准入权限。个人 24 小时缓存按 owner/epoch、连接修订、适配器/模型/查询版本隔离，同一用户方向共享；URL 在公共线索层去重。

Tavily 每日 20、每月 500 次网络尝试，重试也计数；模型搜索同时受搜索额度和原个人 AI 次数/Token 预算约束。网络尝试、实际工具次数、模型 usage 分开记录，未知不得写成 1。额度耗尽暂停新发现，已接来源刷新不受影响。

方向查询保持“产品实习，上海/杭州”：两城市轮转，使用目标招聘类型及产品实习同义词，不拼接所有招聘类型或静默扩成产品运营。只发公开方向关键词，不传简历。版本化缓存、公平调度，不做全组合穷举。

## P2：来源接入与真实质量

随应用提供维护者审阅、带版本的来源目录，记录主体、官方入口、厂商变体、访问范围/依据、能力、核验时间与状态。内置目录只读，本机安装配置覆盖；不批量启用旧配置。首次启用、新增请求范围、恢复暂停来源仍需内部明确操作，获准范围普通刷新自动进行。

首轮完善已支持北森的新租户接入：官方入口 → 识别实际租户/PortalId → 确认页面提供的招聘类型 → 有界实际试采 → ID/分页/条数/正文/投递入口核对 → 可读预览 → 既有 reviewedHash/安装/PG 注册。不得猜参数、用占位选择器或某公司成功冒充通用成功。状态为 complete、explicit_empty、partial、failed；部分失败不关闭岗位，明确零条仍遵守间隔与两次缺席规则。

通用 HTML、结构化数据、受控浏览器和人工快照沿用当前路径；本轮不做第二套通用 ATS 或无限浏览器 Agent。公开 HTML 规则辅助仍属内部维护，不暗用个人 Key。未知来源给出具体原因及可主动导出的公开诊断，只有任务真实运行才显示“正在尝试”，不自动发外部 issue。

修复哈啰任职要求中“我们能提供什么”等福利段；保留职责和要求原句。内容不变仅更新核验时间；真正语义或活动变化生成事件。收藏、已读、暂缓、已投状态保留。首次结果为当前机会，后续才报新增；跨方向合并岗位并保留标签。未说明职能仍可查看，但不算已确认产品实习。

## P3：本机运行与 Windows 安装

使用薄 Electron 壳及 electron-builder NSIS 当前用户安装。固定独立 Node 22、PostgreSQL 16 的补丁版本和校验清单；打包 Web 产物、三服务、独立 Chromium、现有解析器、全部模板/字体及许可。生产包不依赖 Vite、tsx、pnpm 或 Docker；workspace exports 指向编译 JS。原生模块、子进程入口、WASM、字体和 Chromium 使用真实资源路径，不塞进无法读取的 asar。

程序资源只读，持久数据位于 `%LOCALAPPDATA%\Aijob`：PG、文件、加密配置、密钥、Electron profile、日志、备份及来源覆盖层。首次分配 loopback 端口后固定复用，占用时明确提示，不静默换 origin 导致身份丢失。

启动顺序：单实例 → 路径/配置 → 自有 PG 就绪 → 有待迁移时备份一次并前向迁移 → 三权限服务就绪 → UI。旧库故障不重新初始化。worker 最多连续恢复三次，之后显示可操作错误。关窗驻留托盘并首次说明；完全退出停止领取任务、结束 worker、再 `pg_ctl stop -m fast`，只管理本应用 PID。开机启动默认关闭，由用户选择。重启合并到期工作，不重放每个离线日。

本机身份通过设备绑定恢复既有 owner；设备凭据仅主进程 DPAPI，库中仅哈希。有效 cookie 直接复用；过期后走受限本机 IPC 恢复并调用既有 session 服务。账户删除、epoch 改变和撤销均使绑定失效，不提供公开 ownerId 登录接口，不复活已删除账户。主密钥 DPAPI 保留，通过受限通道传给后端。

当前 Docker 业务库/文件/密钥保持原样；安装验证使用独立 dataRoot。迁移向导显式备份、复制原密钥和保留文件、恢复至独立 PG、绑定旧 owner，成功后才切换；不让两套实例重复调度相同订阅。安装签名、公网发布、自动升级单列，不以开发候选冒充已签名发行。

本地受控浏览器沿用 safe-http、精确范围及隔离上下文，可使用独立 Chromium；不伪造 container 标志，不删除既有非本机环境的隔离要求。

## P4：连贯页面与材料闭环

首次启动先就绪，再保存方向、选择已支持来源范围、看实际当前机会；扩展网站和写作 AI 可后配。普通用户不看 8091、PortalId、JSON 或终端。设置统一为“连接与运行”。今日、发现、简历、材料、投递管理沿用现有工作区。

导入、局部纠错、原件留存、四类 Forme/旧 40 模板、服务端同产物预览下载均保留。岗位进入独立稿，与其他稿件分离；投递记录固定当时稿件和文件，后续编辑不改变历史。AI 最多一轮起草一轮审阅，局部采用可撤销；无 AI 仍可写、复用、下载和记录投递。只修复实际失败，不重做引擎或扩大模板数量。
