**1. 为什么这次确定替换**

[架构审计](../reviews/2026-09-11-resume-architecture-audit.md)已确认，问题跨越多个环节：

| 当前事实 | 此次决定 |
|---|---|
| PDF 提取去掉位置和换行，再交给依赖标题行的解析器；自身 6 模块、7 条记录的短稿回导成 1 个 custom 正文 | 替换读取与结构识别接口；采用保留位置、行、列和段落的路径 |
| 学校在导入与表单中使用不同字段 | 新版所有入口使用同一份按模块定义的数据，禁止模板猜字段含义 |
| 40 套模板主要通过通用 entryHtml、profile 和 CSS 特例组合 | 新模板接入原生模板组件、语义布局和分页能力；旧组合器退出新版链路 |
| 中稿有约 1 万像素表单、236 个按钮，预览默认缩小到约 53% | 引入成熟条目编辑与工作区状态，重排控件层级，预览优先可读 |
| 120 组规整样稿可以输出，却未覆盖实际导入后的错误结构 | 导入、编辑、模板、文件分别验收，再验完整旅程 |
| 较早的空正文 PDF 对应的保存快照已无正文 | 保留证据；浏览器曾否存在未保存输入仍未知，不能臆断已查清 |

替换对象是简历模块的核心契约与实现。PostgreSQL、账号隔离、原件、修订、导出产物和投递快照已有独立价值，继续复用。

旧路线图和交接把局部工程验证外推成“简历主体完成”的表述需要纠正。获准实施时同步 README、路线图、交接和 ADR，明确“业务基础保留；简历核心正在替换”，不再把本轮当作零散美化。

**2. 这次固定的技术路线**

- 项目：[Reactive Resume](https://github.com/reactive-resume/app)。
- 发布版本：[v5.3.0](https://github.com/reactive-resume/app/releases/tag/v5.3.0)，2026-09-06 发布，非预发布。

**3. 最终用户会得到什么**

用户从“空白开始、导入文件、已有经历”三种平等入口进入。无需预先选岗位、配置 AI、建立经历库或逐句确认。

| 场景 | 本轮成品行为 |
|---|---|
| 从空白开始 | 可以直接填写姓名、学校、项目和技能，未填完整也能保存 |
| 导入现有简历 | 教育、工作、项目和时间分别进入对应位置；原件随时查看和下载 |
| 修改经历 | 一段项目的角色、时间、描述和成果保持共同上下文 |
| 模板选择 | 展示真实中文样稿，选候选后仍能滚动全部图库；应用后结构明确变化 |
| 继续编辑 | 返回、换工具、重新打开，输入与当前编辑位置能够恢复 |
| 下载 | 刚输入或刚换模板也能下载正确修订；文件正文完整 |
| 其他求职任务 | 经历可复用，方向稿独立，实际投递稿与已开始的面试上下文不被改写 |

**4. 一份权威文档，避免新旧结构反复转换**

**4.1 内容与布局的真源**

新版采用一个版本化文档包，拟称 aijob-resume-native-v1。内部以固定上游 ResumeData 为基础，明确登记 Aijob 的中文与业务扩展。

- 原生模块和 metadata 中分别表达内容、模板与版式；同一次保存整体提交。
- 来源关联只保存原件/经历/条目/修订指针，不重复储存另一份可编辑正文。
- 光标、展开条目、面板、滚动和缩放是工作区状态，不参与投递版本或导出内容散列。
- 新版草稿不双写旧 ResumeStudioContent；旧 Case、助手等需要内容时，读取只读语义投影，不能从该投影反向覆盖新稿。
- 正文与布局仍能分别建立不可变修订，checkpoint 在同一事务中固定二者，保证投递和导出引用正确配对。

“采用原生模型”不等于无条件使用上游的容错默认值。正常写入必须严格校验类型；非法数据明确失败并保留输入，不能被默认空值悄悄替代。

**4.2 中文模块和字段**

| 模块 | 必须具有的独立字段 | 展示与编辑要求 |
|---|---|---|
| 基本信息 | 姓名、方向/简介、电话、邮箱、城市、链接；可选照片 | 联系方式正常保留；无内容不占位 |
| 教育 | 学校、学历、专业、时间；成绩、课程、研究方向可选 | 学校与补充说明分开；本科、硕士、博士均可多条 |
| 实习/工作 | 公司、部门、职位、时间、地点、描述 | 公司、角色、日期和正文共同属于一条记录 |
| 项目/校园实践 | 名称、角色、时间、链接、描述 | 不要求填写企业；一组要点属于同一项目 |
| 科研 | 课题、单位、角色、时间、方法、成果表达 | 不把论文书目当工作职位 |
| 论文/成果 | 标题、作者及本人顺序、刊物/会议、年份、状态、链接 | 长标题和多条文献自然续排 |
| 技能 | 分类、名称、使用说明 | 采用短行或分组，默认不显示能力进度条 |
| 语言、证书、奖项 | 名称、水平/成绩、授予方、时间、说明 | 使用各自标签，不显示企业/项目通用字段 |
| 简介、自定义 | 标题、正文；必要时多条 | 正文不会一律命名为工作成果 |

上游没有完全对应的项目角色、科研或中文补充字段，在同一模型中扩展，并同时接通表单、严格校验、模板绑定、AI 修改和 DOCX。不能把扩展值塞进隐藏字符串，或只在界面临时显示。

日期支持年月、仅年份、至今和原始文字。时间控件与文档日期采用一个明确来源；格式化值只作派生显示，不同时维护两组可各自修改的日期。无法无损拆分的原日期保留为可编辑文字。

草稿允许空姓名、未完成学校、只有描述的项目和输入中的日期。上游要求非空名称的约束需要在受控扩展中区分“可保存草稿”和“可显示内容”；不能因缺一个标题删除已有正文，也不能把填写完成变成保存关卡。完全空的条目不打印，部分填写的真实内容正常打印。

**4.3 一套编辑操作和撤销**

字段修改、富文本修改、插入材料、复制、排序、移动、拆分、合并、显隐、模板应用和 AI 采用，共同修改同一份稿件。

- 一个前端文档状态容器、一条串行保存队列；上游状态接入 Aijob 保存接口后，旧 use-studio-draft 不再同时驱动新稿。
- 富文本输入与文档结构操作统一协调撤销；一次模板切换或 AI 采用是一组操作，连续输入合并记录。
- 中文输入法组合期间不重建输入组件，不重置光标。
- 跨类型移动执行明确字段映射；无法映射的真实内容保留为可见补充，不静默丢弃。
- 常规操作继续保存快照与修订，不建设全量事件溯源系统。
- 已保存、正在保存、保存失败分别显示；后台预览成功不能冒充保存成功。

**5. 导入重建：保留结构，准确归类，可就地修正**

**5.1 读取和识别**

流程固定为：上传原件 → 隔离读取结构 → 模块/条目识别 → 原生文档 → 直接进入编辑。

| 输入 | 读取要求 |
|---|---|
| PDF | 保留页、文字位置、行、列、字体线索和阅读顺序；复用上游可读文本提取能力，再扩展中文识别 |
| DOCX | 保留段落、列表、表格单元格及链接关系；文本框等无法读取内容须报告，不悄悄忽略 |
| 纯文本 | 保留换行、列表、分隔符和原始段落，不先压成一段 |
| 扫描 PDF、图片、加密等现有不支持类型 | 如实提示现有限制；原件保留，允许换文件或粘贴文字，不假装结构识别完成 |

v5.3.0 已增加无需 AI 的文本 PDF 导入，其[读取实现](https://github.com/reactive-resume/app/blob/86a72bef138ae51771ea3bdeda9b2871a3a838c8/apps/web/src/features/resume/import/pdf-text.ts)会处理行和分栏。因此不再沿用“该项目 PDF 必须依赖 AI”的旧判断；其中文准确率和 DOCX 路径仍不能推断为已满足本项目。

Aijob 延续现有文件校验、大小限制和隔离执行。上游浏览器读取代码可以拆出确定性部分复用，不能为了原样运行页面而绕开当前文件处理边界。

中文识别覆盖教育背景/经历、工作/实习、项目、校园实践、科研、论文、技能、语言、证书、奖项与简介。条目边界同时看位置、标题和日期；一个 bullet 不自动成为一段新经历。保留 sourceBlock → section/item/field 的来源关系及解析版本。

**5.2 直接可用和错误恢复**

- 正常结果直接进入对应表单，可显示“已整理 2 段教育、3 段项目”。
- 未识别的非空内容保留为中性补充，不自动叫工作成果，也不藏进不可见区域。
- 支持就地归类、移入现有经历、拆分与合并；编辑旁可查看原件相关区域。
- PDF 原件对应页与坐标；DOCX 对应段落/表格，不伪造页面坐标。
- 提取完成与结构识别质量分开记录：结构化、部分结构化、未能形成结构、不支持。少返回字段不能算高质量。
- 不增加脱敏预览、逐句勾选、事实审批或“确认资料后再次初始化”。
- BYOK 可由用户主动用于复杂识别，普通中文简历的手工/规则路径独立可用；模型结果走相同字段和来源规则。

导入内容不等于恢复原 PDF 的视觉模板。新建导入稿使用默认中文单栏；从模板开始则使用已选模板；向现有稿导入保留当前模板。原文件和可编辑稿分别可查。

**5.3 并发、重复和首次收录**

同文件、解析版本、目标稿件和请求键参与去重，旧错误解析缓存不能当新版结果。解析晚到时只合并未被修改的字段；冲突保留为待取用结果，不覆盖用户输入。

结构化的完整经历首次自动收录；手动新增经历在完成本次条目编辑或离开该条目时收录，未完成内容先保存在草稿。连续编辑同一新条目不重复建库。收录必须与保存结果、稳定条目 ID 和修订一致，不再依赖是否打开助手或是否导出。

**6. 编辑工作室与模板图库**

**6.1 桌面编辑**

- 沿用 V2 视觉，编辑页默认收起全局侧栏，清楚保留返回入口。
- 初始约 40% 编辑、60% 预览，可拖动并记忆；不把比例作为所有屏幕的固定限制。
- 顶部固定稿件名称、保存状态、撤销重做、模板、排版、版本、PDF 和 DOCX。
- 连续模块中当前条目展开，其他条目显示名称、角色和日期摘要；可主动展开多条比较。
- 常用修改靠近内容；栏位、分页和模块配置进入工具面板，不在每段正文旁重复展示。
- 复用成熟富文本部件：加粗、斜体、下划线、段落/列表、缩进、链接、清除格式和粘贴整理。
- 清理粘贴带来的外部字体/字号；保留真实段落、表格和文字格式。正文随内容增长，避免狭窄多层滚动框。
- 材料调用和条目 AI 在当前位置打开，关闭后恢复焦点；整稿审阅在顶部。

纸张实际条目可定位编辑位置，编辑不强制纸张跳动。复用原生布局绑定；需要补充条目 ID 到页/区域映射时，通过渲染结果的交互层实现，不重写分页测量算法。该映射在 K0 验证接口可行性，K1 完成实际操作。

**6.2 预览与屏幕**

| 可用宽度 | 默认组织 |
|---|---|
| >=1200px | 双栏，保证表单宽度和纸张阅读空间 |
| 900–1199px | 收起导航/次要工具，编辑优先；允许并排或切换预览 |
| <900px | 编辑/预览切换，共享输入、条目和位置 |

默认适应宽度，保留 100%、整页和全屏，记忆选择。纸张缩放不改变文档字号和分页，表单按钮不随纸张缩小。PDF.js 必须有可选择文本与可访问的内容入口，不能只留下一个不可交互图片画布。

**6.3 图库**

桌面采用可滚动网格与固定候选详情；窄屏采用候选详情页/抽屉，返回恢复筛选和位置。点击模板不把大预览插在整个列表上方。

提供搜索、风格/单双栏/照片/密度/长材料筛选、收藏、最近使用，以及最多三份候选对照。卡片只加载真实缩略图；个人预览只渲染当前候选，并设总并发预算。

默认使用同一份适量中文样稿，标记“样稿”，与“用我的内容预览”明确切换。姓名空白也能看出完整差异。样稿不得进入用户简历、经历或 AI。

应用模板一次性采用新模板默认字体、间距、区域和分页设置，清除旧模板冲突设置；保留正文、隐藏状态、模块逻辑顺序和来源关系。现有模块全部得到合法区域，模板未预设的模块也有输出位置。应用操作可以完整撤销；成功保存应用后才记录最近使用。

**8. 原生渲染与最终下载闭环**

**8.1 两个预览时点，统一版式来源**

编辑过程中使用原生引擎生成草稿 PDF，PDF.js 显示最新完成的结果。生成在 Worker 等非输入主路径中执行，合并连续修改，旧结果不能覆盖新稿。依赖或字体加载期间显示正在更新，保留上一份结果及对应状态。

下载流程：

~~~text
当前输入完成提交
  → 串行保存完成
  → 同一事务固定正文与布局修订
  → 读取确定的文档、模板、字体、引擎版本
  → 原生服务端渲染
  → 检查内容、链接、页面及可见性
  → 保存私有导出产物
  → 预览该产物并下载同一份文件
~~~

两条路径使用同一原生文档和模板定义、字体文件、资源与语言设置。浏览器与服务端接口不同也必须传递一致参数；不允许客户端有自定义字体或区域而服务端遗漏。

草稿 PDF 与服务器文件的二进制散列可能因文档元数据不同而不同，不把“共用引擎”宣称为字节一致。应验证正文、页数、主要断页及视觉一致；最终文件预览、再次下载和历史下载严格使用同一个已保存产物。

点击下载不强制用户再完成一轮审批。保存或渲染失败时保留输入并显示具体状态；不自动下载旧版本冒充最新。

**8.2 字体、资源和分页**

- 浏览器与后端绑定同版本普通/加粗字重及中文字体，优先复用已有经过许可的 Noto 资产。
- 禁止导出时访问 Google Fonts、竞品 CDN 或任意外网；本地/同源字体与经过 owner 校验的照片由资源适配器提供。
- 加载失败明确报错，不能用不同字体静默回退后仍声称与预览一致。
- 字体加载完成后测量；标题与首段相连，超长条目自然拆分，双栏分别续排；页眉和页脚不压住正文。
- 固定版本处理续页、空标题、孤立日期、长链接、中英文混排和中文标点断行。
- PDF 文本可复制、搜索，链接有效；不把页面栅格化成图片来规避排版问题。
- 不在持有数据库行锁或事务时等待渲染；沿用现有有界并发、租约、超时和删除防复活机制。

**8.3 三层完整性验证**

1. 内容层：从原生模型独立生成应输出的可见字段清单；不从模板渲染结果倒推清单。
2. 排版层：每个可见条目/字段均有页面承载，检查越界、遮挡、断页和重复；不能只有文字存在。
3. 文件层：对最终 PDF 字节读取全部页面，核对字段、数字、中文和链接；同时检查位置及真实渲染。

重复短语按字段所属条目核对，双栏不以简单字符串顺序判失败。仅允许正常空白、断行及等价 Unicode 差异。核验失败不返回成功产物，日志仅保留字段标识与失败阶段。

**8.4 DOCX 与打印**

DOCX 是同一原生内容的独立输出适配，不宣称 Reactive Resume 已提供本项目所需的全部 DOCX 功能。继续复用现有文件/产物服务，补齐模块专用字段与版式转换。

40 套均需有完整、可编辑 DOCX；保留标题、条目、日期、列表、链接、照片和合理分栏。复杂装饰可以明确简化，不用整页图片代替，不承诺 WPS、Word、LibreOffice 像素一致。各软件实际测试结果单列。

打印使用已生成 PDF 的打印入口；旧文档仍可走其原有兼容流程，不为新版再做一套 HTML 打印页面。

**9. 经历、AI、申请和面试接回同一条链**

- 完整经历与当前简历表达分别有修订，通过稳定条目关系连接。
- 首次收录后，普通改写只影响当前稿；更新经历原稿是就地明确操作，不自动同步所有方向稿。
- 材料插入创建正确类型的条目，可以整组撤销；自我介绍、项目长短版、邮件继续使用已有材料入口。
- BYOK 助手直接读取原生稿件及必要完整经历；建议以字段/段落/条目和基准修订表达，不能只返回整段替换文本。
- 局部采用保留富文本、条目归属及未选内容；迟到建议不能覆盖新的修改。
- 经历追问动态回应最新回答，可跳过、结束或先成稿；没有 API 时手工和固定提示明确可用。
- 新版投递记录固定原生文档、版式及导出修订；旧投递稿与已开始的面试上下文继续固定旧快照。
- 面试、岗位准备和图谱需要材料时使用统一只读内容投影；反馈通过同一编辑操作回流，不能后台改写历史稿。

本轮不增设第二套 AI 供应商平台，不购买模型，不恢复脱敏和证据审批。真实 BYOK 效果与夹具验证分开记录。

**10. 代码边界与接口**

以下目录是实施时的职责划分，允许按现有构建组织落位，但职责不可混淆：

| apps/web/src/career-os/studio | 替换主编辑器与预览接线，保留 V2 外壳，接入图库、材料、版本和错误恢复 |
| apps/platform/src/resume、resume-documents | 结构读取、导入、版本保存、产物、附件、材料/AI 接入；旧读取分支独立 |

| 接口/对象 | 拟定变化 |
|---|---|
| v2 Studio 加载/保存/checkpoint | 支持原生文档格式、expectedRevision、幂等键和成对修订；同一事务保存 |
| 导入任务 | 返回提取状态、结构质量、来源映射、解析版本及合并结果 |
| 模板目录 | 返回原生模板 ID/版本、能力、真实缩略图版本、来源和偏好 |
| 导出创建/下载 | 复用已有地址与产物对象，按文档格式分派渲染器，记录原生引擎/模板/字体版本 |
| AI 与材料 | 支持原生条目和类型化变更；明确基准修订 |
| 历史读取 | 保留旧版本及文件，不在 GET 时迁移或改写 |

语义改变的接口使用版本分支，不复制整个平台 API。旧客户端写入新版文档时明确拒绝并引导打开新版，不能容错降级成旧结构。相同幂等键携带不同正文必须返回冲突。

**11. 旧资料迁移与回退**

1. 先备份并部署能同时读取旧/新格式的兼容服务；迁移编号按实施时链路确定，当前文档记录的 065 不能直接当实时数据库探针。
2. 新建文档使用原生格式。已有结构正确的草稿通过一次转换生成新修订，保留旧不可变修订与来源关系。
3. 当前活跃旧草稿通过显式转换任务处理，操作受 expectedRevision 保护；读取不产生转换副作用。界面说明已保留旧稿，不要求重新填写。
4. 对整段 custom 的错误导入，从保留原件重新识别；比较旧导入结果、用户当前修改和新识别结果，只自动应用可确定的未修改部分。
5. 无法安全合并时保留当前稿与新的整理候选，让用户就地取用；原件不存在则保留原文并提供结构整理，不伪造重建。
6. 旧经历库条目同样通过一次类型化转换，新引用指向新修订，旧投递及面试引用保持原版本。
7. 旧模板 ID 和版本继续可读；换成新版中文模板须形成新的布局修订，不按相似名称暗中替换历史外观。
8. 导出文件、原件及历史投递稿不批量重新生成。owner、删除和迟到任务保护同时覆盖新增结构。
9. 回退对象必须是已经具备新文档读取能力的兼容版本。关闭新写入时仍能找回新稿与已有文件；不能回退到只识别旧 JSON 的程序。
10. 新版正式接管后，旧编辑入口退出新建与主编辑路由；旧渲染作为历史兼容保留。后续新模板不得依赖旧 renderer/profile/pagination 文件。

迁移不搬动项目目录，不重复恢复业务库，不触碰 OS-7、纠偏或公司上限取消等已关闭任务。

**13. 验收、失败标准和结束条件**

**13.1 真实输入与结构质量**

建立 30 份不依赖当前生成器的输入：10 单栏 PDF、8 双栏 PDF、8 DOCX（含表格）、4 文本；覆盖本硕博、非技术岗位、实习、科研、长标题和中英文混排。至少 10 份不参与规则调整，留作独立检查；不支持文件另测，不混入准确率。

从原件标注模块、条目边界、所属关系、字段和描述，分别计算各类输入的精确率与召回率，以各项 >=95% 为固定样本目标。漏识别和未归类计入召回损失，错放和多识别计入精确率损失；不得只返回少量正确字段提高分数。样本指标不作为全市场准确率宣传。

已经复现的学校错位、标题误判、日期误读、整份合并为 custom 必须逐项通过；正文静默丢失、凭空补数字和覆盖用户修改为零。每段实质内容都有去向，不能靠剔除困难文件通过。

另外对 40 套短稿进行 PDF 回导，覆盖自身标题、行列和日期；不只依赖私有嵌入 JSON 绕开实际 PDF 读取。

**13.2 40 套 × 三类内容**

至少 120 组真实预览/PDF/DOCX，使用短稿、中稿、长科研稿：

- 短稿正常一页，长稿自然续页，无空白尾页或被推走的大块正文。
- 联系方式、学校、公司、角色、日期、数字、链接、所有模块和扩展字段完整。
- 逐页检查裁切、遮挡、白字、重叠、断行、标题和日期排列。
- 草稿 PDF 与同修订服务器 PDF 的页数、主要断页和布局一致；最终预览与下载产物字节相同。
- PDF 文字可复制，DOCX 可编辑，表格/列表/链接结构合理；测试软件明确列出。
- 原参考与适配结果使用同一内容和明确字体；差异有解释，不以模板名称、总字符数或单一图片相似度代替评审。

故障场景包括：最后一笔输入后立即下载、保存 503、网络断开与恢复、并发修改、重复请求、导入晚到、AI 晚到、渲染超时、字体失败、删除后迟到任务。不得丢输入、下载旧稿冒充新稿或复活已删除资料。
