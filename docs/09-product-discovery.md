# 产品发现与四层礼宾实验

> 本文定义首轮用户研究、礼宾实验和证据判定方法，不记录当前招募和执行进度。依据 ADR-0011，全部参与者任务只在 `G2 Local Complete MVP` 通过后开始；动态进度只更新到 [MVP 路线与当前决策面板](06-mvp-roadmap.md)。

## 1. 研究目标

当前方向仍是待验证假设。首轮研究只回答三件事：

1. 目标用户在现有官方公共服务、企业官网和高校就业网之间做投递决定时，是否存在重复且高后果的问题。
2. 官方岗位清单、来源与时效、资格与经历证据三层信息分别带来什么增量。
3. 规则和模板已经可用后，受控 AI 简历对照修改是否进一步提高理解正确率或决策效率。

研究不以“用户说喜欢”“页面显得专业”或“愿意以后使用”作为成功证据。

## 2. 首轮样本

### 2.1 纳入条件

每名参与者必须同时满足：

- 位于中国大陆且为在校生。
- 未来 30 天内正在真实投递产品或运营实习。
- 已有一份可用于投递的中文简历。
- 最近 30 天使用过至少两个官方渠道寻找岗位。
- 愿意展示或复盘一次近期真实找岗和投递决定。

官方渠道包括企业招聘官网、企业官方链接或确认的 ATS、高校就业网、企业公开招聘页面，以及国家大学生就业服务平台、中国公共招聘网等官方公共服务入口。

### 2.2 排除条件

- 只表达“以后可能找实习”，当前没有真实投递任务。
- 主要目标是校招全职、技术岗、内容岗或社会招聘。
- 没有中文简历，或主要诉求是职业探索、简历代写和自动海投。
- 最近只使用综合招聘平台，无法复盘官方渠道任务。

### 2.3 样本安排

- 先招募 2 名校准用户，完整走通访谈、任务、术语测试和回访；其结果不计入正式分母。
- 校准后再招募 6 名正式用户，不用校准用户补足正式样本。
- 参与者编号、联系方式和研究记录分开保存；研究分析只使用匿名编号。

小样本只用于方向性验证和发现失败模式，不能推断总体市场规模。

## 3. 当前替代方案

访谈必须从用户的实际流程开始，不能先暗示本产品更好。

| 替代方案 | 研究重点 |
|---|---|
| 国家大学生就业服务平台、中国公共招聘网等官方公共服务 | 用户已经获得哪些官方供给和筛选能力，为什么还会离开 |
| 企业招聘官网与官方 ATS | 用户如何发现、收藏、复查和返回申请 |
| 高校就业网、院系通知与就业公众号 | 用户如何判断时效、适用人群和重复岗位 |
| 综合招聘平台 | 覆盖量、搜索效率和既有习惯为何有吸引力 |
| Excel、Notion、飞书表格和收藏夹 | 用户如何记录状态、理由和后续动作 |
| 学长学姐、社群和求职辅导 | 用户信任人的哪些判断，哪些无法规模化 |
| 通用 AI 和简历工具 | 用户如何校验 AI 结论，哪些错误会造成伤害 |

本项目差异不能写成“比官方公共服务更可信”。待验证差异是跨来源资格核对和基于用户证据的投递决策。

## 4. 问题树

~~~text
学生没有形成高质量投递决定
├─ 机会分散
│  ├─ 多个官方入口重复浏览
│  ├─ 岗位字段结构不同
│  └─ 收藏后难以持续复查
├─ 来源和时效不清
│  ├─ 发布主体与申请入口关系不明
│  ├─ 最后核验时间未知
│  └─ 页面异常与岗位关闭难区分
├─ 资格难核对
│  ├─ 城市与到岗时间
│  ├─ 每周出勤与持续月数
│  └─ 毕业年份与招聘批次
├─ 经历证据难判断
│  ├─ 简历内容与岗位要求无法对应
│  ├─ “简历未体现”被误当成“没有能力”
│  └─ 岗位没有说明却被强行推断
└─ 决定与行动脱节
   ├─ 只收藏，不记录理由
   ├─ 前往官方页后丢失上下文
   └─ 不了解下一步应补什么
~~~

访谈要找出哪一支反复出现且会改变投递，不能预设所有分支都同样重要。

## 5. 假设与证据

| ID | 假设 | 失败信号 | 最便宜验证 |
|---|---|---|---|
| H-PROBLEM-001 | 目标用户需要现有官方服务之外的跨来源决策层 | 现有工具已能快速完成资格与证据判断，没有重复成本 | 近期行为访谈和现有流程基线 |
| H-LIST-001 | 统一官方岗位清单降低找岗成本 | 用户仍回到原流程，清单没有改变时间或候选集 | 礼宾 Layer 1 |
| H-SOURCE-001 | 来源类型和最后核验时间影响判断 | 用户不查看或不因这些信息改变决定 | 礼宾 Layer 2 |
| H-VALUE-001 | 资格与经历证据解释改善高质量决定 | 只提高主观好感，不提高理解、效率或行动 | 礼宾 Layer 3 与 72 小时回访 |
| H-PRIVACY-001 | 明确保留和删除边界后，用户愿意提供必要文本 | 大多数用户拒绝或因隐私中断任务 | 校准和正式实验中的真实提交行为 |
| H-AI-001 | AI 简历对照修改比固定模板进一步改善理解或效率 | 效果相同、出现事实错误或用户更难校验 | 同一岗位、同一证据的模板与 AI 盲序对照 |
| H-DATA-001 | 代表性官方来源能以可接受成本持续维护 | 访问边界不允许、结构频繁变化或维护成本过高 | 1 个来源起步、扩至 3 个的连续数据切片 |

每轮只把 1-2 个假设列为最高风险；当前选择以决策面板为准。

## 6. 校准流程

两名校准用户分别完整执行一次正式协议。校准只回答“实验是否可运行”，不用于宣布产品价值。

校准检查：

- 招募题是否能排除非真实投递用户。
- 用户是否能理解“官方渠道”“最后核验”“资格”“经历证据”和“偏好”。
- 20 分钟任务是否足够具体且不需要主持人额外教学。
- 文件/文本隐私检查、提交和删除说明是否可理解。
- 观察表能否区分用户主动行为与主持人提示。
- 72 小时回访是否有明确时间和可联系路径。

出现以下任一情况必须修改协议并重新校准受影响部分：

- 用户无法说清任务目标。
- 主持人必须解释产品逻辑才能完成。
- 同一术语被两名用户以不同方式理解。
- 实验岗位不足以产生 3 个可认真考虑的候选。
- 记录表无法判断信息层级带来的增量。

## 7. 正式实验准备

### 7.1 岗位池

- 先通过 `G2 Local Complete MVP` 的 1000 条可信活动岗位供给门，再从中冻结 300–500 条覆盖职能、城市、SME 与来源结构的正式研究子集，并人工抽检实际实验样本。
- 每条保留发布主体、来源类型、原始链接、最后核验时间和当前状态。
- 城市、到岗时间、每周出勤、持续月数、毕业年份和招聘批次必须有明确值或标为未知。
- 岗位池同时包含明确符合、明确冲突和信息不足案例，避免全部是容易判断的岗位。
- 正式实验开始后不替换岗位；若岗位关闭，只标记状态并记录影响。

### 7.2 用户输入

- 先收集城市、岗位方向、出勤、持续时间、毕业年份、到岗时间和明确排除项。
- 只有用户选择经历证据匹配时才请求 PDF、DOCX 或去标识化中文文本。
- 粘贴文本先在浏览器本地检查；PDF/DOCX 隔离解析后由服务器与浏览器分别提示个人信息，用户确认前不调用 AI。
- 简历原文在经历证据确认后立即删除，最长不超过 24 小时；结构化约束和证据保留 30 天或由用户提前删除。
- 未经用户确认的内容一律保持未知，不能进入确定性判断。

### 7.3 主持纪律

- 先问最近真实行为，再介绍实验材料。
- 不说“我们的岗位更可信”“AI 会更准确”等引导语。
- 不替用户解释结果，不提示应该选哪个岗位。
- 记录用户看到信息前后的决定变化和原话。
- 事实错误、隐私问题和异常必须当场记录，不因实验继续而忽略。

## 8. 四层礼宾实验

每名正式用户按相同顺序经历四层。每层使用岗位质量、方向和已知冲突结构相近但不重复的岗位子集，六名用户轮换子集，减少岗位本身造成的偏差。

### Layer 0：现有流程基线

让用户用自己的常用工具和方法处理一个近期真实岗位任务，或复盘最近一次完整过程。

记录：

- 打开的渠道与切换次数。
- 找到候选、核对资格和形成决定所需时间。
- 使用的表格、收藏和求助方式。
- 最终决定、理由和仍然未知的信息。

### Layer 1：官方岗位清单

只提供人工整理的岗位名称、企业、城市、基础字段和原始链接，不提供额外“可信”标签、资格结论或经历解释。

记录清单是否减少查找时间、扩大候选或替代现有工具。

### Layer 2：来源与时效信息

在 Layer 1 基础上增加发布主体、来源类型、最后核验时间和当前状态。

记录用户是否主动查看这些信息，以及信息是否改变保存、投递、暂缓或放弃决定。

### Layer 3：资格与经历证据解释

在 Layer 2 基础上增加分开的三类结果：

- 资格：未发现明确冲突 / 存在明确冲突 / 需补充信息。
- 经历证据：有明确证据 / 部分证据 / 简历暂未体现 / 信息不足。
- 偏好：符合 / 不符合 / 未设置。

每个结果必须引用岗位原文和用户确认内容。不得显示匹配度百分比，不得使用“不建议”替代具体冲突，也不得自动隐藏岗位。

完成分层任务后，用户面对完整岗位池执行 20 分钟最终任务：找出 3 个愿意认真考虑且无已知硬条件冲突的岗位，并为至少 1 个岗位记录决定和理由。

## 9. 术语理解测试

每名用户需要独立判断四张情境卡：

1. 用户确认无法满足每周出勤要求：资格冲突。
2. 岗位要求用户可能具备，但中文简历没有对应内容：简历暂未体现。
3. 岗位没有写明毕业年份或到岗要求：岗位信息未知。
4. 用户具备资格但不接受该城市：偏好不符。

只有四张全部判断正确，才记为该用户“正确区分”。不得在答题前提示正确术语。

## 10. 模板与 AI 简历修改对照

AI 对照在 Layer 3 完成后单独进行，不与前三层价值混算。

真实用户文本只有在候选供应商完成数据保留、训练使用、处理地区、跨境、删除和退出评审，且参与者明确选择参加后才能发送。参与者会被告知对照中包含外部模型处理，但不告知每一屏的版本顺序；拒绝 AI 不影响模板任务。前提未满足或不足 6 名正式用户自愿参加时，AI Gate 保持未通过并延期，不用合成结果补足分母。

1. 选取同一个岗位、同一份用户确认简历和同一组事实、偏好与经历证据。
2. 模板版与 AI 版必须使用相同对照结构、岗位要求和证据引用；两者都不能改变资格结果。
3. AI 版先经 Schema、引用和事实校验；发现虚构、漏引、事实升级或改写资格结果时，不展示给用户，直接记录为失败。
4. 6 名正式用户中 3 人先看模板、3 人先看 AI，界面不标注版本来源。
5. 分别测量理解题正确率、完成修改所需时间、接受/拒绝/编辑次数和用户能否复述每处修改依据。
6. 只有至少 4/6 用户在理解正确率或决策效率上优于模板，且没有新增事实错误，AI 才通过启用 Gate。
7. 效果相同、结果不稳定或增加校验负担时，保留模板并继续关闭 AI。

这项实验只证明当前目标岗位简历修改任务中的增量，不证明模型通用能力。

## 11. 成功、失败与守护指标

### 11.1 正式实验通过条件

- 至少 4/6 用户能在 20 分钟内找到 3 个愿意认真考虑且无已知硬条件冲突的岗位。
- 至少 5/6 用户正确区分资格冲突、简历暂未体现、岗位信息未知和偏好不符。
- 至少 3/6 用户在 72 小时内完成高质量投递决定，其中至少 2 人自报完成官方投递。

高质量投递决定要求用户查看来源与依据，选择投递、暂缓或放弃，并记录至少一个理由。链接点击或收藏不单独计入。

### 11.2 守护指标

- 明确硬条件冲突漏检：0。
- 错误劝退：0。
- 虚构经历、成果或岗位条件：0。
- 未确认事实参与确定性结论：0。
- 数据删除失败、安全事件和隐私事件：0。

“错误劝退”指系统依据错误、未知或混淆的信息显示资格冲突，或把“简历暂未体现”写成用户不具备能力，并因此促使用户放弃岗位。任一守护事件发生即停止扩展并复盘，不用其他成功数据抵消。

### 11.3 产品北极星观察

正式实验的 72 小时阈值用于快速 Gate；产品长期观察仍使用：

> 在 7 日活跃求职周期内，已完成约束与证据确认且查看至少 3 个岗位的用户中，对至少 1 个岗位完成高质量投递决定的用户比例。

72 小时内自报官方投递作为下游强证据单独记录。

## 12. 工程验证样本

- G2 Local Complete MVP 先建立至少 20 个高风险金标案例。
- Private Alpha 前扩至 30 个。
- Beta 前扩至 60 个。
- 案例必须覆盖明确冲突、岗位未知、简历暂未体现、偏好不符、时间范围边界和来源状态变化。

金标集用于防止规则、模板或 AI 变更造成回归，不替代真实用户实验。

## 13. 证据记录与决策

每次校准和正式实验至少记录：

- 匿名参与者编号和纳入条件检查。
- Layer 0-3 的输入、时间、决定、理由和变化。
- 主持人提示次数和异常。
- 术语理解题结果。
- 72 小时回访和官方投递自报。
- 事实错误、反例、隐私顾虑和删除结果。
- 模板/AI 对照顺序与结果。

证据强度从高到低为：

1. 实际完成的高质量决定和官方投递。
2. 可展示的近期浏览、收藏、表格和投递记录。
3. 实验中的可观察行为、完成时间和错误。
4. 对近期具体事件的叙述。
5. 对未来产品的态度。

正式实验结束后只允许四种决定：

- **继续**：结果和守护 Gate 全部通过，进入下一阶段。
- **修改**：价值信号存在但任务、术语或岗位样本有明确可修正问题。
- **回退**：用户或问题假设不成立，回到问题发现。
- **停止**：增量价值不足、隐私边界不可接受或来源不可持续。

每次决定使用 [实验卡模板](templates/experiment-card.md) 记录，并把摘要、Gate 和下一日期回写 [MVP 路线与当前决策面板](06-mvp-roadmap.md)。没有原始记录和反例的实验不算完成。
