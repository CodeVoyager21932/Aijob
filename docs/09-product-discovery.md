# 产品发现与实验

## 1. 当前结论的证据等级

当前产品方向合理，但仍处在“有逻辑支持的假设”，不是已经验证的市场事实。

| 判断 | 当前状态 | 还缺什么 |
|---|---|---|
| 官方来源比综合平台转载更可信 | 强逻辑假设 | 用户是否愿意因此改变找岗和投递路径 |
| 学生难以判断自己是否符合岗位 | 待验证 | 近期真实任务、频率、错误后果和现有处理方式 |
| 可解释匹配比单一分数更有帮助 | 待验证 | 用户能否理解并因此完成投递 |
| 企业官网和高校就业网可持续采集 | 技术/合规待验证 | 代表来源样本、条款、结构变化和维护成本 |
| 用户愿意持续回来使用 | 未验证 | 重复求职周期中的真实留存行为 |

所有对外表达都需要保留这个边界，不能提前写成“已解决”“已验证”或“受到用户认可”。

## 2. 首要用户收窄

长期用户包括在校生、应届生和其他求职者，但产品发现阶段一次只研究一个首要人群。

建议优先候选：

> 正处于未来 1-3 个月实习或校招投递期、已经有一份基础简历，但在多个官方渠道之间找岗并判断是否值得投递的在校生/应届生。

选择原因：

- 当前任务紧迫，容易观察真实行为。
- 能提供简历、收藏和投递记录等证据。
- 同时存在来源分散、资格复杂和经历不足三类问题。
- 与项目的官方来源和证据匹配能力直接对应。

这仍是待验证细分，不在访谈前永久锁定。

## 3. 当前问题树

```text
用户没有高质量完成投递
├─ 没发现机会
│  ├─ 企业官网分散
│  ├─ 高校网站信息结构不同
│  └─ 岗位更新和截止时间不清
├─ 不知道是否有资格
│  ├─ 毕业年份/学历/专业限制
│  ├─ 到岗、出勤和持续时间限制
│  └─ 岗位描述措辞模糊
├─ 不知道是否值得投
│  ├─ 缺少正式经验
│  ├─ 不会识别可迁移经历
│  └─ 传统关键词匹配无法解释
└─ 没有行动
   ├─ 选择过载
   ├─ 不知道简历突出什么
   └─ 收藏与真实投递脱节
```

访谈需要判断哪一支是高频、高影响且现有替代方案解决不好的首要问题，不能假设四支都同样重要。

## 4. 当前替代方案

研究时至少观察：

- 综合招聘平台。
- 企业招聘官网收藏夹。
- 高校就业网、公众号和微信群。
- Excel、Notion、飞书表格和个人文档。
- 学长学姐、求职社群和付费辅导。
- 通用 AI 对话或简历匹配工具。

重点不是证明它们“不好”，而是理解用户为什么仍然选择它们，以及什么切换成本会阻止用户使用新产品。

## 5. 假设清单

| ID | 假设 | 类型 | 风险 | 最便宜验证方式 |
|---|---|---|---|---|
| H1 | 目标用户每周需要跨多个官方来源找岗位 | 需求 | 高 | 访谈最近一次找岗过程和浏览记录 |
| H2 | 资格判断错误会导致放弃合适岗位或浪费投递时间 | 需求 | 高 | 收集真实误判案例 |
| H3 | 带证据的推荐能提高官方投递行动 | 价值 | 最高 | 人工礼宾推荐 A/B 对照 |
| H4 | 用户愿意在明确隐私边界后粘贴去标识化简历文本换取推荐 | 隐私/价值 | 高 | 脱敏文本礼宾实验 |
| H5 | 官方来源能够以可接受成本持续维护 | 可行性 | 最高 | 3 个代表来源的连续采集实验 |
| H6 | AI 解释的新增价值高于规则与模板 | 技术/价值 | 中 | 同一结果规则版与 AI 版对比 |
| H7 | 用户会在一周内再次使用 | 留存 | 高 | 私测真实行为 |
| H8 | 免费/低成本服务能覆盖抓取、模型和维护成本 | 可持续性 | 中 | 记录单用户和单来源成本 |

每轮只验证 1-2 个最高风险假设。

## 6. 用户访谈方法

### 招募条件

- 最近 30 天实际找过实习或校招岗位。
- 至少浏览过两个来源，或维护过收藏/投递记录。
- 能够回忆并展示一次具体经历。

### 访谈原则

- 问过去真实行为，不问“你会不会使用”。
- 请用户展示最近使用的页面、表格和简历，而不是只讲感受。
- 先理解现有流程，再介绍产品设想。
- 不在问题中暗示“官方来源”和“AI 匹配”一定更好。
- 访谈材料脱敏，未获授权不保存简历全文和联系方式。

### 核心问题

1. 最近一次认真找岗位是什么时候？从哪里开始？
2. 当时打开了哪些网站、群或表格？为什么？
3. 最耗时、最困惑的一步是什么？具体花了多久？
4. 有没有因为资格不清而放弃或误投？发生了什么？
5. 你如何判断一个岗位值得投？会看哪些证据？
6. 收藏后为什么没有投？最终是什么推动你投递？
7. 为解决这些问题，你已经使用过哪些工具或向谁求助？
8. 如果只能改善一个环节，你会选哪个？

## 7. 证据强度

由强到弱：

1. 实际完成投递、付费或投入时间的行为。
2. 可展示的浏览记录、表格、收藏、简历版本和投递记录。
3. 对近期具体事件的详细叙述。
4. 多名用户反复出现的主题。
5. 对未来产品的态度和泛泛意见。

路线图优先由前四类证据驱动。

## 8. 人工礼宾实验

### 实验输入

- 20-30 条人工确认有效的官方岗位。
- 用户脱敏简历或结构化经历。
- 城市、时间、岗位方向和排除条件。

### 人工输出

- 5-10 条推荐。
- 明确资格状态。
- 每条岗位的经历支持证据、缺口和未知项。
- 官方原始链接。

### 观察

- 用户最先看什么，忽略什么。
- 是否质疑资格或证据判断。
- 是否点击、保存、投递。
- 没投的真实原因。
- 相比原流程节省了什么，是否愿意下次再来。

### 成功与失败

成功不是“用户说不错”，而是用户能够依据结果做出更快、更清楚的投递决定并产生行动。

## 9. 定位假设

### 内部定位句

> 对于正在实习或校招投递期、已经有基础简历却难以从分散官方来源中筛选合适岗位的学生，本产品提供可追溯的官方岗位和基于真实经历证据的投递建议；不同于追求岗位数量和黑盒分数的招聘平台，它优先保证来源、资格与解释可信。

定位句必须在阶段 1-2 后根据证据修改。

## 10. 指标框架

### 核心结果指标

- 查看推荐后完成真实投递的用户比例。

### 前置信号

- 简历/约束确认完成率。
- 推荐到官方投递页点击率。
- 用户认为推荐理由可理解且有帮助的比例。
- 一周内再次使用率。

### 守护指标

- 无效岗位率。
- 明确硬条件冲突漏检率。
- 无证据解释率。
- 用户数据删除失败数。
- 安全或隐私事件数。

不能用岗位数、AI 调用数、注册数替代核心结果。

## 11. 实验记录规则

每个实验使用 [实验卡模板](templates/experiment-card.md)，至少记录：

- 要验证的假设。
- 为什么它是当前最高风险。
- 方法、样本和成功/失败标准。
- 实际观察和反例。
- 结论可信度。
- 继续、修改、停止或回到发现阶段的决定。

没有记录结果的实验不算完成。
