# 官方岗位投递决策助手

这是一个待验证的产品项目，面向**未来 30 天真实投递产品或运营实习、已有中文简历、近期使用过多个官方渠道的中国大陆在校生**。它把企业官方招聘网站、经企业确认的官方 ATS、高校就业网站和企业公开招聘页面中的岗位整理为可追溯信息，并依据用户确认过的约束与经历证据，帮助用户完成投递、暂缓或放弃的高质量决定，最终回到官方页面投递。

它不是追求岗位数量的招聘信息流，也不以“官方来源”暗示绝对真实。项目需要证明的增量是：跨来源的资格核对、经历证据解释和轻量决策管理，是否能让目标用户更准确、更高效地决定要不要投。

## 当前已经能运行什么

仓库已经具备第一条可执行纵向切片：

```text
腾讯官方公开岗位接口
  -> 来源准入与访问策略检查
  -> 限速采集、原始快照和哈希校验
  -> 字段规范化、冲突/未知值保留、复核项
  -> PostgreSQL
  -> 本地内部岗位列表与详情页
  -> 腾讯官方岗位链接
```

这条链路用于验证工程可行性，不代表腾讯来源已经获准公开聚合。当前来源为 `pending_review`，因此 14 条岗位只出现在本地内部预览接口；公开 `/v1/jobs` 仍返回空列表。两个由上游返回的聚合占位 ID（`-2`、`-3`）会被拒绝并留下复核记录，不会伪装成真实岗位。

### 本地启动

前置条件：Node.js 22+、pnpm 11 和 Docker Desktop。Docker 在这里仅用于在 coco 的电脑上运行 PostgreSQL，不需要购买云服务器。

```powershell
pnpm install
pnpm infra:up
pnpm db:migrate
pnpm source:assess
pnpm source:probe
pnpm dev
```

然后打开 <http://127.0.0.1:5173/research/jobs> 查看含 5 条人工确认岗位的 G0 研究检索原型，或打开 <http://127.0.0.1:5173/internal-preview/jobs> 继续内部字段复核。这 5 条只获准进入本地 `dev/test` 研究样本，不表示腾讯来源已通过准入或可以公开发布；生产研究路由和公开 `/v1/jobs` 仍保持关闭。其中 `source:probe` 会低频读取腾讯官方公开岗位接口并写入本地数据库；它不登录、不处理验证码，也不使用浏览器自动化。停止本地数据库可运行 `pnpm infra:down`。

日常代码检查：

```powershell
pnpm check
pnpm build
```

## 核心链路

```text
审核后的官方岗位
  -> 来源与时效可见
  -> 用户确认事实、偏好与经历证据
  -> 资格、证据、偏好分开判断
  -> 未决定 / 已保存 / 准备投递 / 已投递 / 已放弃
  -> 前往官方页面完成投递
```

资格只使用“未发现明确冲突 / 存在明确冲突 / 需补充信息”；经历证据只使用“有明确证据 / 部分证据 / 简历暂未体现 / 信息不足”；偏好只使用“符合 / 不符合 / 未设置”。产品不输出匹配度百分比，也不自动劝退或隐藏岗位。

## 已锁定原则

- 首轮只验证产品/运营实习决策，不混入其他职能、校招全职或社会招聘。
- MVP-0 人工导入岗位；3 个代表来源稳定后才与产品汇合进入 Private Alpha。
- 匿名邀请使用，不收手机号或邮箱；只有用户要求经历证据匹配时才请求去标识化简历文本。
- 简历原文在证据确认后立即删除，任何情况下最长不超过 24 小时；结构化事实、偏好和证据保留 30 天并可提前删除。
- 规则与模板必须独立完成核心流程；AI 只有在至少 4/6 用户中证明理解正确率或决策效率增量，且没有新增事实错误时才允许启用。
- 不抓取 BOSS、实习僧、牛客等综合招聘平台，不绕过登录、验证码、访问控制或明确禁止的边界。
- 不自动填写、批量投递或模拟登录；用户始终在官方页面完成申请。
