# Aijob：可信官方岗位驱动的求职工作区

Aijob 面向中国大陆本科、硕士、博士在校生，把发现机会、整理经历、写简历、记录投递和面试复盘接成连续流程。岗位事实来自经过核验的企业官网及官方 ATS，最终由用户到官方页面自行投递。

## 当前使用方式

日常开发与使用基线是 `C:\Users\72998\Projects\Aijob` 的网页开发版：React/Vite 前端、Fastify API、两个后台 worker，以及 Docker 中的 PostgreSQL。桌面安装包专属适配、同步构建、安装验收和资料迁入已暂停；现有实现与候选保留，待 coco 明确确认终版后再恢复。

当前目标、未关闭问题读[路线图](docs/06-mvp-roadmap.md)，工程状态读[当前交接](docs/handoffs/current.md)。本页不重复维护迁移版本、岗位数量或进程状态。

## 可以怎样使用

1. 在[发现机会](http://127.0.0.1:5173/jobs)保存方向，查看当前岗位及后续变化。已接官网刷新不需要搜索 Key；扩展新入口时可检查并复用支持搜索的个人 AI，或主动选择 Tavily。
2. 在[我的简历](http://127.0.0.1:5173/resumes)空白起草、导入 PDF/DOCX/文本或复用经历，直接编辑、局部纠错和换模板。原件可以找回；预览与 PDF 下载使用当前保存稿对应的同一产物。
3. 从岗位进入材料准备，形成独立岗位稿。自行投递后记录实际使用的文件，后续编辑不会改写已留存的投递稿。
4. 在[今日](http://127.0.0.1:5173/today)查看变化、继续准备和日程；[连接与运行](http://127.0.0.1:5173/settings/ai)管理个人 AI 与搜索方式。无 AI 时仍可编辑、导出和记录投递。
5. 网页会自动记住当前浏览器，会话到期后续接原资料。在[账户与资料](http://127.0.0.1:5173/settings/data)下载并保存恢复文件；清除浏览器数据或换浏览器后，用该文件找回同一本机服务里的简历和配置。

搜索只提供待核验线索，不会自动接入任意网站或替用户投递。电脑关机或服务停止时后台暂停；重启后按预算处理到期任务。当前来源覆盖和使用限制见交接，不把一次联调当长期稳定性证明。

## 启动与配置

当前网页版的简历基础主线已完成本轮收口：现有六套模板支持内容编辑、局部文字格式、撤销和保存重开，正式 PDF 严格一页。实际成品、资料保留与后续项见[简历模块收口记录](docs/evidence/resume-module-closeout-2026-10-15.md)。DOCX 为可编辑内容导出，本轮局部排版及 Word/WPS 分页尚未同步验证。

唯一日常入口是[网页开发版运行说明](docs/runbooks/system-upgrade-local.md)：先检查已有服务，复用原 `.env`、密钥和业务库，再启动确实停止的进程。运行依赖为 Node.js 22+、仓库锁定的 pnpm 及 Docker Desktop；命令以该手册和当前 package scripts 为准。

此 C 盘工作区已恢复业务数据，不从旧 HEAD 重建，不执行旧空库初始化或 `local:bootstrap` 来“恢复当前环境”。新机器首次部署、灾备恢复和安装包运行属于不同场景，不能混用旧手册里的数据库和启动命令。

个人 Key 只在本机设置中填写，按账户加密保存，不提交到 Git。生成接口可用不等于支持搜索；系统根据真实工具执行及来源证据检查搜索能力，不要求所有用户填写两种 Key，也不自动切换付费供应商。

## 保留的产品边界

- 覆盖在校生可投的实习、校招、应届和管培岗位；学历与院校供个人核对，未说明保留 `unknown`。规模、数量及分布是报告或观察项，逐来源质量准入继续有效。
- 简历、经历和练习可以独立开始；原件、正文、经历与保留产物持续保留至用户删除。24 小时清理只适用于临时解析副本或未保留预览缓存，不适用于保留原件。
- AI 使用个人材料支持事实，岗位要求只安排重点；不编造经历和数字，建议由用户采用且可撤销。不恢复脱敏复核、逐句证据审批或二次初始化。
- 不抓取综合招聘平台，不绕过登录、验证码或访问控制，不自动填写或提交申请。普通 Web 不获得内部来源管理权限。
- 无匹配百分比或自动劝退；岗位事实、个人经历证据和偏好分开表达。工程检查通过不代表真实用户价值已验证。
